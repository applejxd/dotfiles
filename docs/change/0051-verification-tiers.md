# CHG-0051: 検査（verify / verify:all）を段階化し、安い検査を先に・重い検査を後にする

- **状態**: In progress
- **更新日**: 2026-11-01
- **基準**: コミット 135417f 以降（作業ブランチ `feature/verify-tiers`）

## 目的と非目的

**目的**: `verify:all` が重く（全コアを使い切る）、安い検査で分かる失敗が、約 3 分 30 秒の全件の最後に分かる問題を直す。動機は 4 つ。

1. **順序**: ruff の指摘や、`verify.py` への試験ファイルの登録漏れのような、数秒で分かる失敗が、全件の後にしか見えなかった
2. **負荷**: `-n auto` が全コアを使い、実行中の PC が重くなる
3. **食い違い**: 「約 9 分」の数字が古い（実測は約 3 分 30 秒）。`verify:all` は shellcheck を回さない。lint_docs が二重に走る
4. **印（stamp）の弱さ**: 実行の終わりに印を作るので、実行中に編集したファイルまで「検証済み」になる

**非目的**: 検査を弱めること（全件のフォールバックは維持する）。CI での置き換え。`pi` を起動する試験の件数や起動費用の削減（後続）。

## 受入条件

- **A1**: 全件は T0（安い検査）→ T1（変更に当たる試験）→ T2（残りの全件）の順で走り、前の段で失敗したら次を始めない（`--keep-going` で続行できる）
- **A2**: T2 は T1 と T0 の試験を `--ignore` した補集合で、取りこぼしも二重実行も無い
- **A3**: T0 に shellcheck と、試験の登録ずれの検査（`test/test_verify.py`）を含める。lint_docs の二重実行はしない
- **A4**: 並列度の既定はコア数の半分で、`VERIFY_JOBS` / `--jobs` で変えられる。`nice` で低優先度にする
- **A5**: 印は検証の開始時の状態を記録し、終了時に作業ツリーが変わっていれば書かない（開始と終了の 2 点の比較。実行中に編集して元に戻す変更は検出できないので、検証中は編集しない）
- **A6**: 全件のフォールバック（未一致・削除・全件の領域）と、Windows 実機の「未検証」の明示は変わらない
