## permission-system との関係（観点 5）
- 前提（`@gotgenes/pi-permission-system@42.0.0` の docs/configuration.md「shellTools」）: `shellTools` は**実行時設定**（グローバル config）。キーが tool 名、値が `{commandArgument, workdirArgument?}`。bash と同じ分解・ラッパー・パス・`bash:` ルールに通る。tool が未登録なら無効（害なし）。プロジェクト側の設定は runtime config として merge されない（0644 migration）ので、**利用者のグローバル config に書く**。
- pi-background: `bash` は同名で再登録（pi 組み込みのときだけ）→ tool 名は `bash` のままなので判定はそのまま効く。`bg_run` は別経路なので次が要る:
  ```json
  "shellTools": { "bg_run": { "commandArgument": "command", "workdirArgument": "cwd" } }
  ```
  `bg_status` / `bg_kill` はコマンドを実行しないので allow でよい（方針は利用者が決める）。
- pi-background-tasks: `bg_run` も `commandArgument: "command"`（workdir 引数なし）。`bg_delegate`/`fusion_*` は別モデル・子 pi を呼ぶので ask 推奨。
- pi-patty: `bash`（同名上書き、引数 `command`）はそのまま効く。`bash_bg` と `monitor` は `command`。`agent_bg` は子 pi で判定の外。

## cc-safety-net との関係（観点 6）
- ソース（cc-safety-net@2.7.6 `dist/chunks/index-xavta84c.js`）: pi 用フックは `tool_call` で、shell とみなす tool 名は固定の `bash`→posix、`powershell`→powershell のみ。**`bg_run` などの別名は shellTools のような設定がなく、網の対象外**（確認済み）。
- 影響: pi-background の `bash` 経由（120 秒で自動背景化）は網に通る。`bg_run` 直接呼びは通らない。permission-system の deny/ask（shellTools 経由）は効くので、「破壊的コマンドの網」だけが抜ける。
- 対策案: (A) `bg_run` を shellTools に載せ、網の抜けを受け入れる。(B) permission で `bg_run` を deny し、長いコマンドは bash に任せる（120 秒で自動背景化、完了で wake）。(B) は `wake_on` が使えず、モデルへの指示（`bg_run` を使え）と衝突して無駄な試行が出る。12 分の全件検査が主用途なら (B) でも足りる。**推測**: 実機で試すまで (B) の体験は不明。

## pi-subagents との衝突（観点 7）
- pi-subagents（0.87.0）の tool は `subagent`、`subagents_enable`、`bg_wait`（名前は設定で変更可）。pi-background の `bg_run` / `bg_status` / `bg_kill` とは**名前が重ならない**（grep で確認）。pi-background-tasks も `bg_wait` は使わないが、`bg_` の接頭辞が並び、`/bg` コマンドも持つので紛らわしい。
- 役割: pi-subagents は「子エージェント」の背景実行、pi-background は「シェルコマンド」の背景実行。重複はない。UI 枠は pi-background が `background-jobs` ウィジェット（入力欄の上）、pi-subagents が FleetView（エディタの下）。衝突は未確認。
- pi-background-tasks は `bg_delegate`（読み取り専用の子 pi）を持ち、pi-subagents と**機能が重複**。入れるなら `PI_BG_FEATURES=process` に絞る。

## 候補ごとの詳細

### pi-background 0.4.2（推奨）
- 事実（README・background.ts を全読）:
  - `bg_run({command, cwd?, wake_on?})`。終了で exit code とログ末尾 20 行を steer で送り、`triggerTurn:true`。失敗は即 wake。kill は wake しない。
  - bash が 120 秒を超える（または timeout が短ければその時点）と、止めずに背景 job へ移す。→ 前景の `bash` で 12 分のコマンドを回しても、2 分で背景化され、終わったら wake。
  - `bg_kill`: AbortController で子プロセスごと停止。pi 終了（`session_shutdown`）で実行中 job は全部 abort。
  - 他の拡張が bash を置き換えている場合（サンドボックスなど）は手を出さない。
  - ネットワークなし。env は `PYTHONUNBUFFERED=1` を足すだけ。`pi.getSettings()` から shellPath と shellCommandPrefix を使う（Windows で WSL の bash を拾わない配慮）。
  - ライセンス MIT、依存ゼロ。
- 弱み / 未確認:
  - pi を閉じると job が死ぬ（12 分の検査中に pi を閉じない運用が前提）。再開で job は戻らない（コードより）。
  - 1.5.0 との実機の動作は未確認（peer は `*` で、`createBashToolDefinition` `getSettings` `sendMessage` の API 依存。型は 1.5.0 で確認していない）。
  - `/tmp/pi-bg/` にログが残る（掃除なし）。Windows では `tmpdir()`。
  - ctrl+b と pi-polish 連携の `globalThis` フラグ（他の拡張に害はない）。
  - 作者・Issue 対応は未確認（リポジトリ pringled/pi-extensions）。DL が少ない。
- 設定:
  - `pi-stock-packages` に `npm:pi-background@0.4.2`
  - permission のグローバル config に上の `shellTools`、`bg_status` / `bg_kill` は allow
  - 利用者の settings.json は任意（`"background": {"jobs": "compact"}`）

### pi-background-tasks 2.6.10（保留）
- 良い点: 機能が最も豊富（ログ読み取り、`bg_result`、ダッシュボード、reload 越しの生存）。`bg_run` は既定で完了通知＋follow-up turn。
- 問題: (1) peer が pi 0.81〜0.84 のみ、現在の 1.5.0 は範囲外（本体 latest は 1.5.0 で、更新が 2026-10-13 を最後に止まっている）。(2) 6MB と大きい。(3) 既定で Anthropic のリクエストを書き換える attribution（Claude Code OAuth 属性＋プロンプト整形）が有効。意図しない挙動。(4) `isAgent` と `name` が必須で、モデルの手間が増える。(5) fusion/delegate が pi-subagents と重複。
- 入れるなら `PI_BG_FEATURES=process`、`PI_BG_DOCK_SHORTCUT=off`（Shift+Down の衝突を避ける）。1.5.0 との互換が確認できてから。

### @agimon-ai/po-runner（除外）
- BUSL-1.1（非 OSS 扱い）、alpha、Po 配布の一部（セッション ID と `PO_SESSION_TEMP_DIR` が前提）、macOS/Linux のみ（Windows 不可）、peer に react-native、pi 1.5.0 固定。`bash` の `command` が配列で、permission-system の bash 判定との整合が不明。目的（検査を背景で回す）に対して重すぎる。

### pi-patty-bg-tasks 1.1.6（保留）
- 良い点: 依存ゼロ・MIT。`bash` の同名上書きなので permission-system と cc-safety-net が**そのまま効く**。`jobs` でログ検索、kill。
- 問題: 完了 wake が弱い（1.1.5 の方針で、ターン中に終わると `triggerTurn:false`。ターンが終わったあとは次のユーザー入力まで気づかない可能性。**アイドル中に終わった場合だけ steer で wake**）。12 分のうち agent が待っているケースに合わない可能性が高い。`agent_bg` が `pi -p` を detached で起動（判定の外、pi-subagents と重複）。`bash` を上書きするので、pi-background と同時には入れられない。最終更新 2026-07（4 か月前）。

## 判断した点

## 利用者に聞きたいこと
1. `bg_run` を shellTools で許可（cc-safety-net の網の外）か、deny して bash の自動背景化だけにするか。推奨: 最初は (A)、実機で問題があれば (B)。
2. pi を閉じても job を残したいか（pi-background は不可）。必要なら別の仕組み（tmux 等）の検討になる。
