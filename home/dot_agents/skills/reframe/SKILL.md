# 問題を見分けて言語化する

利用者の言葉と手元の材料から出発せよ。専門用語を増やすことではなく、次に調べる対象や作るものを絞ることが目的である。

1. 説明から成り立つ解釈を最大 3 つに整理し、それぞれを見分けられる症状・ログ・操作を一つ出す。
2. 最も根拠のある解釈と、まだ区別できない点を示す。分からないことを確定にしない。
3. 使うと調査や設計が変わる用語だけを挙げる。各語に、元の依頼のどの部分を表すか、その語で何を検索・依頼できるかを添える。
4. 既存の実装・論文・規格を例に出す場合は、原文が同じ意味で使っていることを確かめる。似ている部分と違う部分を分ける。確認できなければ引用しない。
5. 次に渡せる短い依頼文に書き直す。解釈の違いが判断を変え、観測から決められなければ、見分ける質問を一つ残す。

依頼されていない実装には入らない。テーマを特定した後の広い文献収集とは分ける。
