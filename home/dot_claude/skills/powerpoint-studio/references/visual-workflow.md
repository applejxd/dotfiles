# Visual Workflow

## Choose the visual by the claim

| 示したいこと | 視覚 |
| --- | --- |
| 大小、順位 | sorted bar / dot plot |
| 時系列 | line / small multiples |
| 分布 | histogram / box / violin |
| 内訳 | stacked bar。円グラフは少数カテゴリのみ |
| 因果、処理 | directed diagram |
| システム構造 | layered architecture diagram |
| 操作結果 | screenshot with callouts |
| 実験の信頼性 | metric + uncertainty + conditions |
| 選択肢 | matrix / cards / trade-off table |

## Charts

- 3D、二重軸、不要な凡例、過剰なグリッド線を避ける。
- 単位、母数、期間、条件を明記する。
- index や相対値を使う場合、基準値、方向（増減が良いのか）、計算式、測定窓を明記する。
- raw count を異なる期間や異なる母数で比較しない。同じ期間へ揃えるか、週率、
  1件あたり、100 PR あたりなどへ正規化する。
- 比率は分子と分母を、アンケートは設問、回答者範囲、集計方法を短く明記する。
- 色だけで系列を区別しない。線種、ラベル、位置も使う。
- 結論に関係する系列を accent、その他を muted にする。
- 軸を切る場合は切断を明示する。
- 参照線、閾値線、色帯は意味をラベルで説明できる場合だけ使う。装飾線を
  データ閾値のように見せない。
- 離散的な手法・カテゴリの点を線で結ばない。順序や連続性が本当にある場合を除き、
  unconnected points を使う。
- `loss` の正の大きさと `change` の負符号を混在させない。軸名、値、符号の
  convention を統一する。
- 実験結果は seed、試行数、誤差、baseline を可能な限り示す。
- 数値の出典、サンプル数、算定責任者を置けない場合は `illustrative` / `target`
  / `hypothesis` と明示し、actual に見せない。

## Diagrams

- 左→右または上→下の一方向を基本にする。
- ノードは 7 個程度まで。詳細は段階を分ける。
- 矢印は動詞で読める関係にし、線の交差を避ける。
- 同じ意味の図形、色、線種を統一する。
- SVG の viewBox と全ラベルを確認し、PPTX 化後にも読めることを確認する。
- 生成 AI に文字入りの図を描かせない。文字と形は決定論的に生成する。
- native / hybrid / external の選択は `diagram-routing.md` に従う。
- 一度でもネイティブ図形の矢印・ループ・ラベルが崩れたら、同じ方式で座標調整を
  続けず、専用作図ツールへ切り替える。

埋め込む前に SVG の viewBox、外部参照、ラベル境界を検査する。

```bash
uv run scripts/validate_svg.py assets/method.svg --output ./.tmp/svg-report.json
```

GraphvizのSVGはグループ変換の内側で負の座標を使うことがある。
`validate_svg.py`は祖先・要素の`transform`属性を合成して文字の基準点を確認する。
ローカル座標の符号だけではみ出しと判断しない。この検査は文字の全字面の境界を
測るものではないため、実フォントの幾何検査と最終レンダーの確認も行う。

## Screenshots

- ブラウザやアプリ全体ではなく、主張に必要な領域へクロップする。
- UI の原文、ロゴ、数値を勝手に描き直さない。
- 余白、角丸、1px 相当の枠、控えめな影で背景から分離する。
- 注釈は 1〜3 個。番号または短いラベルで、対象を隠さない。
- 複数スクリーンショットは高さ、拡大率、枠、キャプションを揃える。
- 長い縦画像はそのまま縮小せず、複数パネルへ分割する。
- サムネイルを並べる場合も、少なくとも1枚は内部UIラベルを読める主画像にする。
- `evidence-screenshot` など証拠として命名した画像は、原則2.0インチ幅・1.0インチ高
  以上にする。これ未満は証拠ではなく装飾として扱い、削除または拡大する。
- 元スクリーンショット自体に切れ・秘匿漏れ・壊れた表示がある場合、その欠陥を
  強調して見せない。主張に必要な健全な領域へクロップするか、別の原本を使う。

## Evidence versus outcome

- evidence ページは測定値、比較、操作証拠を示す。
- outcome ページは同じ数値を繰り返さず、利用者の行動、時間、リスク、意思決定が
  どう変わるかを示す。

## Image integrity

- PptxGenJS 4.0.1 の推移依存 `image-size` には、特定の ICNS/JXL/HEIF 入力で
  停止し得る既知の DoS advisory があり、修正版 npm release は調査時点でない。
  未信頼の特殊形式を直接渡さず、入力サイズを制限して PNG/JPEG へ事前変換する。
- 写真を引き伸ばさない。
- `contain` は全体を見せる必要がある図・画面、`cover` は雰囲気を優先する写真。
- 主要ラスター画像は表示時 140 PPI 以上、細字を含む図は 180 PPI 以上を目安にする。
- JPEG の再保存を繰り返さない。
- 透明画像は暗背景と明背景の両方で縁を確認する。

## Japanese line breaking

- 2〜4文字の重要語（「決定」「集中」「承認」など）を1文字だけ次行へ送らない。
- レンダリング後、各スライドを原寸で見て一文字孤立を確認する。
- 発生時は、文を短くする、枠を広げる、自然な位置で改行する、語を言い換える。
  フォントを全体的に小さくするのは最後の手段とする。
