# 子エージェントの起動は、利用者の常設の指示で授権し、数の上限は設けない

- **ステータス**: Proposed
- **日付**: 2026-11-11
- **決定者**: applejxd
- **関係**: [ADR-0031](0031-evaluate-existing-extensions-first.md)（既存の拡張・設定を先に使う）に従い、`pi-subagents` の標準の設定と、利用者の常設の指示だけで実現する。ADR-0006（強制は機構へ）に従い、安全は指示でなく権限の機構で担保する。

## コンテキスト

- `pi-subagents` は、子エージェントを「利用者が指示したとき（直接、または適用される利用者・プロジェクトの指示を通じて）」だけ起動する。利用者が明示しないと、親は子を起動しない。
- 利用者が最も困っていたのは、**明示の指示がないと子が起動しない**こと。並列の調査・実装後の監査・別系統の意見が、頼まないと使えず、子エージェントをフルに活用できていなかった。
- 既定の上限（同時の非同期実行 4・深さ 1・1 回の実行での起動数 32）も、活用を妨げていた。利用者は「上限や深さの制限は取り払う」と決めた。
- 子が作業ツリーの外を読もうとすると、確認が親の画面へ転送され、誰も答えないと 5 分（`promptTimeoutMs`）で拒否される。離席中の子が 5 分止まる問題は、別に解いた（agent 定義の写しに `external_directory: deny`。[実測](../research/agents/subagent-permission-frontmatter-2026-11.md)）。

## 検討した選択肢

### 案 1: 現状のまま（利用者が毎回指示する）

- **欠点**: 利用者の最大の不満が残る。却下。

### 案 2: 設定項目で自動起動にする（`authorityPolicy` など）

- `authorityPolicy` は、危険な操作の確認の設定で、起動の授権ではない。目的に合わない。却下。

### 案 3: 拡張・hook で、条件に合う場面で子の起動を強制する

- **欠点**: 自作の仕組みになり、維持費がかかる（[ADR-0031](0031-evaluate-existing-extensions-first.md)）。却下。

### 案 4（採用）: 利用者の常設の指示で授権する

- `~/.pi/agent/AGENTS.md`（全プロジェクト共通。配備元は `home/.chezmoitemplates/agent-instructions-stock.md`）に「委譲（サブエージェント）」の節を置く。**常設の指示は、利用者があらかじめ出している指示**で、`pi-subagents` の規則（利用者の指示で委譲する）に当たる。
- **利点**: 標準機能だけで実現でき、維持するコードが無い。利用者が文面で、いつでも調整できる。
- **欠点**: 守られるかは、モデルの従順さに依存する（強制ではない）。

## 決定

**案 4 を採る。あわせて、数の上限は設けない。安全は、数の上限ではなく、外側の権限の機構で担保する。**

### 1. 授権（常設の指示）

次の場面では、利用者の依頼を待たずに、`subagent` で子へ委譲する。

- 独立した調べものが 2 つ以上あり、それぞれが多数のファイルや複数の情報源にまたがる → `scout`（コード）・`researcher`（Web）を並列で。
- 挙動・権限・設計・安全に関わる変更を終えた → コミットの前に `reviewer` に差分を監査させる。
- 担当ファイルが重ならない実装が 2 件以上 → 専用の作業ディレクトリ（git の枝を分けたもの）を作り、`worker` を並列で。
- 設計の選択肢が分かれ、決め手が弱い → `oracle` に二番目の意見を求める。
- 数分以上かかる検証・測定 → 子ではなく `bg_run`。

**小さな作業は委譲しない**（自分で数分以内にできる作業・数行の修正・docs だけの変更・1 回の検索で済む調べもの。利用者が「自分でやって」と言ったときも）。

作法: すべて非同期で起動する。依頼文に、担当・変えてはいけないもの・合格条件・読むファイルのパスを書く。子の自己申告を信じず、親が同じコマンドを再実行して確かめる。利用者の承認が要る操作（`push`・`chezmoi apply`・外部への書き込み）と、秘密を扱う作業は、子に任せない。

### 2. 数の上限は設けない

`home/dot_pi/agent/extensions/subagent/modify_config.json.py.tmpl` が、`~/.pi/agent/extensions/subagent/config.json` を整える。

| キー | 値 | 意味 |
| --- | --- | --- |
| `maxActiveAsyncRunsPerSession` | 0 | 無制限 |
| `maxSubagentSpawnsPerSession` | 0 | 無制限 |
| `maxSubagentSpawnsPerRun` | 10000 | 事実上の無制限（0 は無視され、64 になる） |
| `globalConcurrencyLimit` | 1000 | 事実上の無制限（0 は読み込みが失敗する） |
| `maxSubagentDepth` | 8 | 子が子を起動できる深さ |
| `parallel` | `maxTasks` 64・`concurrency` 16 | 1 回の並列の依頼 |

旧既定（4・1・32）のままなら新しい値へ移し、利用者が別の値を選んでいれば保つ（利用者の値を上書きしない）。

### 3. 安全は外側で担保する

- 作業ツリーの外は、子でも**確認ではなく即拒否**（agent 定義の写しの `external_directory: deny`）。
- 危険な操作は、確認（ask）ではなく、理由つきの deny にする（ADR-0006）。全 deny に理由がある。
- グローバルな環境変更は deny し、理由で `uv`・`mise` へ案内する。worktree の中のローカルな変更は自由。
- 子のコマンドには、必ず外側の `timeout` を付ける（`subagent stop` は子のサブプロセスを止めない）。

### 4. 役ごとのモデル

`reviewer`・`oracle`・`evidence-auditor` は、親・`worker` の Claude と**別系統**の GPT 6.1 sol（high）にする（同系統の自己点検は効きにくく、評価役は同系統の出力を好むため。根拠）。`worker`・`researcher` は Sonnet 5.5（medium）、`scout` は Sonnet 5.5（low）。自律的に起動する子には、高価な Opus を使わない。

## 結果

### ポジティブな結果

- 利用者が毎回指示しなくても、並列の調査・実装後の監査・別系統の意見が使える。実装後の監査は、実際に MAJOR 2 件・MINOR 5 件を見つけた（2026-11-10。`subagent-autonomy` の変更）。
- 維持するコードが無い（設定の整形と、指示の文面だけ）。

### ネガティブな結果・トレードオフ

- **費用の上限が無い**。起動数の上限を外したので、暴走（同じ依頼の再起動の連鎖など）を止めるのは、深さ（8）・子ごとの `timeout`・`subagent stop` だけ。
- 「小さな作業は委譲しない」は、指示で、強制ではない。過剰に起動する可能性がある。
- 常設の指示が実際に効くか（指示なしに子を起動するか）は、**まだ観察していない**。

### 今後の見直し条件

- 費用が急に増えた、または起動の連鎖が起きた → 上限を戻す（まず `maxSubagentDepth` と並列の数）。
- 起動すべき場面で起動しない／過剰に起動する → 常設の指示の閾値（小さな作業の除外）を調整する。1〜2 週間使ったあとで、`friction-review` スキルでセッションのログから確かめる。
- 実際に使って問題が無ければ、Accepted にする。
