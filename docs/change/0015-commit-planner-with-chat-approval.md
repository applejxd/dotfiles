# CHG-0015: 計画役の子にメッセージ案を作らせ、承認は会話で行う

- **状態**: In progress
- **更新日**: 2026-10-07
- **基準**: `8b63a9f`

## 目的と非目的

**目的**: OpenCode で「コミットして」と頼んだとき、次を満たす。

- 差分を読む重い作業は安いモデルの子エージェント（`commit`）に任せ、親の文脈を差分で膨らませない
- コミット前に、全単位の対象とメッセージ全文を会話の中で（タップせずに）読める
- 全文を読む前にコミットされない

[CHG-0013](closed/0013-commit-agent-as-planner.md) は同じ分担で、`git commit` の確認画面を承認の場にしたため、
親が全文を示さずに先へ進めた。[CHG-0014](closed/0014-deterministic-commit-runner.md) はそれを照合の仕組みで
防ごうとして部品が増え、取り下げた。本案は**承認の場を会話に移す**ことだけで解く。会話で承認を求めるには
全文を示す必要があるので、抜けても利用者の目に見える。

**非目的**:

- 承認の操作を減らすこと（通常起動と `ocs` で 2 回、`bypass` で 1 回のままでよい。利用者の判断）
- スクリプトや照合の仕組みを足すこと
- 同じファイルの中をハンク単位で分けるコミット

## 現在地

段 1 を実装した。流れは次のとおり（[コミットの確認](../spec/agent-config-generation.md#コミットの確認)）。

1. 親が `commit` を呼ぶ。子は commit スキルの手順 2 として、対象とメッセージ全文（計画）を返す
2. 親は全文を返答に示し、利用者の承認を待って返答を終える
3. 承認されたら、親がスキルの手順 3〜6 でステージとコミットを行う。差分は読み直さず、
   `git status --short` と `git diff --cached --name-only` で対象を確かめる

子の定義と権限は CHG-0013 のものとほぼ同じ。変えたのは、親向けの説明（確認画面ではなく会話で承認を待つ・
`git add` と `git commit` を別々に実行する）と、子の指示の「親がそのまま利用者に示す」の一文。

## 評価基準

- 必須: 承認を求める返答に、全単位の対象とメッセージ全文がある
- 必須: 承認の前にステージもコミットもしない
- 望ましい: 親が差分を読まない（子の結果と `git status` だけで進む）
