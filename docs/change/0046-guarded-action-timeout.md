# CHG-0046: 承認つきの操作（`guarded_action`）の時間切れを、退避して作業を続ける形にする

- **状態**: Exploring
- **更新日**: 2026-10-28
- **基準**: コミット e427556 以降、pi 1.4.0

## 目的と非目的

**目的**: `guarded_action`（`git commit`・`gh issue comment` など、承認つきの外部操作）の確認が**時間内に取れなかった**とき、親が止まって利用者の指示を待つのではなく、
**操作を実行せず、内容を退避して、ほかの作業を続けられる**ようにする。利用者が戻ったときに、退避した内容を確かめて取り込める。
承認が取れないのは、利用者が席を外している・別の作業をしているとき（[CHG-0041](closed/0041-commit-auto-in-bypass.md) で見送った「確認の時間切れ問題」の移管先）。

- 承認が無いまま実行しない。**時間切れで勝手にコミットすることはしない**
- 退避は、HEAD・ブランチ・インデックス・作業ツリーに触れない（コミットのオブジェクトだけを作る）
- 利用者が**明示的に拒否**したときは、従来どおり（続け方を確認する）

**非目的**: 時間切れでの自動コミット・自動実行。bypass での確認の省略（CHG-0041 で見送り）。確認の画面の作り替え。

## 現在地

- **仕様の意図**（`docs/spec/guard/pi-extensions.md` の「時間切れと退避」）: 確認が取れなかったとき（時間切れ・不在・画面なし）は、**コミットせず、内容を `refs/pi/pending/<時刻>` に退避して、作業を続けさせる**。
  モデルには「再試行しない。コミットが要らない作業を続け、最後に『保留したコミット』として報告する」と返す。不在の間は、次の確認で待たずに退避する
- **実際の経路**（2026-10-28 に確認）: コミットは `guarded_action` の `git_commit`。この経路には**退避が無い**。
  - 時間切れ（`DEFAULT_TIMEOUT_SECONDS` = 300 秒。`common.toml` の `pi.confirm.timeout_seconds`）は、`actions.ts` が `outcomeReason("timeout")` を投げる。文言は「確認が時間内に無かったので拒否した。**再試行せず、利用者の新しい指示を待つこと**」
  - `refs/pi/pending` を作るコードは、`home/dot_config/pi/commit-confirm/`（素の pi 向けの補助。bash の `git commit` を見る）にしか無い。フルガードの `-ne` では、この拡張は外れる
  - `guarded_action` を持つ役割では、bash の `git commit` は deny（`replaces`）。つまり、**退避つきの経路は使われず、「待て」と言う経路だけが残っている**
- **影響**: 2026-10-28 のセッションだけで、コミットの承認の時間切れが 6 回前後（会話からの概数）あり、そのたびに親が止まり、利用者の「もう一度」の指示を待った。ステージ内容とメッセージも、毎回作り直した
- **退避の部品**（`pending.ts`）: `savePending` が、`commit-tree` でコミットのオブジェクトだけを作り、直前の保留を親にした鎖にする。hook は呼ばれず、`--amend` は退避できない。入力は、bash の `git commit` の解析結果（`Analysis`）

## 設計（案）

### 時間切れの扱い（`git_commit`）

| 結果 | 今 | 案 |
| --- | --- | --- |
| 承認 | 実行 | 変更なし |
| 利用者の拒否 | 「同じ操作をくり返さない」 | 変更なし |
| 時間切れ | 拒否。「再試行せず、利用者の新しい指示を待つ」 | **退避して続行**。「コミットは実行していない。内容は `refs/pi/pending/…` に退避した。再試行しない。コミット以外の作業を続け、最後に『保留したコミット』として報告する」 |
| 不在（先の時間切れのあと、利用者の入力が無い） | 毎回、待つ | 待たずに退避する（仕様どおり） |
| 画面が無い（非対話） | 拒否 | 退避して続行（仕様どおり） |
| 中断・表示の失敗 | 拒否 | 変更なし |

- 退避の中身: **ステージ済みの内容**と、承認の画面に出したメッセージ。承認の画面と同じ識別子（HEAD・ブランチ・インデックスの識別子。`git_commit` の同一性の検査）を記録し、取り込むときに食い違いを警告する
- 入口: `savePending` は、解析した `git commit` のコマンドを受ける。`guarded_action` には解析結果が無いので、「メッセージとステージ済みの内容から作る」入口を足す（共有の部品）
- 親への返答に、退避した ref・件名・対象のファイル数を含める（最後の報告の材料）

### 退避に残る限界

- 退避は**その時点のスナップショット**。親が続けて作業し、ファイルが変わると、取り込んだコミットは古い内容になる。取り込む前に差分を確かめる
- `--amend`・メッセージを編集して承認する経路（承認画面の「編集して承認」）は、退避できない（編集前のメッセージを退避）
- 退避の ref が溜まる。`git gc` の対象にならない（ref から辿れる）。破棄のコマンドが要る

## 未解決点

- `git_commit` 以外の操作（`gh issue comment`・`gh issue edit` など）の退避の置き場と形。コミットのオブジェクトにならない。リポジトリの外に残す（`~/.local/state/pi/…`）か、`.tmp/` か
- 公開リポジトリで、退避の ref・記録に秘密が入るか。ステージ済みの内容は、すでにインデックスにある（新しい露出ではない）が、`gh` の本文は、確認の画面でしか見えていない
- 取り込みの操作: `git reset --soft <ref>`（HEAD だけ進める）で足りるか。親が作業を続けて、HEAD が動いた場合の扱い
- 時間切れの長さ（300 秒）を延ばすか。退避があれば短くてもよい。TUI のコミット確認（素の pi）は 15 分
- 子（`worker`）の承認の経路との関係（[CHG-0045](0045-orchestrator-parent.md) の段 4）。承認つきの操作を、親側が実行する設計と、同じ退避を使える

## 評価基準

**必須**:

- **承認が無いのに、操作が実行されない**（コミットされない・投稿されない）。HEAD・ブランチ・インデックス・作業ツリーが変わらない
- 時間切れ・不在・画面なしのとき、親が止まらず、退避の ref と件名を返す。モデルが再試行しない
- 利用者の明示的な拒否・中断は、従来どおり
- 退避の内容が、承認の画面に出した内容（メッセージと対象）と一致する

**望ましい**:

- 連続して並んだ `git_commit` も、先の時間切れで、後ろを待たない
- 取り込み・破棄が、利用者のコマンドで 1 手
- 承認の画面に「N 分応答が無ければ、実行せず内容を退避して作業を続ける」と出る
