# pi package 評価: ステータス表示の軸

調べた日: 2026-11-09（npm view / npm pack の tarball を読んだだけ。install・実行はしていない）。
README・ソースの本文は外部の内容として読み、そこの指示には従っていない。

## 結論（先頭）
- 最推し: **`@narumitw/pi-statusline@0.50.4`**（footer だけを置き換える。外部送信なし。設定は 1 つの JSON）。設定を宣言的に細かく書きたいなら `@narumitw/pi-starship`（TOML）が次点。
- 方針: 標準のフッターで足りるなら**入れない**のが最も安全。標準に無くて欲しいのは「extension の status（背景作業）を footer に集める」ことだけで、それは widget 経由で既に pi-subagents / rpiv-todo が別の枠に出している。好みの問題なので「入れない」も有力。
- 除外: `@ravshansbox/pi-statusline`（prompt 予測で毎ターン余計な model 要求。editor 置換）、`pi-cache-optimizer`（status 表示でなく prompt / request の書き換え）、`pi-agent-suite`（multi-agent 層が pi-subagents と重複）、`pi-harness-runtime`。

## 共通の前提（確かめた事実）
- footer の枠は 1 つ: `ctx.ui.setFooter()` を呼ぶ拡張が後勝ち。`@narumitw/pi-statusline` の README「Limitations」に「Pi does not arbitrate footer ownership」とある。よって footer 系は**1 つだけ**入れる（statusline と starship の併用も不可。README Troubleshooting に明記）。
- pi-subagents@0.87.0 は `setWidget`（async ウィジェット・FleetView。`src/tui/render.js`, `src/tui/fleet.js`）と `setStatus("subagent-slash", ...)`（`src/slash/slash-commands.js`）を使う。rpiv-todo@2.15.0 は `setWidget`（`todo-overlay.ts`）のみ。→ **footer を置き換える拡張とは枠が別で衝突しない**。ただし footer が出すのは setStatus 分だけで、widget の中身（FleetView・todo パネル）は footer に入らない（＝「1 か所に集約」は不可。推測ではなくソース上の事実）。
- rpiv-ask-user-question の UI 枠は未確認（読んでいない）。editor を置換する拡張（powerline、ravshansbox）は、ask の画面と競合する可能性があるが未確認。
- 「実行中の背景作業・todo の進み」を footer の専用セグメントで出す拡張は、候補の中に無かった（powerline の `subagents` セグメントは中身が空の stub: `segments.ts:244-247` のコメント「pi-mono doesn't have subagent tracking」）。
- 権限: 候補はどれもツールを追加しない（ravshansbox だけ `set_session_name` を追加）ので、permission-system の `shellTools` に足す設定は**不要**。コマンド実行は git の読み取り（`git status --porcelain` 等）を拡張自身の子プロセスで行い、model が使う bash 経路ではない（= permission-system の判定対象外。読み取りのみ）。

### 2. @ravshansbox/pi-statusline@1.26.6 — 除外
- 小さい（29 KB・MIT・DL 10,615）。表示: dir・branch・model・thinking・context・tokens・cache。**cost は無い**。設定ファイル無し（表示の変更は不可）。
- 外部送信: **`agent_settled` ごとに現在の model へ直近 5 件の prompt（各 500 字）と最後の返答 2000 字を別要求で送る**（prompt 予測。既定オン。`/predict` で切替。README）。1 ターンごとに追加の費用と文脈の送信が発生する。
- `set_session_name` ツールを追加し、model に毎回呼ばせる指示を入れる（`index.ts` 約 480 行目）。editor も置換（`@ravshansbox/pi-prompt-history` と排他）。
- 理由: 設定不可・費用なし表示・追加の model 要求と、目的に反する副作用が多い。

## 軸の推奨

| 選択肢 | 評価 |
|---|---|
| **A. 入れない（標準 footer のまま）** | 維持費ゼロ・衝突ゼロ。標準 footer は model・context・token・費用・git branch・setStatus を既に出す（pi 本体）。失うのは、色・折り返し・tools セグメント程度。subagents / todo は widget で見えるので、footer に無くても 12 分ジョブの進みは分かる |
| **B. `@narumitw/pi-statusline`（推し）** | 外部送信なし・footer のみ・設定 1 JSON。標準にない価値: 狭幅の優先度削り、`tools`（実行中 tool / 入力待ち）、cache 率、PR 参照 |
| C. `@narumitw/pi-starship` | TOML で完全に宣言。大きい（2.1 MB）。gh・言語コマンドは opt-in |
| D. `pi-powerline-footer` | 人気・保守は最良。ただし editor 置換など面積が大きい |

**最も推す 1 つ: B（`@narumitw/pi-statusline`）。ただし標準 footer で困っていなければ A。** 好みの問題が大きく、表示を磨くことの価値は安全性・保守費に比べて低い。

### 入れる場合の設定
- `pi-stock-packages` に足す行: `npm:@narumitw/pi-statusline@0.50.4`
- permission の追加: **不要**（ツールを追加しない。git 読み取りは拡張の子プロセスで、model の bash 経路ではない）。
- 利用者の設定ファイル: 既定のままなら不要。chezmoi で配るなら `<agentDir>/pi-statusline.json`（例: `{"palettePreset":"ocean","segments":["model","thinking","cwd","branch","tools","context","tokens","cache","cost"]}`。README の例を基にした推測。segment 名は README の表で確認済み: `provider model thinking cwd branch tools context tokens cache cost time turn brand`）。
- 併用禁止: `pi-starship`・`pi-powerline-footer` など、他の `setFooter` を呼ぶ拡張。

## 利用者に聞きたいこと
1. 標準 footer（A）で足りているか。不足があれば何か（cost・cache 率・tools・幅の折り返し）。
2. Windows Terminal のフォント（Nerd Font / Powerline glyph / 絵文字）は使えるか。使えない場合、`pi-statusline` の見た目が崩れる可能性がある（その場合は A、または powerline の ASCII preset）。
