# 読者に伝わる Markdown

- 冒頭に結論と、読者が次にできることを置く。見出しだけでも論点が分かるようにする。
- 1 段落には 1 つの論点。手順は番号付きリスト、順序のない並列は箇条書きにする。
- 共通の観点で比べるときは短いセルの表にする。条件や理由が長いなら表の下に書く。
- 流れや関係は、図の方が伝わるときだけ描く。図に頼らず、結論や見てほしい点を本文にも書く。画像には代替テキストを付ける。
- 用語を初出で説明する。コマンド・ファイル名はコード表記にし、リンクの文言は移動先が分かるものにする。
- 既存文書では依頼された節を優先し、文体に合わせるだけの全体書き換えは避ける。

対象文書や配布先に固有の規約があれば、そちらを優先する。
