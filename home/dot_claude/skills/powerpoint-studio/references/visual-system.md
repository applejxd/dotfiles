# Visual System

## Surface and three color roles

新規デッキは背景面と、意味を持つ3役を最初に決める。

| Role | Usage |
| --- | --- |
| Surface | スライド背景。原則1色 |
| Base | 本文文字、通常の線・情報 |
| Main | 見出し、ボックス、通常の強調 |
| Accent | 特に注目させる箇所。5〜10% |

白、黒、グレーなどのニュートラルは可読性のため補助的に使えるが、意味を持つ色を
4色以上へ増やさない。成功・警告・危険をすべて別色にせず、形、ラベル、線種でも区別する。

```json
{
  "surface_color": "F7F4EC",
  "base_color": "14213D",
  "main_color": "008F95",
  "accent_color": "E9A23B",
  "neutral_colors": ["FFFFFF", "5E6B78", "D8D0C5"],
  "allowed_background_colors": ["F7F4EC"],
  "max_background_colors": 1
}
```

```bash
uv run scripts/validate_style.py deck.pptx --policy style-policy.json
```

## Background

- 本文と表紙で背景を交互に変えて刺激を作らない。
- 原則として全ページを同じ surface 背景にする。
- 章の変化は余白、サイズ、main色の面、番号で示す。
- テンプレート指定時だけ、テンプレートの背景体系を優先する。

## Pills, badges, tags, and chips

小さい背景図形と文字を別々に配置するときは、背景の内側を文字のレイアウト領域にする。

- 水平余白を左右それぞれ0.08インチ以上確保する。
- 垂直余白を上下それぞれ0.04インチ以上確保する。
- 文字が収まらない場合は、文字箱だけを自動拡張しない。
- 優先順位は、ラベル短縮 → 背景と文字を同時拡張 → フォントを許容範囲で縮小。
- 文字と背景に `pill-*`, `badge-*`, `tag-*` など対応する object name を付ける。
- レンダリングと `quality_gate.py` の containment 検査を両方通す。

## Hierarchy

- 表紙のタイトルがデッキ内で最も大きい文字であること。
- 表紙タイトルは発表内容を表す名称にし、主張文は副題へ置く。
- 本文スライド上部の表題は、そのページの内容を簡潔に示す。
- 目次とまとめは、同じセクション名・順序・色役割を使う。

## Minimal slide chrome

ユーザー指定がない新規デッキでは、スライド外周をUIのように装飾しない。

- 小さい章ヘッダー、現在位置タブ、上端の帯を既定で付けない。
- 共通フッター、出典パス、制作方式、QA状態を既定で付けない。
- Part、章、現在位置はページタイトル自身へ統合する。
- 出典は必要な図、引用、数値の近くへ短く置き、全ページへ反復しない。
- ページ番号だけは全ページで必須とし、同じ位置と形式を使う。
- ユーザー指定テンプレート、ブランド規定、法務要件がある場合だけヘッダー／フッターを
  許可し、`chrome_policy` に `user-requested` と記録する。

```json
{
  "chrome_policy": {
    "enabled": true,
    "header": "none",
    "footer": "none",
    "page_numbers": "required"
  }
}
```

## Grid, proximity, and whitespace

- 共通の左端、右端、中央線を少数だけ定める。
- 類似要素の幅、高さ、間隔を揃える。
- 関連する要素は近づけ、異なるグループ間の距離を広げる。
- 枠線を増やす前に、近接と余白だけでグループが読めるか確認する。
- 余白を外側、カード内、関連要素間、非関連要素間に分けて設計する。
- 太い枠、影、囲み、色を重ねて強調しない。削除とサイズ差で優先度を作る。
- 表のヘッダーと行は、同じ列のアンカーから配置する。各々を目分量で中央寄せし、
  見出しだけをずらさない。左寄せの列なら見出しと本文の左端を揃える。
- カードの外形が同じでも、文字の読み始めや説明の段位置がばらばらなら整列したことには
  ならない。比較に必要な名前・図・説明・状態の順と位置を揃える。
- 行数が異なる比較リストは文字箱を上揃えにする。同じy座標でも縦中央揃えのままでは、
  先頭行の高さが一致しない。原寸レンダーの先頭行も確認する。
- 名称と補足が横並びで窮屈になる場合は、名称を上段、補足を下段へ積む。
  長い名称だけを小さくして横並びを維持するより、読める幅を使う。
- 大きい空白は直ちに欠点としない。小さい主要文字や図と不釣り合いに同居する場合に、
  未使用の幅・高さを可読性へ振り向ける。

## Fonts and line breaks

- CJK、Latin、数字、記号を同じレンダラーで確認し、字面・太さ・高さを揃える。
- デッキ全体でprimary sansを1書体に固定する。コード、識別子、パスだけmono 1書体を許可する。
- 推奨サイズ帯は表紙40〜56pt、本文タイトル25〜34pt、主要本文14〜22pt、
  注釈・出典11〜13.5pt、ページ番号10〜12pt。11pt未満は使用しない。
- 1ページで使用する文字サイズ段階は原則6段階以内とし、0.2pt刻みの場当たり的調整を避ける。
- 図中文字はスライドへ配置した**最終表示サイズ**で本文14〜18pt相当を目安とする。
  Graphvizの`fontsize`だけで判断せず、画像解像度と配置サイズによる縮小率を確認する。
- Graphviz、D2、Mermaid、PlantUMLなどのソースへprimary書体を明記する。
  ノード見出しは太字、説明とedge labelはRegularを基本とし、スライド本文と対応させる。
- 引用した原図・スクリーンショット内の書体は改変対象外だが、自作・再構成した図は必ず統一する。
- ポイント数だけで可読性を判定せず、投影サイズで確認する。
- 単語や意味単位の途中で改行せず、極端に短い最終行を作らない。
- フォントを縮小する前に、文章の短縮、枠幅、行間を調整する。
- 重要語、状態、境界、変数は口頭だけにせず画面上へラベルとして残す。
- `node()`等の共通部品で、説明文を無条件に注釈サイズへ落とさない。
  画面で読ませる内容か、補足として参照する内容かを先に判断する。
- `fit: "shrink"`は指定したptがそのまま表示される保証ではない。主要ラベルには、
  意味単位での改行と十分な枠幅・高さを与え、可能な限り縮小を不要にする。
- 長い技法名・章名は、Part番号と名称、名称と補足の境界で改行する。
  英単語を途中で折ったり、名称だけを他カードより大幅に小さくしたりしない。

```json
{
  "typography_policy": {
    "enabled": true,
    "primary_font": "Noto Sans CJK JP",
    "mono_font": "Noto Sans Mono CJK JP",
    "minimum_font_size": 11,
    "deck_title_range": [40, 56],
    "slide_title_range": [25, 34],
    "body_range": [14, 22],
    "caption_range": [11, 13.5],
    "page_number_range": [10, 12],
    "max_size_steps_per_slide": 6,
    "title_minimum_difference_pt": 5,
    "title_minimum_ratio": 1.2,
    "generated_diagram_apparent_font_range": [10, 18],
    "generated_diagram_sources": [
      {
        "path": "assets/diagrams/architecture.dot",
        "image": "assets/diagrams/architecture.png",
        "placement_width_inches": 10.5,
        "render_dpi": 220
      }
    ]
  }
}
```
