# 環境変数の一覧・個別参照は許可リスト方式で止め、診断は env-check に集める

- **ステータス**: Accepted
- **日付**: 2026-10-25
- **決定者**: applejxd

## コンテキスト

`pis` の内側で、プロキシの設定を診断しようとして `env | grep -i proxy` を実行したところ、`環境変数を全件出力するコマンドは許可されていません: env` で止まり、
同じ複合コマンドの別の部分（`gh api …`）も実行されなかった。拒否文は `echo $VAR_NAME` を案内するだけで、変数名を列挙できないと診断が難しい。

環境変数の値には、秘密（トークン・鍵）や、認証情報つきのプロキシの URL が入りうる。従来の判定は、名前が秘密らしいもの（`_SENSITIVE_ENV_RE`）を止める拒否リスト型だった。
判定器は Python（`rules_files.py`）と TypeScript（`rules_files.ts`）の二重実装で、表は `tables.toml` を共有する。

## 検討した選択肢

### 選択肢 1: パイプの形を許可する

`env | cut -d= -f1` のように、値を必ず削る形だけを通す。

- **利点**: 診断に必要な「変数名の列挙」が自然にできる
- **欠点**: 判定の抜け穴を作りやすい（`cut -f1,2`、`; env`、`tee` など）。許可の形を狭く保つ必要があり、パイプの意味解析が要る

### 選択肢 2: 許可リスト方式 + 診断用の許可済みコマンド（採用）

`env` / `printenv` / `export -p` / `declare -p` などの一覧と、許可リスト外の名前の個別参照を止める。診断は、専用スキルのスクリプトに集める。

- **利点**: 抜け穴の議論が要らず、スクリプトの出力を完全に管理できる。拒否文から診断の入口へ誘導できる
- **欠点**: スクリプトを足す保守と、docs・試験の追加が要る

## 決定事項

選択肢 2 を採用する（利用者の指示: 「環境変数関連は広く禁止して、ホワイトリスト形式で許可する。ただし誘導はしっかり」）。

- 許可リストは `tables.toml` の `[rules_files] env_readable_names`（`HOME`・`USER`・`LANG`・`WEBSEARCH_BROKER_URL` など、認証情報が入りえないもの）。プロキシの URL は載せない
- 一覧の出力と、許可リスト外の個別参照（`printenv NAME` / `declare -p NAME`）は deny。代入（`export FOO=1`）と `set -eu` は通す
- 拒否文に、(1) 複合コマンドの場合は全体を実行していないこと、(2) 診断の入口（`env-check` スキルの `env_check.py` の `names` / `show` / `get`）、(3) 許可リスト、を必ず入れる
- `env_check.py` は、秘密らしい名前の値を出さず、許可リストと `proxy` / `broker` などの名前の値を出し、URL の認証情報は `***@` に伏せる。`[pi.skill_scripts]` で確認なしに実行できる
- `echo $NAME` は従来のまま（秘密らしい名前の出力だけ止める）。広げると `$HOME` や `$PWD` を使う通常の開発操作を止めてしまう

理由: 値の漏れを止める目的は、許可リスト方式の方が抜け穴が少ない。誘導を拒否文に必ず入れることで、診断が止まる問題（今回の発端）を避ける。

## 決定の確認方法

- [x] 拒否の形（`env | cut -d= -f1`、`printenv HTTPS_PROXY`、`declare -p FOO_BAR` など）が deny で、許可リストの形が通る（`test_check_bash_sensitive.py`）
- [x] 拒否文に診断の入口と許可リストが入る（同上）
- [x] `env_check.py` が、秘密らしい名前の値を出さず、URL の認証情報を伏せる（`test_env_check.py`）
- [x] Python 版と TS 版の判定が golden で一致する（`checks_golden.jsonl`）
- [ ] `pis` の内側で、拒否文の誘導どおりに診断が通ること（未実測）

## 結果

### ポジティブな結果

- 診断の入口が 1 つになり、値を漏らさずに変数の設定の有無を確かめられる

### ネガティブな結果

- 秘密らしい名前の正規表現を、`env_check.py` に複製して持つ（`test_env_check.py` が一致を固定する）
- 名前に `SESSION` を含む無害な変数（`WT_SESSION`）が、`echo $WT_SESSION` で止まる誤検知が残る（未修正。[記録 S2](../research/agents/pis-sandbox-field-test.md#記録-s2--2026-10-25内側のネットワークページ取得クリップボード)）

### 中立的な結果

- 許可リストへ足すときは `tables.toml` を直し、golden を再生成する
