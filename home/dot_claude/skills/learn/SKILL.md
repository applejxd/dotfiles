# learn

> **この skill は fork しない（`context: fork` を付けない）**
>
> 入力が親の会話そのものなので、独立したサブエージェントでは成立しない。
> OpenCode は `context` を読み捨てるため無害だが（記録 E1）、Claude Code 側で
> 効くと**会話が見えないまま知見を捏造する**ことになる。
> see docs/research/opencode/skill-frontmatter.md

## 手順

### 1. 現状の把握

- プロジェクトルートの `AGENTS.md`, `CLAUDE.md`, `.claude/CLAUDE.md` を探し、読み込む
- 存在しない場合、その旨を最終レポートに含める

### 2. 知見の抽出

これまでの会話を振り返り、以下の観点で追記すべき情報を特定する:

- **ビルド・テスト手順**: 新たに判明したコマンドや手順
- **コードスタイルの暗黙知**: 合意した命名規則、設計方針、パターン
- **アーキテクチャ上の決定**: 技術選定、依存関係、ディレクトリ構成の変更
- **落とし穴・注意事項**: デバッグで判明したハマりポイント、既知の制限
- **ワークフローの変更**: Git 運用、デプロイ手順、CI/CD の更新
- **ユーザーの好み**: コーディングスタイルや作業フローの嗜好

### 3. 肥大化防止チェック

差分を作成する前に以下を必ず確認する:

- **重複排除**: 既存の記載と意味的に重複する内容は追加せず、既存項目の更新で対応
- **統合整理**: 同一セクションに類似の項目が 5 つ以上並ぶ場合は上位概念でまとめ直す
- **詳細の分離**: 3 行を超える詳細は AGENTS.md 本体に書かず、別ファイル（`.claude/rules/`, `docs/` 等）に切り出して参照リンクを貼る
- **陳腐化チェック**: 新たな知見で古くなった記載があれば更新・削除を提案

### 4. 差分を提案する

- 肥大化防止チェックを通過した変更を、対象ファイルごとの差分（追記・更新・削除）として提示する。**この段階ではファイルに書き込まない**
- 詳細の分離が必要な場合は、作成するファイルのパスと内容の要約、AGENTS.md に置く参照リンクも併せて示す

### 5. 反映（明示的に頼まれた場合だけ）

- ユーザーが「反映して」「書き込んで」など明示的に指示した場合に限り、提案した差分を書き込む。一部だけ採用と言われたらその部分だけ反映する
- 指示が無ければ手順 4 の提案で終える

### 6. 報告

ユーザーへの報告は以下の形式で**簡潔に**まとめる。反映していなければ「提案」、反映したら「反映済み」と書く。

```text
## AGENTS.md の更新<提案 | 反映済み>

変更前: <N> 行 → 変更後: <M> 行

### 変更内容
- [セクション名]: <変更の要約>（理由: この会話で○○が判明したため）

### 外部ファイル
- `<ファイルパス>`: <内容の要約>
```

反映済みの場合は、`git diff` で確認でき、不要なら `git checkout` で戻せることを添える。

## 制約

- **会話に根拠のない情報を追加しない**: 推測で記載しない
- **変更理由を明記する**: 「この会話で○○が判明したため」等
- **AGENTS.md は簡潔に保つ**: 詳細は別ファイルに分離し参照で繋ぐ
- **言語**: ユーザーの使用言語に合わせる
