# 条件を満たす実装は 1 件でも worker に委譲する

- **ステータス**: Accepted
- **日付**: 2026-11-26
- **決定者**: 利用者
- **結論**: 親は編集前に実装担当を決める。並列にできる件数ではなく、検証可能な作業単位と委譲の利点で判断する。

## コンテキスト

- [ADR-0033](0033-delegate-subagents-by-standing-instruction.md) は、独立した実装が 2 件以上のときに常設の指示で `worker` の起動を求めていた。
- [feature-orchestration](../../.agents/skills/feature-orchestration/SKILL.md) は単独の実装も対象としていた。起動条件と手順の対象に差があった。
- 別の会話で探索や実装を行うと、親に残る中間出力を減らせる。一方で、契約の作成・子の再調査・親の再検証が増える。
- [CooperBench](https://arxiv.org/abs/2601.13295)（2026-01）は、潜在的に衝突する機能を 2 エージェントに分けると、単独実装より成功率が平均 30% 低下したと報告した。chezmoi での改善幅を示すものではない。

## 検討した選択肢

| 選択肢 | 利点 | 欠点 | 判断 |
| --- | --- | --- | --- |
| 独立した 2 件以上だけ | 条件が簡単 | 有益な単独委譲を逃す | 見送り |
| 変更の大きさで起動 | 起動条件が明快 | 曖昧な設計を渡してしまう | 見送り |
| 作業の切り出しと利点で判断 | 単独と並列を分けて判断 | 親の判断と観測が要る | 採用 |

## 決定事項

- 自宅・会社で共通の常設指示にする。数分で済む変更や、設計を対話で詰める作業は親が担当する。
- 目的・編集範囲・禁止事項・合格条件が固まった非小規模の実装は 1 件でも対象とする。探索の分離などの利点が引き継ぎと再検証に見合うなら委譲する。
- 複数の実装は、担当範囲が重ならず、前提とインターフェースが確定したときだけ並列にする。書き手を worktree ごとに分ける。
- コードの横断調査は `scout`、外部の一次資料の照合は `researcher` に任せる。問いが 1 件でも対象とする。調査を並列にするのは、互いの結果を待たずに進められる場合だけとする。
- 親は検査を再実行する。挙動・設計・互換性・権限・安全に影響する変更は、数行でもコミット前に新しいコンテキストの読み取り専用 `reviewer` に渡す。
- 利用者が委譲を禁止した範囲では、起動条件や監査手順より禁止を優先し、子を起動しない。別の規則が独立監査を要求する場合は、未監査のままコミットしない。
- 委譲の条件は常設の指示で伝える。権限の強制とは分け、モデル・package・実行上限は変更しない。

根拠は、[Codex の常設指示による授権](https://learn.chatgpt.com/docs/agent-configuration/subagents) と [Claude Code の作業分離](https://code.claude.com/docs/en/agents) を参照した。2026-11-26 に確認した。

## 決定の確認方法

- 自宅用・会社用の描画に同じ起動条件が含まれることを試験する。
- 1〜2 週間、委譲条件を満たした実装の件数を分母にし、起動・見送りの理由を確認する。
- 親が書き直した件数、受け入れまでの時間、起動と権限の失敗も見る。手戻りや時間が増えるなら、起動条件を絞る。
