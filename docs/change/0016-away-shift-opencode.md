## 目的と非目的

離席中に検証・実験を反復させる skill `away-shift` に、**深層学習の学習ジョブが止まったときの原因調査と再開を任せる運用**を決める
（連休中などに、学習ジョブが止まったとき。どこで・何を任せるか）。制約のある環境の機（Claude Code + Bedrock）でも使う。

非目的:

- 制約のある環境の機からこの skill を外すこと（2026-10-07 の棚卸しで、その環境でも使うため残すと決めた）
- away-shift を pi 上で動かすこと（[CHG-0030](0030-away-shift-on-pi.md) の範囲。0030 は、この案件の段 2 を非目的にしている）
- OpenCode 向けの最適化（OpenCode を使っていない。2026-10-20、[CHG-0020](0020-pi-migration.md)）

## 現在地

段 2 の決定が、どこにも引き継がれていない（CHG-0030 の非目的）。away-shift 自体は、pi では CHG-0030 の P1・P2 まで実装済みで、
残りは実機（TUI の `pis`）での確認と P3（書き込み範囲の役割）。

2026-10-08 時点の気づき（2026-10-25 に有効性を整理した）:

- **無効**（OpenCode 前提）: `SKILL.md:23` の autopilot の前提が OpenCode で成り立つか。frontmatter の `allowed-tools`（`SKILL.md:4`）が OpenCode で読み捨てられること
  （[skill の frontmatter の調査](../research/opencode/skill-frontmatter.md)）。OpenCode の permission と事前検査（`scripts/executable_preflight.py`）の判定のずれ
  （preflight は、pi では `--judge pi` で pi の判定器に問い合わせる形になった）
- **有効（段 2 の論点）**: 作業範囲は `./.tmp/away-shift/` に限られる（`SKILL.md:3`）。学習ジョブの再開では、本来のチェックポイントやログの場所に書く、
  プロセスを起動し直す、といった範囲外の操作が要りがちで、範囲外として止まる可能性がある
- **有効（段 2 の論点）**: 制約のある環境の機では、無人でエージェントを動かすことが組織の規則で許されない場合があり、長時間の反復で Bedrock の利用料がどこまで積み上がるかも確かめる必要がある
