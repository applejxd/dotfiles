# 依頼（worker）: ツール隔離の最小プロトタイプ（feature/remote-tools-spike）

担当: 1 worktree = 1 feature = 1 worker。worktree は `/home/alice/.local/share/chezmoi/.tmp/worktrees/remote-tools-spike`（枝 `feature/remote-tools-spike`。基は develop）。この中だけを編集する。**コミットしない**。`git flow finish`・`merge`・`rebase`・`reset`・`git -C` は使わない。heredoc は使えない（ファイルの作成・編集は guarded_write / guarded_edit）。書き込みと実行は別のターンにする。

## 目的
pi のフルガード付きハーネス（`home/dot_config/pi/harness/`）に、**ツール隔離**（pi 本体と判定器はホストに残し、ツール `bash`・`read`・`write`・`edit`・`grep`・`find`・`ls` の**実行だけ**を別の環境へ流す）の**最小の差し込み口**を作り、仕組みが成立するかを**実測で確かめる**スパイクを行う。利用者の決定: kcage（Incus の箱に pi を入れる方式）に固執せず、pi は隔離せずツールだけ隔離する設計を検討する。実行先の第一候補は WSL 内の Incus の箱（`kcage exec -- <argv>`。標準入出力にバイト列を流せる。1 コマンドごとに子プロセス）。**このスパイクでは実機の箱は使わず、実行先を「コマンド接頭辞」で差し替え可能にして、偽の実行先（ローカルの `sh` や `env -i` のラッパー）で試験する。**

## 実装の方針（調査で決まったこと）
- **既定は無効。** 環境変数 `PI_REMOTE_EXEC`（JSON の argv 配列。例 `["kcage","exec","--"]` や、試験用の `["sh","-c",…]`）が設定されたときだけ、各 `create*ToolDefinition(cwd, { operations })` に新しい operations を渡す。未設定なら**現行の挙動と 1 バイトも変わらない**こと（golden・既存の試験がそのまま通る）。
- **鏡写し cwd**: ホスト側の cwd と実行先の cwd は**同じ絶対パスの文字列**を前提にする（kcage の shared モードはホストと同じパスで重ねるので変換が要らない）。パス変換は入れない。判定器（`judge/`）は無改造。
- 新規モジュール `home/dot_config/pi/harness/remote-ops.ts` に、トランスポート・環境変数の篩い・各ツールの operations を置く。`index.ts` の既存の編集は最小（差し込みの分岐だけ）。**`judge/` の入力の形（`Request`）と `guarded_` の接頭辞は変えない**（golden 試験が固定）。
- **フルガードの判定は実行より先**（`tool_call`→`execute`）のまま。実行先の差し替えは `execute` の中の operations だけ。
- **環境変数を渡さない**: 実行先へ渡す環境は許可リスト方式（`PATH`・`LANG`・`LC_*`・`TERM`・`HOME` は実行先の値に任せる・`AGENT_ENV`。`PI_*`・`GH_TOKEN`・`COPILOT_*`・`*_TOKEN`・`*_KEY`・`SSH_*`・`AWS_*` などは**渡さない**）。`bash` の operations の `env` 引数は無視して許可リストを使う。
- **子プロセスは argv 配列で起こす**（シェル文字列を連結しない）。bash は `[...prefix, "sh", "-c", 'cd "$1" && exec bash -c "$2"', "sh", cwd, command]` の形（cwd とコマンドは位置引数）。stdin は無し・pty 無し・stdout と stderr を混ぜて `onData` に流す。
- **中断・時間切れ**: `AbortSignal` と timeout で、ローカルの子プロセス（プロセスグループごと）を kill する。実行先の中の子プロセスの後始末は「できる範囲」でよい（実行先に `timeout`・`kill` を使う案を試し、**止まらないケースがあれば報告に正直に書く**）。
- **read**: 実行先の `cat`（stdout の Buffer。バイナリもそのまま。上限を設ける）。**write**: 実行先で一時ファイルへ書いて `mv`（stdin から。base64 を argv に載せない）。`mkdir`・`access` も実行先で。**edit** は read と write を組み合わせる。**ls**: `exists`/`stat`/`readdir` は 1 回の `find -maxdepth 1` 等で取ってキャッシュし、往復を減らす。**find**: 実行先の `find`/`rg --files`。**grep**: `operations` では検索エンジンを差し替えられない（公式の限界）ので、`grep` ツールは自作の `execute`（実行先の `rg`、無ければ `grep -rn`）で `GrepToolDetails` の形を保って返す。まず **bash・read・write・edit を完成**させ、ls・find・grep は次に実装する（時間が足りなければ未実装のものを報告に明記し、その間は `PI_REMOTE_EXEC` 設定時に**組み込みのローカル実行へ黙ってフォールバックせず**、明確に拒否する＝fail-closed）。
- **同時実行**: ツール呼び出しは既定で並列なので、実行先への同時起動数に上限（既定 4。環境変数 `PI_REMOTE_EXEC_MAX` で変更可）を設ける。
- **`user_bash`（`!` コマンド）** は `tool_call` を通らない。このスパイクでは、`PI_REMOTE_EXEC` 設定時は `user_bash` を**実行先へ流す**か**拒否する**かのどちらかにして（決めた方を報告に書く）、ホストで素通しにしない。

## 試験（必須。実行して出力を根拠に）
- **単体**（偽の実行先）: 実行先を `["sh","-c",…]` や `env -i` のラッパー、**別の一時ディレクトリを cwd にして記録するスクリプト**にして、(a) bash の終了コード・出力・stderr の混在・大きな出力・改行とクオートを含むコマンド、(b) 中断と時間切れで子が残らない、(c) 環境変数の遮断（`HOST_SECRET=x` をホスト側に置いて、実行先の `env` に**現れない**こと。許可リストの変数だけ）、(d) read（バイナリ・大きなファイル・存在しないファイル）、(e) write（原子的・上書き・mkdir）、(f) edit、(g) 同時数の上限、(h) 実行先が壊れた（非 0 で即終了・見つからない）ときのエラー、(i) fail-closed（未実装のツール）。
- **配線の試験**（`test/agents/test_pi_harness.py` 型の faux モデル）: `PI_REMOTE_EXEC` を設定した pi で、**フルガードの deny が実行より先に効く**（deny されたコマンドは実行先に届かない）こと、許可されたコマンドが**実行先の記録に残る**こと（＝ホストで直接実行されていない）こと、`PI_REMOTE_EXEC` 未設定では現行と同じであること。
- 既存の試験が**そのまま通る**こと: `uv run --with pytest --with pytest-xdist --with pyyaml --no-project pytest test/agents/ -q -n 4 --dist worksteal`（全体を回すのは重いので、関連: `test_pi_harness.py`・`test_pi_*` のうちハーネスの index.ts を触るもの・`judge_golden` 系。最後に 1 回は `test/agents/` 全体）。ソース文字列を固定している試験（`test_pi_session_tmp.py:113`・`test_pi_quiet_notices.py:293`・`test_work_settle_wire.py:545`・`test_pi_harness_removal.py:84`・`test_pi_integrate_index.py:65`）を壊さない。
- 新しい試験ファイルは `scripts/verify.py` の該当の Rule（pi のハーネス）に登録が要る（`test/test_verify.py` が見つける）。登録の仕方を `verify.py` の `_PI_TESTS` で確認し、**登録が要る旨を報告に書く**（自分で `scripts/verify.py` を編集してよいのは、この登録のためだけ）。
- テンプレート（`*.tmpl`）を触ったら `mise exec -- python3 scripts/lint_templates.py`。TS の型検査・整形の道具がリポジトリにあれば使う。

## 守る条件
- C1: ホストのフルガードの**判定器の入力・golden・`common.toml.tmpl` の規則は変更しない**（権限を広げる変更はしない）。実行先を差し替えるだけで、拒否が増えることはあっても減らない。
- C2: 公開リポジトリ。ホームの絶対パス・個人情報を書かない。コメントと docs は日本語。
- C3: 実機（Incus・`kcage exec`・ネットワーク）は使わない。実機で確かめていないことは断定しない。
- C4: 既定は無効（環境変数が無ければ何も変わらない）。

## 報告の形式
先頭に結論（成立したか・難所は何か）。「根拠」（実行したコマンドと結果）、「実測で分かったこと」（中断で箱の中の子が止まるか・遅延・出力の上限・並列・pty が無いことの影響）、「未実装・fail-closed にしたもの」、「判断した点」（`user_bash` の扱いなど）、「契約への提案」、「次に要る作業（実機の箱での確認・子エージェント・guarded_action の git・bg_run・post_edit・PR summary のどれをどうするか）」。長い説明は書かない。
