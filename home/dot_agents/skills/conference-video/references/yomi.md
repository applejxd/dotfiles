# 読み辞書(yomi.json)の書き方

VOICEVOX の読みの辞書。英字・略語・専門用語の誤読を直す。**手で編集せず**、確認画面の
「読み」タブか `yomi.py` の CLI で直す(ADR-0003。サーバと CLI が同時に書いても、
更新が消えないように、窓口 `state_store` だけが書く)。

## 形式

`yomi.json`(UTF-8)。1 語が 1 項目で、キーは台本に書いた表記(大文字小文字を区別する)。

```json
{
  "schema": 1,
  "entries": {
    "SLAM": {"pron": "スラム", "accent": 1, "status": "確認済み", "note": ""},
    "KL": {"pron": "ケーエル", "accent": 3, "status": "候補", "note": "下書き"}
  }
}
```

| 項目 | 内容 |
| --- | --- |
| pron | 全角カタカナの読み |
| accent | アクセント核のモーラ位置(0 は平板) |
| status | `確認済み` または `候補` |
| note | 自由記述。読みには影響しない |

CLI と画面では、`ス'ラム` のように、核の直後に `'` を 1 つ書く記法を使う
(`pron` と `accent` に変換される)。

## 直し方(読みの修正はここ)

動画ごとの辞書は、**セッションフォルダの `yomi.json`**(例:
`~/.conference-video/<slug>/yomi.json`)。場所は `tts_generate.py` の出力の
「読み辞書」の行(「この動画(ここを直す)」)に絶対パスで出る。

```bash
yomi.py list [--all]                  # 一覧(--all は層を合成した結果)
yomi.py set 表記 読み [--status 候補] [--note メモ]   # 既定で確認済みにする
yomi.py rm 表記
yomi.py confirm 表記...               # 候補を確認済みにする
```

- 既定は `./yomi.json`。`--file PATH` で別のファイル、`--user` でユーザー共通の辞書を直す
- どの語を直すかは `review_sheet.py --notes`(画面で書いた指摘)で分かる
- 漢字の語(疎な など)も、同じように `set` で直せる
- どの語をどう読めばよいか分からないときは、会話で「○○ を △△ と読んで」と
  伝えてもよい(エージェントが `set` する)
- ハイフンでつながる語(`SLAM-MER`、`7-Scenes`)は 1 つの表記として書ける。
  台本に「7-Scenes」と「7Scenes」のどちらで書いても同じ辞書が効く
  (ENGINE の辞書はハイフン入りを一致させられないため、内部でハイフンを
  除いた形で登録し、読み上げる文も同じ形に直す。字幕は元の表記のまま)
- CLI の終了コード: 0 = 成功、1 = 該当なし(`rm` / `confirm`)、2 = エラー
  (壊れた辞書・不正な読み・書き込み失敗)、3 = 他の書き手と競合し続けた

## アクセントの書き方

`'` はアクセントが下がる直前のモーラの後ろに置く。無ければ平板。

| 読み | 意味 |
| --- | --- |
| `ス'ラム` | 1 モーラ目で下がる(頭高) |
| `ケーエ'ル` | 3 モーラ目で下がる |
| `スラム` | 下がらない(平板) |

- 拗音(`キョ`)は 1 モーラ、促音(`ッ`)・撥音(`ン`)・長音(`ー`)も
  それぞれ 1 モーラ
- 聞いて不自然なら `'` の位置を動かす。1 つずつ動かして聞き比べる
- 初期値(`assets/yomi.default.json`)のアクセントは未聴の推測

## 層

後のものが前を上書きする。

1. 既定: スキル同梱の `assets/yomi.default.json`
2. ユーザー共通: `$CONF_VIDEO_HOME/yomi.json`(既定 `~/.conference-video/yomi.json`)。
   直した読みを次の動画でも使うために置く
3. 動画ごと: セッションフォルダの `yomi.json`

`--yomi FILE...` を指定したコマンドは、その FILE だけを使う(層は使わない)。

## いつ作り・直すか

1. **取材**: 利用者に読みが分かれる固有名詞・略語を聞き、先に入れる(`yomi.py set`)
2. **台本の後**: `yomi.py candidates narration.txt --out yomi.json` で、
   辞書に無い英字を候補にする。ENGINE の現在の読みが下書きで入る
   (ENGINE がカタカナで返さなかった語は、候補にできず、一覧で報告される。
   `yomi.py set` で入れる)。台本の確認と同時に、利用者が画面で読みを直し、状態を
   「確認済み」にする。候補が残ると `narration_check.py` が止まり、候補は合成に使われない
3. **聞いた後**: 指摘された語を画面か `yomi.py set` で直して合成をやり直す。
   辞書は合成のキャッシュの鍵に入るので、直した語を含む行だけ再合成される。
   語ごとに聞き比べたいときは `yomi.py audition` で試聴音声を作る
   (`audition/all.wav` が全語の連結、`index.csv` が順序)

## 読み上げ前の整形(字幕は元のまま)

字幕を読みやすくする書き方が、読み上げでは悪影響になることがある。字幕はそのままにし、
**ENGINE に渡す直前の 1 か所**(`speech.prepare()`。`scripts/speech.py`)で整形する。
台本は読みやすさを優先して書いてよい。規則は名前つきの表(`speech.RULES`)で、何が変わるかは
`narration_check.py` が行ごとに注意として示し、`readings.py` が「読み上げ文」を併記する。

- `ja-space`: 日本語と英数字の間の空白(`精度が 3 倍`、`SLAM を`)を除く(息継ぎの間になる)。
  英数字同士の空白(`Sparse Voxel Grid`)は残す
- `compound-hyphen`: 複合語のハイフン(`SLAM-MER`)は ENGINE の辞書に一致しないので除いた形で渡す
- 整形の結果は行ごとのキャッシュ鍵に入る(整形規則を変えると、影響する行だけ再合成される)
- 規則を増やすときは、先に実エンジンで影響を確かめ(推測で入れない)、`speech.RULES` へ足し、
  ここに書き、`tests/test_speech.py` の例を通す。ENGINE に文を渡す新しい経路も、必ず `prepare()` を通す

逆向きの問題も防ぐ: 音を合わせるために**字幕に読み(カタカナ)を書く**と、字幕が正式名称でなくなる。
字幕は正式名称で書き、読みは辞書で直す。`narration_check.py` は、辞書の表記が行に無く、
その読みがカタカナで行にあるときに指摘する(`SLAM-MER(スラマー)` のような注記、
より長いカタカナ語の一部、候補の語は対象外。意図したカタカナ表記は `--allow-kana`)。
辞書に無いカタカナの当て字は検出できないので、英字の表記を先に辞書へ入れておく。

## 注意

- 下書きの読みは ENGINE の推定で、長音の位置などが不完全なことがある。
  必ず直す前提で扱う
- 登録は優先度 9(既定辞書に負けないため)。ENGINE のユーザー辞書は
  プロセスの間だけ残る(Docker を作り直すと消えるが、毎回 `yomi.json` から登録し直す)
- 辞書から消した語・候補に戻した語は、次の合成(`tts_generate.py`)・登録(`yomi.py register`)で
  ENGINE から取り除く(優先度 9 の登録だけ。別の動画の辞書の語も、いまの辞書に無ければ取り除かれる)。
  ENGINE のエディタ等でユーザー自身が登録した語(既定の優先度 5)には触れない。
  `yomi.py register --no-prune` で取り除きを止められる
- 漢字語の誤読(`疎な` など)は、候補にならない(英字だけを抽出する)。
  `readings.py` の仮名を見て、必要な語を `yomi.py set` で足す
- 辞書が壊れている(手で編集した、途中で切れた)と、スクリプトも画面も書かずに止まる。
  内容を直すか、別名に退避して作り直す
