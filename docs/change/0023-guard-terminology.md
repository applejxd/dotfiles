# CHG-0023: 「ハーネス」の呼び方を整理し、`pis` をサンドボックス既定にする

- **状態**: In progress
- **更新日**: 2026-10-14
- **基準**: コミット 8cab246、pi 1.1.0、WSL2 (Ubuntu)

## 目的と非目的

**目的**:

1. 利用者の感覚（pi 本体を含む仕組み全体が「ハーネス」）と、このリポジトリの呼称（pi に足す判定の拡張を「ハーネス」）の食い違いをなくす。
   判定の層は「ガード」、OS の隔離は「サンドボックス」と呼び分ける
2. `pis` を、サンドボックス（Fence）つきの起動を既定にする。サンドボックス無しの選択肢をなくせるかを決める

**非目的**: 識別子（`PI_HARNESS_*`・`~/.config/pi/harness`・テスト名・`--boundary`）の改名（段 4 で別に判断）。
過去の案件・調査記録・ADR の本文の書き換え（当時の記録なので触らない）。

## 用語

| 用語 | 指すもの | 旧称 |
| --- | --- | --- |
| ハーネス | pi 本体を含む仕組み全体（一般の用法。このリポジトリでは特定の拡張を指さない） | （拡張を指していた） |
| ガード | ツール呼び出しを判定し、allow / ask / deny に振り分ける層 | ハーネス（拡張の意味のとき） |
| フルガード | `pis` で効く、役割・確認・伏字化まで含むガード | ハーネス |
| 簡易ガード | 素の `pi` に付く、deny と伏字化だけのガード | 素の pi のガード |
| サンドボックス | Fence による OS レベルの隔離。ガードとは別の層 | 境界 |

正本は [pi のガード](../spec/pi-guard.md#用語)。

## 現在地

- 段 1・2 は完了。旧称は過去の案件・調査記録・ADR（`docs/change/` `docs/research/` `docs/adr/`）に残る。
  ファイル名も変えていない（`0006-pi-harness-trial.md`・`pi-harness-spike.md` など）。対応は [pi のガード](../spec/pi-guard.md#用語)
- 検証: `test/agents/` と `test_windows_assets.py`・`test_chezmoi_templates.py` は通った。Windows 実機は未確認（コメントと文言のみの変更）

## 未解決点

段 3 の前に決めること。`docs/spec/pi-guard.md#サンドボックス` と CHG-0020 の段 4 から分かる現状:

- **サンドボックスでは拡張が未対応**: `pis --boundary` は起動を `ocs` に任せるので、`todo`・`plan`・`btw`・`activity` を足していない
- **Orca の状態表示**: サンドボックスの内側は `~/.pi/agent` を読めないので使えない
- **OS**: Fence に依るので Ubuntu / WSL のみ。Windows・macOS で「サンドボックス無しをなくす」と `pis` が使えなくなる
- **サンドボックス内の判定の既定**: `PI_HARNESS_BOUNDARY=1` を判定器へ渡すが、判定器はまだ使っていない（確認を外すかは未定）
- **`on/off` の経緯**: 段 4 としてガード（段 2・3）のあとに足した。既定にするかどうかを検討した記録は見つからない

## 次の調査・実験

1. 拡張（`todo`・`plan`・`btw`・`activity`）をサンドボックスの中でも読める形にできるか（`ocs` の `pi.py` の起動引数）
2. 既定をサンドボックスにして、サンドボックス無しを `--no-boundary` のような明示の脱出口にするか、完全になくすか
3. Windows・macOS は対象外とするか（`pis` を Unix 限定のまま、サンドボックスは Ubuntu / WSL のみ）
