# Independent Review Rubric

レビュアーには編集ソースを見せず、PPTX、レンダリング PNG、要求、deck plan を渡す。

## Pass 1: montage

- 物語の流れが一目で分かるか
- 同じ構図や密度が連続していないか
- 重要ページに視覚的ピークがあるか
- 章の切れ目と結論が分かるか
- 背景色が頻繁に反転せず、base / main / accent の役割が一貫しているか
- 各ページを一文のclaimへ要約でき、すべての要素がその一文を支えるか
- focusedは5、overviewは7を超える情報単位を同時に処理させていないか
- overviewは認識すべき構造を明示し、細かいラベルを会場で読ませようとしていないか
- ユーザー指定なしで小さいヘッダー、現在位置帯、共通フッターを追加していないか
- ページ番号が全ページの一定位置にあり、出典は必要な要素の近くへ置かれているか
- 本文、ネイティブ図、自作の外部図でprimary/mono書体が統一されているか
- タイトル、本文、注釈、ページ番号のサイズ階層が一定で、図中文字だけ過大・過小でないか
- 1枚目がタイトル、長い発表の2枚目が目次、最後がまとめになっているか

## Pass 2: full-size slides

- 3 秒でタイトル、主要証拠、結論が読めるか
- テキスト切れ、折返し事故、軸ラベル欠けがないか
- pill / badge / tag の文字が背景図形からはみ出していないか
- 日本語の重要語が一文字だけ次行へ孤立していないか
- 罫線、矢印、区切り線が文字の字面を横切っていないか
- 図の矢印、ノード、凡例、注釈が論理的か
- 入口から終了まで全矢印を追えるか。戻り線が別の枝やラベルと接触していないか
- 条件ラベルが線上ではなく脇にあり、説明用ラベルが架空の実行ノードに見えないか
- 元画像ではなく最終PDFでもノード間隔、8px以上の線・ラベル間隔、矢印先端が保たれるか
- スクリーンショットがぼけず、見せたい箇所が分かるか
- テンプレートの余白、書体、配色、フッターが保たれるか
- 表紙タイトルが副題や主張文より大きいか
- 表の列見出しとセルが同じアンカーへ揃い、見出しだけがずれていないか
- 横並びの長い名称・補足を小さく押し込まず、意味に沿った段分け・改行になっているか
- カード内の主要語に十分な大きさがあり、補足やバッジの方が目立っていないか
- 良好なページや承認済みの図を、統一感だけを理由に不必要に作り替えていないか
- 一般説明の英語混在を減らし、正式名称・コード識別子は保持しているか
- 「予算」等の単位が曖昧な語や、終了処理を反復すると読める表現が残っていないか

## Pass 3: factual integrity

- タイトルの主張を視覚が実際に支えるか
- 数値、単位、期間、条件、出典が一致するか
- グラフの軸、尺度、色、集計が誤解を招かないか
- 装飾を証拠のように扱っていないか
- 引用符内が原文と一致し、翻訳・省略・意訳が明示されているか
- 実装名、状態名、制御フローが原コードと一致するか
- 日本語化によって条件・単位・上限・処理の向きを変えていないか
- direct / derived / illustrative / opinion が区別されているか
- 図・スクリーンショットの出典、ライセンス、変更内容を追跡できるか

## Pass 4: timing and delivery

- 各スライドの予定時間と話者ノートが対応しているか
- 図を指す順番、具体例、次ページへの接続がノートにあるか
- 約10分ごとのチェックポイントと遅延時の短縮策があるか
- デモ、問いかけ、間、質疑の時間を含んでいるか
- リハーサル、TTS、文字数推定のどれを使ったか正確に記録しているか

## Output

finding は次の形式に限定する。

```json
{
  "slide": 4,
  "severity": "error|warning",
  "category": "layout|readability|narrative|visual-integrity|factual|template",
  "problem": "観察可能な問題",
  "evidence": "どこを見て判断したか",
  "fix": "実行可能な修正"
}
```

好みだけの指摘、根拠のない全面作り直し、抽象的な「もっと良く」は除外する。
