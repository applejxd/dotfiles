# 終了した案件を `change/closed/` へ移す

- **ステータス**: Accepted
- **日付**: 2026-09-22
- **決定者**: applejxd

## コンテキスト

[ADR-0010](0010-exploratory-spec-driven-docs.md) で docs を 4 種類に分けた
とき、終了した案件の扱いをこう決めた。

> 終了した案件は削除せず、状態と終了日を付けて同じパスに残す。目的（古い計画を
> 現在の指示として誤読しない）は、索引の「活動中」から外すだけで達成できる。
> **別ディレクトリへ退避する必要も無い。**

この判断は「索引を読む」ことを前提にしていた。実際に CHG-0003 が終了した
時点で、前提が成り立たない場面があると分かった。

**ファイル一覧を見たときに、取り組み中のものと終了したものが混ざる。**

```console
$ ls docs/change/
0001-compaction-context-handover.md      # In progress
0002-opencode-ask-by-default.md          # In progress
0003-ask-command-description.md          # Done
index.md
```

索引を開けば区分は分かるが、次の場面では索引を経由しない。

- エディタのファイルツリーやタブ
- `git status` / `git diff` の対象確認
- エージェントが `glob` や `ls` で案件を探すとき

案件が増えるほど、終了したものが視界の大半を占める。ADR-0010 自身も
ネガティブな結果として「終了した案件が増えると索引の『終了』区分が伸びる」
を挙げていたが、**伸びるのは索引だけではなかった**。

## 決定

**終了した案件（`Done` / `Abandoned`）は `docs/change/closed/` へ移す。**
`change/` 直下には取り組み中のものだけを置く。

`closed/` という名前にしたのは、`Done` だけでなく `Abandoned` も入るため。
索引の区分「終了」と対応する。

移動時にすること。

1. `git mv` で履歴を保つ
2. 移動したファイル内の相対リンクを貼り直す（階層が 1 段深くなる）
3. 索引の行を「活動中」から「終了」へ移し、リンクを `closed/` 付きにする

**ADR-0010 のうち「別ディレクトリへ退避する必要も無い」という 1 点だけを
改める。** 4 種類の分割と記録単位の考え方はそのまま有効なので、
ADR-0010 は `Superseded by` にしない。

## 却下した選択肢

**索引だけで区別を続ける（ADR-0010 の現状維持）。** 索引を経由しない
参照経路（ファイルツリー、`git status`、エージェントの `glob`）で効かない。
案件が 10 本を超えると一覧の大半が終了済みになる。

**ファイル名に印を付ける（`x-0003-...` など）。** 並び順が崩れ、番号の
一貫性も失われる。リンクの張り替えは結局発生する。

**削除して git 履歴に残す。** ADR-0010 が退けたとおり、当初の期待・
変更した判定条件・試さなかった候補には参照価値がある。

**`docs/archive/` のような別カテゴリを作る。** 案件は終了後も
「なぜそう決めたか」の参照先として ADR や spec から張られる。
カテゴリを跨ぐとリンクの意味が変わり、索引検査の対象からも外れる。

## 決定の確認方法

- [x] `ls docs/change/*.md` に終了した案件が出ないこと
- [x] `closed/` 配下の掲載漏れを `lint_docs.py` が検出すること
- [x] 索引が実在しないファイルを指したとき検出すること
- [x] 移動後に壊れたリンクが 0 件であること

索引検査は `research/` のサブディレクトリ分割（2026-09-22）で再帰化済み
だったため、追加の実装は要らなかった。

## 結果

### ポジティブな結果

- ファイル一覧が現在地を表すようになった
- エージェントが案件を探すとき、終了したものを読まずに済む

### ネガティブな結果

- 終了時の手順が 1 つ増える（相対リンクの貼り直し）
- 案件へのリンクが `closed/` の有無で変わるため、終了時に外部参照の
  更新が要る

### 中立的な結果

- 番号空間は変わらない。`closed/` 配下も同じ連番を共有する
