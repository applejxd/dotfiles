# 学会動画の構成の指針

3〜5 分の発表動画を、取材から台本までまとめる。

## 6 部構成と尺の目安(4 分の場合)

| 部 | 尺 | 内容 | 映像 |
| --- | --- | --- | --- |
| 冒頭 | 約 25 秒 | タイトル、**全体の概要図**、これからの流れ | 概要図(論文の図または Manim) |
| 動機・課題 | 約 40 秒 | 何の技術か、なぜ必要か、既存の何が足りないか | **応用の写真・短い動画** + Manim |
| 提案(理論背景) | 約 80 秒 | 手法の要点。概要図を育てながら説明する | Manim |
| 仕組みの補足 | 約 30 秒 | 判断基準、最適化など。削れる部分 | Manim |
| 結果 | 約 45 秒 | 数値の比較と、実動作の映像 | グラフ + 実動画 |
| まとめ・公開 | 約 20 秒 | 要点 3 つ、コードの場所、出典 | Manim |

SLAM-MER の試験では、冒頭の概要図が無かった。利用者から「最初に全体の
アーキテクチャを見せるとよかった」「動機のところはネットから代表的な
画像・動画を取得して置いてよかった」と指摘があった。下の 2 節はそれを反映した。

1 行 5〜10 秒、1 文字 0.18 秒が目安(VOICEVOX 四国めたん、速度 1.0)。
試験の実測は 25 行・約 200 秒。

## 冒頭の概要図

- 手法の全体像を最初に 1 枚で見せる(15〜25 秒)。聴衆が「これから何を
  見るか」を知ってから部品の説明に入る
- 論文の全体図(パイプライン図・アーキテクチャ図)を優先する。使えるかは
  取材で許可を聞く。無い・合わないときは、論文の構成要素をなぞって
  Manim で簡略図を自作する(ブロックと矢印だけ。詳細は省く)
- 理論部で同じ図を使い回し、説明中のブロックだけを強調する。
  「いま全体のどこの話か」が常に分かる

## 動機・課題の具体素材

- 抽象的なアイコンで済ませず、代表的な応用の写真・短い動画を使う
  (例: AR グラスの使用場面、ロボットの室内走行、カメラだけで迷う場面)
- 1 場面 5〜10 秒。台本の言葉と素材の内容を合わせる(「ロボットの自律移動」で
  ロボットの映像)
- 集め方・権利の扱い・台帳は SKILL.md の「1.5 素材の収集」。公開範囲で使える素材が
  変わる(公開なら CC0 / CC BY / Pexels など、再利用できるものだけ)
- 代表的と言えるものを選ぶ。候補が多いときは利用者に 3〜5 個見せて選んでもらう

## 取材のしかた

- 論文は節ごとに主張を 1 行で抜き出し、台本のメモに出典(節・図・表)を付ける
- 数値は表から転記する。丸めた値や換算した値(比など)は、
  「算出」と明記する
- 公式の発表動画があれば、構成の参考にする。ただし台本は書き直す
  (発表の話し言葉をそのまま読まない)
- リポジトリの `doc/` に論文の節に沿った説明があれば、理論部の素材にする
- リポジトリに SDD 流の `docs/`(`docs/index.md` と、`spec/`・`adr/`・`change/`・
  `research/` の索引)があれば、**構成(プロット)の材料にする**。索引から辿る:
  - `spec/`(何を実現するか): 主張・提案の部。受け入れ条件は「できること」の根拠
  - `adr/`(なぜその方式か): 動機・課題と、手法の分岐点(代替案と選んだ理由)の部
  - `research/`(調査・実測): 結果の部と先行研究。数値は出典と日付つきで使う
  - `change/`(経緯と現在地): 課題・失敗・限界と今後の部
- docs の状態を守る: 採用済み(Accepted / Active / Verified など)だけを断定に使い、
  検討中・置き換え済み(Proposed / Exploring / Superseded など)は「検討中」と書くか使わない。
  各行の出典に docs のパス(例: `docs/adr/0001-...`)を付ける
- docs と論文・コードが食い違うときは、論文・実装を優先し、食い違いを利用者に報告する。
  docs は内部記録なので、未公開の事情が含まれないか、公開前に利用者に確認する
- 論文が無く docs だけのリポジトリでも、この対応で構成案を作れる

## 利用者への取材

- まず資料(論文、README、docs、渡された動画)を読み、読めば分かることは
  聞かない。既定値を示して「これでよいか」だけ取る
- 聞くのは、資料から決められないこと、利用者だけが知っていること
  (聴衆、強調、未公開の点、許可)、好みで結果が変わること(話者、語り口)
- 質問は 1 回 4 問まで。独立な問いはまとめ、答えに依存する問いは次の回に回す
- 答えは `assets/brief.template.md` を写した `brief.md` に残す

### 質問表

| 区分 | 質問の例 | 選択肢の例(推奨を先頭) |
| --- | --- | --- |
| 目的・聴衆 | どこで見せる動画か | 学会発表 / 社内 / 公開用 |
| 目的・聴衆 | 聴衆の前提知識は | 分野の研究者 / 隣接分野 / 一般 |
| 目的・聴衆 | 目標の長さは | 3〜4 分 / 5 分 / 1〜2 分 |
| 主張 | 一番伝えたいことは(1 つ) | 論文からの候補を 2〜3 個示す |
| 主張 | 触れない点・未公開の点は | なし / 指定する |
| 素材 | 結果の動画・表の場所と使える範囲は | パスと秒数を自由記述 |
| 素材 | 論文の図・公式動画を使ってよいか(許可) | 使ってよい / 一部のみ / 不可 |
| 素材 | 冒頭の概要図は | 論文の全体図を使う / Manim で自作する |
| 素材 | 動機の具体素材をネットから取得してよいか | 公開可の素材だけ / 仮でもよい / 用意する |
| 表現 | 話者(キャラクター)と速度は | 四国めたん 速度 1.0 / ほかの話者 |
| 表現 | 語り口は | です・ます(やや柔らかい) / です・ます(統一) / である調 |
| 表現 | 画面の配色と BGM は | 白地・BGM なし / 白地・BGM あり / 暗い背景 |
| 読み・用語 | 読みが分かれる固有名詞・略語の読みは | こちらの推定を示して確認 |
| 公開 | 公開範囲とクレジット表記は | 私的検証 / 社内 / 公開 |

質問の選択肢は、資料から分かる候補を入れて具体化する(表の例のまま出さない)。

### 確認の種類

- **構成案の確認**: 部ごとの尺、各部の要点 1 行、使う図・動画、出典。
  主張と構成が合っているかを見てもらう
- **台本の確認**: 行番号つきの全文。数値・固有名詞・主張の言い回しを
  特に見てもらう。直しは行番号で受け、直した行だけ再提示する
- **音声の確認**: 合成後、利用者が聴いて読み・アクセント・同期を確かめる
  (エージェントは聴けない)

## 台本の書き方

- 1 行 1 文、40〜60 文字。句読点で息継ぎを作る
- 数式は読み上げる。`=`、`∪`、`_` は使わず、言い換える
  (「和集合」「ケーエル発散」など)。画面の式は図の側で見せる
- 英字は読み辞書(`yomi.json`)に登録する。SLAM、RANSAC のような略語は
  `yomi.py candidates` が未登録を候補にし、`narration_check.py` が候補の残りを止める
  (書き方と進め方は `references/yomi.md`)
- 数字は `0.056` と書くと「ゼロ点ゼロ五六」と読まれる。聞いて不自然なら
  漢数字や言い換えにする
- 動作の説明は「何が見えているか」を言い、画面の動きと同じ順に並べる

## 読みの確認

1. `readings.py` で、行ごとの仮名を見る(区切りは `|`)
2. 誤読は `yomi.py set` か画面で直す(書き方は `references/yomi.md`)。辞書の語は優先度 9 で
   登録する(既定の辞書に負けるため。SLAM-MER の試験で「AR」が辞書を無視した)
3. アクセントは初期値。実際に聞いて、不自然な語だけ直す

## 公開の前に

- VOICEVOX のキャラクターごとの利用規約とクレジットを確認する
- 論文の図・実動画を使うときは、権利者(出版社・所属機関)の許可を確認する
- 映像の出典を画面に残す
