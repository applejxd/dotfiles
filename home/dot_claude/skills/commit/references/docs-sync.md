# コミット前の docs 反映

コミットを依頼されたら、作業の経緯を知る側（会話の当事者）が行う。次のどれかに当たるときは飛ばす。

- リポジトリのルートに `docs/change/` が無い
- `sdd-docs` スキルの前提の構成が欠けている（構成を作るか尋ねず、理由を添えて飛ばす）
- メッセージ作成だけを依頼された

1. 今回の変更が `docs/change/` の活動中の案件に関わるかを判断する。
   決めたこと・見送ったこと・検証の結果など、差分に現れない経緯が対象
2. 関わる案件ファイルに、編集の前に `git diff --cached -- <パス>` と `git diff -- <パス>` で
   既存の差分が無いかを見る。自分の作業と判断できない
   差分や部分ステージがあれば、編集せずに利用者へ尋ねる
3. `sdd-docs` スキルの A2（案件の更新）を、始める前の控えと「仕上げ」の検査まで行う。
   ADR・仕様・調査記録（B）はここでは書かない。検査が失敗した・実行できないときは、
   報告して続けるかを尋ねる
4. 承認時の提示の直前に、結果を 1〜2 行で示す。
   更新したなら「`docs/change/NNNN-….md` の現在地を …… に更新」、
   しなかったなら「docs 反映は不要（理由: ……）」

更新した案件は、それが記録している変更と同じコミットに含める（docs だけのコミットに
分けない）。1 つの案件が複数のコミットにまたがる変更を記録しているときは、
コミットをまとめるか、どれに含めるかを利用者に尋ねる。複数のリポジトリにまたがるときは、
この節をリポジトリごとに行う。
