# CHG-0039: 入力待ちの通知（BEL）に、メッセージを添える

- **状態**: Exploring
- **更新日**: 2026-10-26
- **基準**: pi 1.3.0、`notify` 拡張（`home/dot_pi/agent/extensions/notify/index.ts`）。BEL（`\x07`、端末のベル文字）を 1 バイト送るだけで、本文は運べない

## 目的と非目的

- **目的**: 利用者が別の画面にいるとき、`pis` が入力を待ち始めたことを、**何を待っているか**が分かる形で通知する。
  今は「待っている」ことしか伝わらず、完了・確認待ち（フルガードの確認）・質問（`ask`）の区別と、何が起きたかが、端末へ戻るまで分からない
- **非目的**: 通知の音や見た目を作り込むこと。OS の通知機能を `pis` から直接呼ぶこと（境界の外への操作になるので扱わない）。RPC や ACP 経由の通知（BEL は TUI のときだけ書く、という現行の約束は変えない）

## 現在地

- **現状（コードで確認、2026-10-26）**: BEL は 4 か所で `process.stdout.write("\x07")` を書く（TUI のときだけ）。完了（`notify/index.ts`、`agent_settled`）、`ask` の質問の直前（`ask/index.ts:359`）、フルガードの確認の直前（`home/dot_config/pi/harness/index.ts:141`、`:425`）。仕様は [pi-guard.md](../spec/guard/pi-guard.md) の `notify`
- **Zed の Terminal Threads**: フォーカス外の端末が BEL を出すと、スレッド一覧に青丸が出る（利用者が `printf '\a'` で確認済み。[CHG-0027](0027-zed-pi-acp-with-pis.md)）。ポップアップや音は出なかった
- **本文を運ぶ方法（一般論。端末ごとの対応は未確認）**:
  - OSC 9: `\x1b]9;メッセージ\x07`。iTerm2・Windows Terminal・Ghostty・WezTerm などが対応する、とされる
  - OSC 777: `\x1b]777;notify;タイトル;本文\x07`。Ghostty・VTE 系・WezTerm などが対応する、とされる
  - 非対応の端末では無視されるか、文字が表示される。tmux の中では `allow-passthrough` が要る
- **Zed と Orca が OSC 9 / 777 を通知にするか**は、確認していない。公式の文書にも、ここまでの調べでは記述が見つかっていない

## 未解決点

- 使っている端末のうち、どれが OSC 9 / 777 を通知として扱うか（N1 の実測）。**再開条件**: 利用者の端末での確認
- 非対応の端末で、OSC が表示を壊さないか。壊す端末があるときの切り替えの方法（環境変数の判定か、`local.toml` の設定か）
- メッセージの中身。候補は、状態（「完了」「確認待ち」「質問」）と、直前の発話の先頭の数十文字。**機密が通知に出る**（画面共有や通知センターの履歴に残る）ので、本文を出すかは設定で選べるようにするか
- 長いメッセージや改行、制御文字の扱い（端末へ制御文字を注入されないよう、エスケープの対象にする）

## 評価基準

- **必須**: 非対応の端末でも、従来どおり BEL が鳴り、表示が壊れない。RPC・print モードの出力（JSON 行）を汚さない。メッセージに含まれる制御文字で、端末の状態を変えられない
- **望ましい**: 状態（完了・確認待ち・質問）が通知の上で区別できる。通知の本文を、設定で省ける
