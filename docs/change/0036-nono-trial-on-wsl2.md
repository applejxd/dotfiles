# CHG-0036: nono を WSL2 で小さく試し、`ocs` の境界の層の置き換えの可否を測る

- **状態**: Exploring
- **更新日**: 2026-10-24
- **基準**: 現行の境界は Fence ＋ `ocs`（[CHG-0033](0033-sandbox-build-value-assessment.md) の「現在地」）。環境は WSL2（Ubuntu、カーネル 6.18、Landlock ABI 7）。コミット `d0f9358`

## 目的と非目的

**目的**: nono（OS の隔離型のサンドボックス。`pi` を名指しで対応する）が、現行の境界（Fence ＋ `ocs`、約 2,266 行）の**どこまでを置き換えられるか**を、この環境で**実測**する。[CHG-0033](0033-sandbox-build-value-assessment.md) の覆る条件 (a)「nono を試して、ファイル制御・`pi` の包み・ホストの道具が現行の境界と同等と実測できたら、境界の層を置き換える」を判定するため。

**非目的**:

- nono を現行へ導入する・`ocs` を置き換える（判定の後、別の案件）
- 資格情報の代理の評価（WSL2 では既定で使えない。下の「現在地」）
- 試験を、私が許可なく実行する（導入と実行は、利用者の許可が要る）

## 受入条件（試験で測る期待動作）

置き換えの「同等」を、次の観測で判定する。各項目は、現行の境界で同じ試験を行い、結果を比べる。

1. **ファイル制御**: 作業フォルダ（リポジトリ）を読み書きできる。ホームの秘密（`~/.ssh`、`~/.aws` など）を、読めない・書けない。リポジトリの外（`~` 直下など）に書けない
2. **`pi` の包み**: `nono run --profile <pi 用> -- pi` で、`pi` が起動し、モデルとの往復ができる（認証の戻しなど、`pis.py` が行っている処理の差）
3. **ホストの道具**: `mise`・`uv`・`git`・`node` が、そのまま使える（子プロセスに制限が伝わるが、道具は動く）
4. **子プロセスへの伝播**: `pi` が起動する子（`git`・ビルド）にも制限が及ぶ
5. **ネットワーク**: 現行の境界は、許可したドメインだけに通信を絞る（`ocs` の中継つき）。nono の WSL2 での代替を**測る**（下の「現在地」の制限）
6. **確認の手段**: 実行前に許可の一覧が出る、`nono why`・`--dry-run` で判定を見られる、が実際に使える

## 現在地

`explore` の子の下調べ（2026-10-24。ベンダーの公式の docs・README が中心。nono は**実行していない**）。

**引けたこと**:

- **導入**: 単一バイナリで、root 権限は要らない（README）。`curl -fsSL https://nono.sh/install.sh | sh`、`brew install nono`、Debian/Ubuntu は `.deb`（`sudo dpkg -i`）。WSL2 は、ディストロの中に Linux 用の方法で入れる。ライセンスは Apache-2.0
- **`pi` を包む**: `nono pull nolabs-ai/pi` の後 `nono run --profile nolabs-ai/pi -- pi`。自分用は `nono profile init pi-local --extends nolabs-ai/pi`。基本形は `nono run [OPTIONS] -- <COMMAND>`。**pack の中身（許可するパス・通信・環境変数）は、見つからなかった**（`registry.nono.sh` は「0 packs」と表示。JS の描画の可能性）
- **ファイル制御**: `--allow`（読み書き）・`--read`・`--write`。作業フォルダは `workdir.access`、`--allow-cwd` で確認を省ける。拒否リスト（`filesystem.deny`）、「秘密のパス 46 件」を既定でブロック（WSL2 の機能表）。プロファイルは JSON/JSONC で `~/.config/nono/profiles/`、`extends` で継承
- **確認の手段**: `nono run --dry-run`、`nono why --path <P> --op read`、`nono setup --check-only`、`nono profile show`、実行前に許可の一覧が出る
- **成熟度**: 1.0 の前（README）。リポジトリは `nolabs-ai/nono`（`always-further/nono` から移った）。v0.77.0（2026-09-11）、メンテナー 4 人、registry は「Alpha」

**WSL2 の制限**（ベンダーの docs。カーネル 6.6・Landlock V3 を前提に書かれている）:

- ファイル制御と `--block-net`（全遮断）は完全。**ポート単位の通信は不可**（Landlock V4 が要る）
- **資格情報の代理と、ドメインの許可リスト（`--allow-domain`・`--network-profile`）は、既定で拒否**。`wsl2_proxy_policy: "insecure_proxy"` で実行できるが、子が代理を迂回できる。理由は、WSL2 の init が seccomp の通知リスナーを占有するため（microsoft/WSL#9548）
- **このことは、受入条件 5 に直結する**: 現行の境界は、許可したドメインだけに通信を絞る。**nono は WSL2 で、これを標準では提供しない**（全遮断か、迂回できる代理のみ）。したがって、nono 単独では、現行の境界を**完全には置き換えられない**可能性が高い（動かしていないので、確定ではない）
- 記述の食い違い: 公式のページはカーネル 6.6・Landlock V3 を前提にしている。この環境は 6.18・ABI 7 で、何が使えるかは `nono setup --check-only` の実機の結果が要る

**引けなかったこと**: pi の pack の中身、`mise`・`uv`・`node` がそのまま使えるという明示、`/mnt/c` の扱い、`deny_credentials` グループの具体的な中身。

**着想（未検証）**: nono は Landlock を使い、Landlock は Fence の内側で入れ子にできることを、[CHG-0029](0029-worktree-isolation.md) の実測で確かめた。nono を、現行の境界の**置き換え**ではなく、**Fence の内側で、子エージェントの Landlock の包み（`landlock_exec.py`）の代わり**に使えるか、は別の問い。

## 未解決点

1. **ドメインの許可リストの代替**（受入条件 5）。nono 単独では不可の見込み。Fence に残し、nono を併用する形（入れ子）が成り立つか。**再開条件**: 段 N1 の結果
2. 段 N1〜N4 は、**この環境にソフトウェアを入れる**ので、利用者の許可が要る。**再開条件**: 許可
3. `pi` の pack の中身が不明。`nono pull` の後でないと読めない（段 N2）
4. 「秘密のパス 46 件」と、現行の保護対象（`ocs/boundary.py` が導出するもの）の差

## 次の調査・実験

1. 利用者に、段 N1（導入と `--check-only`）の許可を尋ねる
2. 許可が出れば、手順書（`scripts/agents/`）を作り、使い捨てのリポジトリで段 N2・N3 を行う
3. 結果を [CHG-0033](0033-sandbox-build-value-assessment.md) に反映する

## 評価基準

**必須**: 受入条件 1〜4・6。**条件つき**: 受入条件 5（nono 単独で不可なら、併用の形で判定）。**判断の原則**: サンクコストを使わない。置き換えで減る保守（`ocs` の約 2,266 行、直近 2 週間で 13 コミット）と、増える依存（nono は 1.0 前で、名前空間が移った実績がある）を比べる。結果を見て基準を変えたら、「重要な更新」に残す。
