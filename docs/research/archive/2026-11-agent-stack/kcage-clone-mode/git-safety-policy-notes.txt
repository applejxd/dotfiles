# git の安全方針の整理（私用メモ。利用者の判断待ち）— 2026-11-08

利用者の方針: main・develop などのブランチは、reflog などで戻せる限り保護対象にしない。禁止するのは、.git の削除・push など取り返しのつかないものだけ。
適用範囲と、二段（フルガード＝ホストの AI の道具呼び出し／箱＝kcage）の分担は、利用者が検討中（Q1 保留）。Q2（箱の中の復元手段の破壊への備え）も保留。

## 原則（案）
- フルガード = 意図の検査（うっかり防止）。取り返しのつかない操作と外への影響を止める。可逆な操作は止めない。
- 箱 = 能力の遮断（境界）。認証・ネットワーク・ホストの書き込み先・ホストで実行される経路を渡さない。箱の中にフルガードを作り直さない。
- 二段で同じ操作を二重に止めない。箱が境界で防げるものは箱、防げないものだけをガードか復元点で補う。

## 担当（案）
| 種類 | 例 | フルガード | 箱 |
| --- | --- | --- | --- |
| 可逆（reflog で戻る） | commit・branch 作成と削除・merge（develop/main 含む）・rebase・reset --soft/--mixed・local tag・worktree add | 許可 | 許可（素の git。git flow は箱では config が ro のため不可） |
| 未コミット作業の喪失 | reset --hard・checkout -- .・clean -fd・stash drop・rm | 作業ツリーに変更があるときだけ確認 | 許可（共有のためホストにも及ぶ） |
| 復元手段の破壊 | .git の削除・reflog expire/delete・gc --prune=now・filter-branch・update-ref -d・未マージの branch -D | deny | 保留（rw 共有のため境界では防げない。復元点・規則・許容のどれか） |
| 外への公開 | push（force 含む）・PR の作成/マージ・パッケージ/image の公開 | deny（人が実行） | 認証を渡さないのでできない（境界） |
| 秘密・認証 | トークンの読み取り・送信 | 既存どおり | 認証を箱に入れない（境界） |
| ホストで実行される経路 | hooks・config・commondir・alias | 対象外 | ro で重ねる（commondir は feature/kcage-commondir で修正中） |
