# CHG-0066: pi のツール単位 sandbox（層 b）の問題を洗い出し、自作の境界を決める

- **状態**: In progress
- **更新日**: 2026-11-12
- **基準**: [ADR-0035](../adr/0035-pi-sandbox-gpu-runner.md)（runner の採用。拡張を使う方式）と `pib` の配備（`ea7401cd`）後の実機（WSL2・Ubuntu 24.04）。実装後の仕様は [pi-sandbox-runner](../spec/sandbox/pi-sandbox-runner.md)、決定は [ADR-0036](../adr/0036-pi-sandbox-shell-wrap-and-tool-policy.md)

## 目的と非目的

**目的**: ADR-0035 で入れた層 b（pi 本体は外側、bash だけを bwrap で包む。`pib` = `@yuru7/pi-sandbox` と runner）を、実機で使って見つかった問題を洗い出し、次の 2 つを、継ぎ足しにならない形で決める。

1. **何を守ると言うのか**（脅威モデル）。
2. **どこまでを自作し、何を自作しないか**（境界）。

**非目的**:

- 層 c・d（ツールを別環境へ送る・環境ごと隔離）の導入。別案件（[CHG-0064](0064-dev-environment-isolation.md)）。
- ネットワークの絞り込み、認証の仲介（凍結した broker）、新しい pi 拡張の自作。
- 実装の詳細は仕様に置く。この案件は、洗い出しと決定、実装の結果の記録まで。

## 現在地

### 問題の洗い出し（2026-11-12）

確認の区分: **実測**（実機で確かめた）、**ソース**（拡張・pi のコードや文書を読んだ）、**推測**（根拠から導いたが未確認）。

#### A. sandbox を通らない実行・操作（抜け道）

| ID | 問題 | 確認 |
| --- | --- | --- |
| A1 | `bg_run`（拡張 `pi-background`）は sandbox の外で動く（HOME に書けた）。ただし権限の層の判定は効く（`~/.config/gh` の読み取りが bash と同じ規則で拒否された） | 実測 |
| A2 | 利用者が打つ `!` `!!` は、拡張の仕様で sandbox の外 | ソース |
| A3 | 昇格（`danger-full-access`）は、1 コマンドが丸ごと外。承認は既定で別モデルの自動レビュー（HOME への書き込みを ALLOW した例がある） | 実測（[調査記録](../research/agents/pi-gpu-sandbox-2026-11.md#発見)）。遅延・費用・判断の質は未観測 |
| A4 | `read` ツールの読み取りは無制限（拡張の仕様）。秘密を止めるのは権限の層の path 規則で、bash・`bg_run` では確認済み。`read` ツールでは未確認。`write` / `edit` は拡張がプロセス内の防護で止める | ソース／実測（bash・`bg_run`）／未確認（`read`） |
| A5 | MCP サーバー・他の拡張のツールは、ホストで動く（設計） | ソース |
| A6 | 子エージェントに sandbox が及ぶか。拡張は「子にも適用」と書く。`ssh.ts`（層 c）の試験では、子が外で動いた | 未検証（層 b）／実測（層 c） |
| A7 | `/tmp` がホストと共有で、tmux のソケット（`/tmp/tmux-1000/default`）と X11 のソケット（`/tmp/.X11-unix/X0`）が内側から届く位置にある。サーバーが動いていれば、内側から外側のシェルや GUI へ入力を送れうる | 実測（ソケットの存在。tmux はサーバー停止中で、接続は未確認）／推測（悪用） |

| [CHG-0033](closed/0033-sandbox-build-value-assessment.md)・[CHG-0036](closed/0036-nono-trial-on-wsl2.md) | 自作の囲い（`ocs` 約 2,266 行）を、既存の CLI（nono・Docker Sandboxes・OpenShell など）に置き換えられるかの評価 | 文書を読んだだけで、動かしていない。GPU は原文に記述なし。nono は WSL2 でドメインの許可リストが標準では使えない。凍結（[ADR-0030](../adr/0030-freeze-agent-stack-return-to-stock-pi.md)）で打ち切り |

当時の見送りは、ADR-0012 の方針（pi の**プロセス全体**を囲う）が前提だった。今回は、前提が違う。

- 自作の判定器とハーネスは凍結し、stock の pi に権限の拡張を載せている。
- bash だけを囲う構成は、前回は利点（認証が外に残る）より弱点（範囲）を重く見て退けた。今回は、D1（守る対象）で範囲の重みを決め直す。

当時の教訓（[CHG-0033](closed/0033-sandbox-build-value-assessment.md)）: 既存の囲い（Fence）の穴（`denyWrite` が未存在のパスに効かない、通信の中継、入れ子ができない）を自作で埋めた結果、自作層が約 2,266 行になり、直近 2 週間で 13 コミットの保守が続いた。**既存の囲いの穴は、自作で埋めず、「保証しない」と書くか別の囲いに替える**を、境界の規則に足す。

### 実測: Fence を `shellPath` の先に置く（2026-11-12）

使い捨ての作業ツリー（`.tmp/handson/fence-spike/`。git 管理外）で試した。pi 1.5.0・Fence 0.1.67・WSL2。作業ツリーの `.pi/settings.json` に `shellPath` を置き、呼ばれたことを囲いの外のログで確かめた。

| 試験 | 結果 |
| --- | --- |
| pi の bash ツールが `shellPath` を通る。HOME への書き込みは止まる | 通った（呼び出しがログに残り、`touch` が拒否された） |
| `bg_run` が `shellPath` を通る（A1） | 通った（HOME への書き込みが止まった） |
| 利用者の bash（`!` と同じ経路。RPC の `bash`）が `shellPath` を通る（A2） | 通った（止まった）。TUI での `!` は未確認 |
| 子エージェント（`worker`）の bash が `shellPath` を通る（A6） | 通った（呼び出しがログに残った）。子が HOME へ書く試験は、権限の層（`external_directory`）が先に拒否したので、囲いでの確認は未実施 |
| GPU（`/dev/dxg`） | 通った（`nvidia-smi -L` が RTX 3070 を認識。`devices.allow`） |
| 秘密・履歴・Windows ドライブ（B1） | 見えない（`defaultDenyRead` の許可リスト方式。`.bash_history`・`.ssh`・`.config/gh`・`/mnt/c` など） |
| `/tmp` のソケット（A7） | 見えない（`/tmp` は内側専用） |
| `/run/user`（rootless docker のソケット） | **既定では見える**。`denyRead` に `/run/user` を足して塞いだ |
| `.git/config`・`.git/hooks` | 書けない（保護対象にしたとき）。`git commit` はできる |
| 標準のキャッシュ（`~/.cache/uv`）（C3） | `allowWrite` に足せば書ける。足していない `~/.cache` 直下は書けない |
| 通信（B3・D8） | 許可したドメインだけ通る（`example.com` は通り、`github.com` は止まる） |
| git の worktree | `.` だけでは `git` が動かない（`gitdir` が外）。設定の生成で `gitdir`・`commondir` を足せば、`commit` もでき、共有の `hooks`・`config` は書けない |
| 1 コマンドあたりの遅さ | 既定では**約 1 秒**（囲いなし 約 5 ミリ秒、`bwrap` 直接 約 8 ミリ秒）。原因は、WSL の `/mnt` 配下の `PATH` 要素と、cwd のファイル数に比例する走査。ラッパーで `PATH` から `/mnt` を外すと**約 0.25 秒**（[調査記録](../research/agents/fence-latency-2026-11.md)）。ファイル 14 万件の checkout（`.tmp` を含む main）では約 1.2 秒 |

読み取り:

- Fence は、洗い出した問題の多く（A1・A2・A6・A7・B1・B3・C3）を、設定だけで塞いだ。自作は、設定の生成（worktree の `gitdir`・`commondir` の追加を含む）だけで済む。
- 代償は 2 つ。**1 コマンドごとの遅さ**（`PATH` から `/mnt` を外せば約 0.25 秒。外さないと約 1 秒）と、許可リスト方式の**道具の置き場の保守**（`allowRead`）。公式は、コマンドごとに包む使い方を勧めず（エージェント全体を 1 回包む）、常駐の仕組みも無い。Fence は、最新リリースから 2.5 か月動きがなく、遅さに関する PR（#238）は close された。[CHG-0033](closed/0033-sandbox-build-value-assessment.md) の利用者の回答で、使わなかった理由に挙がった「許可の追加が面倒」と同じ種類の摩擦になりうる。
- 未確認: `read`・`write`・`edit`（プロセス内のツールは囲いの外。権限の層に任せる前提）、MCP・拡張のプロセス、TUI の `!`、実際の開発作業での使い勝手。

### 実装の結果（2026-11-12）

ADR-0036 の決定（コマンドの実行は `shellPath` の囲い 1 つ、方式は素の bwrap）を、feature の中で実装した。仕様は [pi-sandbox-runner](../spec/sandbox/pi-sandbox-runner.md)。

| 洗い出した問題 | 結果 |
| --- | --- |
| A1 `bg_run`・A2 `!`・A6 子エージェントが囲いの外 | **解消**。`shellPath` を通る。実測（pi 1.5.0・WSL2）: bash ツール・`bg_run`・利用者の bash（RPC）・子の bash が、同じ囲いを通る（内側では `/mnt/c` が見えず、`MISE_STATE_DIR` が設定される）。TUI の `!` は未確認 |
| A7 共有の `/tmp` のソケット | **解消**。`/tmp`・`/var/tmp`・`/run/user` を空で覆う（自己確認で tmux・X11 が見えない） |
| B1 履歴・Windows のドライブ・一覧に無い秘密 | **解消**。ホーム・`/mnt`・`/media` を空で覆い、`visible` に書いた所だけを見せる（許可リスト型）。`hide` が後から勝つ |
| B2 環境変数のトークン | **一部**。`env.unset` の一覧の名前を消す（拒否リスト）。独自の名前は渡る |
| B3 通信 | 既定で開ける。`pib --offline` で全遮断 |
| B4 「読ませない場所」の一覧が複数 | **一部**。囲いの設定（`runner.toml`）と権限ポリシーは、まだ別々に持つ。同じ一覧から生成する案（ADR-0036 の 4）は未実装 |
| C1 git の保護 | worktree の git ディレクトリは、`.git` ファイルの値を信じず、back-reference と `commondir` の形が揃うときだけ渡す（エージェントが書き換えて他の場所を書き込み可にできない）。覆えるのは既存の `hooks`・`config` だけ（限界は残る） |
| C3 標準のキャッシュ | **解消**。`visible.write` に `~/.cache/uv`・`~/.npm` などを入れた。`mise` の状態は使い捨て |
| D1・D2 昇格 | **なくした**（昇格の仕組みは作らない。囲いの外が要るときは `pi`） |
| E1・E2・E3・E4・E5 拡張への依存・設定が二つ・入口の分散 | **解消**。拡張を外し、設定は `runner.toml` と任意の `runner.local.toml` |
| A4 `read`・`write`・`edit` | 囲いの外。パスの判定（`pi-permission-system`）に任せる。ソースで、外かどうかの判定がシンボリックリンクを解決した実体で行われることを確認。`external_directory` は ask で、YOLO では自動承認になる（実機の試験は未実施） |
| gh・git push・issue / PR の投稿 | 内側では認証が見えず失敗する（`~/.config/gh`・`~/.git-credentials` は見えず、`~/.config/git/credentials` は隠す。内側の `git credential fill` は認証を見つけない） |

実機の自己確認（`scripts/pi_sandbox_selftest.py`。GPU の CUDA カーネルを含む）は、すべて PASS。試験は `test/test_pi_sandbox_runner.py` の 244 件。

**監査（`reviewer`）で見つかり、直したもの**（コミット前。BLOCKER 2・MAJOR 3・MINOR 1）:

| 指摘 | 直し方 |

## 評価基準

**必須**:

- 実行の入口が 1 つ。
- 「読ませない場所」の方針が 1 か所で、重複がない。
- 拡張の内部の挙動に依存しない。
- 主張する保証は、すべて否定試験（破れないことを確かめる試験）で縛れる。
- 自作は 1 部品。

**望ましい**: GPU が使える。普段の `pi` と同じ操作感。設定が宣言的。

## 実装・検証

段 4 は、段 3 の決定後に起票する。

### 段 5（保留）: 標準のキャッシュ領域を書き込み可にする

- **利用者の方針（2026-11-12）**: 大きなキャッシュが多いので、標準のキャッシュ領域を各ツールの位置のまま使う。`/tmp` への退避は採らない。
- **設計案**: `runner.toml` に `[writable]`（`dirs`）を足し、存在する標準のキャッシュを `--bind` する。シンボリックリンクは実体で覆う。並びは GPU → 書き込み可 → git → 隠蔽 → docker（隠蔽が勝つ）。`HOME` やその上位は拒否する。
- **標準の領域の候補**: `~/.cache/uv`・`~/.cache/pip`・`~/.cache/pre-commit`・`~/.npm`・`~/.cache/huggingface`・`~/.cache/torch`。状態の領域（`~/.local/state/mise`）も要るかを、再開時に決める。
- **代償**: キャッシュに書けるので、ホストが後で使う成果物（wheel・hook の環境・モデル）を差し替えられる。`pre-commit` は、コミット時にホストで実行されるので、特に重い。`~/.cache/huggingface/token` は読めるまま（隠す一覧の対象かを決める）。
- **再開条件**: 段 3 の完了後。案 X を採るなら、設定はシェル層の `runner.toml` に載せる。
- **補足**: この案件の作業は、`pib` の中では、git の hook が uv のキャッシュで失敗する見込みなので、`pi` で行う（ADR-0025）。
