# 繰り返す失敗を仕組みで防ぐ

同じ結果が何度も出る原因を一つに絞り、注意書きより先に、ミスが成立する経路を減らせ。

1. 利用者が挙げた事例、既存のテスト、コミットや不具合記録から、繰り返した失敗とその共通原因を拾う。別の原因ならまとめない。過去のセッションを直接読むことを前提にしない。
2. 次の順に、過去の失敗を防げる最も簡単な層を選ぶ。
   1. **アーキテクチャ:** 正本や書き込み口を一つにし、誤用できる経路をなくす。
   2. **型・境界:** 不正な状態を表せなくするか、境界で拒否する。
   3. **lint・CI:** 誤った使い方を検出し、エラーに直し方を出す。
   4. **振る舞いテスト:** 利用者が困る結果を再現し、同じ失敗を止める。
   5. **文書:** 機械で決められない判断だけを残す。
3. 許可された作業範囲で、過去の例を止め、正しい例を通すことを確かめる。新規の機械チェックは、修正前の状態または意図的に壊した例で検出できることも確かめる。
4. 提案だけの依頼なら実装しない。実装した場合は、どの層で何を止めたか、実行コマンド、未確認点を報告する。

新しい注意書きが既存規則を重ねるだけなら加えない。許可されていない Git 操作、環境設定、配布は行わない。
