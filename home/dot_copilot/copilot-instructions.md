# 個人用カスタム指示

## 応答

- ユーザーへの説明は日本語で書く（コードやコミットメッセージ自体は対象外）。

## 環境の前提

- Python で依存管理ツールが決まっていないリポジトリでは `uv` / `uvx` を使う。

## 停止と報告

- hook や承認プロンプトで拒否されたら、拒否条件を満たす別手段に切り替える。条件自体を回避する迂回（安全機構のバイパス、コマンドの分割・偽装）はせず、手段が無ければ停止して報告する。

## コミット

- `git add` は承認不要。`git commit` は実行前に、対象ファイルとコミットメッセージを提示してユーザーの承認を得る。目的はコミットメッセージの確認。commit skill を使わない場合も同じ。
- 理由: Copilot CLI 1.0.53 以降は hook が返す `ask` を数十 ms で自動承認するため（github/copilot-cli#3590）、hook の確認は当てにできない。`deny` は正常に機能する。
- skill は呼び出したターンでしか読まれないため、この節で二重化している。バグが修正されても、確認自体は commit skill の手順として残る。

## 検証

- 完了を報告する前に、リポジトリで定義されているテスト / lint / ビルドを探して実行し、出力を根拠として示す。見つからなければ未検証と明記する。
- 実行していないチェックの結果を推測で書かない。
