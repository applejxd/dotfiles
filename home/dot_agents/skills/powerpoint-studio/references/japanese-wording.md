# Natural Japanese for Technical Slides

日本語資料では、英語を減らすこと自体ではなく、聞き手が意味をすぐ理解でき、
必要なら原典やコードへ戻れることを目標にする。

## Classify before translating

| 対象 | 方針 |
| --- | --- |
| 一般的な説明・操作・役割 | 自然な日本語へ置き換える |
| 製品名・教材名・正式な技法名 | 正式名称を保ち、必要なら日本語の説明を添える |
| コード識別子・API・設定キー・指標名 | 原文を保持する。説明文と区別する |
| 引用原図・スクリーンショット内の文字 | 原文を保持する。勝手に描き直さない |
| URL・ファイル名・shape名・参照用ID | 翻訳しない。機械検査や参照の契約を保つ |

例えば`state`が説明文なら「状態」とするが、`AgentState`や実際の引数名はそのまま残す。
`graph`が処理構造を指すなら「処理フロー」や「処理グラフ」とし、数値の可視化とは区別する。
`LangGraph`を「処理フロー」と置換してはいけない。

## Meaning, units, and direction

- `budget`を無条件に「予算」と訳さない。金額、時間、トークン数、反復回数、
  ツール呼び出し回数のどれを制限するのか、原コード・仕様を確認する。
- 回数制限なら「回数上限」や「検索・反復の上限」とする。
  金額と誤解される「調査予算」だけの表記は避ける。
- `fallback`は単なる「失敗」や「異常終了」とは限らない。
  取得済みの情報で回答する処理なら、その動作を説明する。
  実装名`fallback_response`は残し、説明を「取得済み情報で回答」とする。
- 終了分岐を「反復する」と書かない。主張の文と矢印を照合し、
  何を繰り返し、どの条件で止まり、最後に何を返すかを区別する。
- 数値の上限・単位・比較条件を訳文で変更しない。最終回答を受け付ける条件と、
  追加の処理を止める条件が異なる実装にも注意する。

## Avoid needless language mixing

「各agent」「結果をstateへ」「graphをcompileする」のような混在は、
説明として「各エージェント」「結果を状態へ保存」「処理フローをコンパイルする」
などへ整える。定着した外来語まで、不自然な漢語へ置き換える必要はない。

正式な技法名を消すよりも、名前を残して役割を日本語で示す。
例えば`HyDE`はそのまま残し、「答えに近い仮想文書を作る」と説明する。
原典の章名を表示用に和訳しても、参照用の`source_sections`等のキーは原文を維持する。

同じ意味の語は、表題、本文、図、注記、話者ノートで揃える。
意味が違う語を単語だけで一括置換しない。小さな用語表に推奨訳、
保持する名称、誤解を招く表現を記録すると再発を防ぎやすい。
表の列見出しは、セルに実際に並ぶものを直接表す。パート番号の列なら
「原典のパート」とし、「介入群」のような抽象的な説明で読み手に解釈を求めない。

## Review every rendered text surface

PPTXのネイティブ文字だけでなく、自作SVG/PNGの元ソース、キャプション、
話者ノートを確認する。PDFのテキスト抽出だけでは、画像化された図の文字は拾えない。
古い未使用の作図ソースや、引用原図の英語まで一律に修正対象にしない。

表現変更後は、正式名称・コード識別子・URL・数値・分岐の意味が残っているか検査する。
既知の悪い表現を文字列で検出する検査は補助として有効だが、
それに通ることを自然な日本語の証明にしない。別のレビュアーが文脈を読む。

## Reflow after translation

英語から日本語へ変えると字幅や行数が変わる。まず短く自然な言い回しと
意味単位の改行を選び、それでも必要なら文字枠や図の配置を調整する。
読める文字サイズや既存の余白規約を緩めて押し込まない。
図の実フォント計測、PPTX/PDF再生成、原寸レビューを再実行する。

表現だけの改訂でも、図のノードID・接続・分岐条件・数値・出典リンクを保持した
ことを確認する。ラベルの変更後に画素一致を主張せず、配置・接続の維持と
表示上の変更を分けて報告する。
