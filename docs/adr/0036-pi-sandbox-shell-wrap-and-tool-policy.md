# pi の sandbox は、コマンドの実行を `shellPath` の囲い 1 つに、ファイルの道具をパスの判定に分ける

- **ステータス**: Accepted（責務の分担・原則・実装の方式。残りは、下の「未決」）
- **日付**: 2026-11-12
- **決定者**: applejxd（責務の分担を 2026-11-12 に承認。「責務が私のポリシーと一致している」。実装の方式を素の `bwrap` と決めた）
- **関係**: [ADR-0035](0035-pi-sandbox-gpu-runner.md)（拡張に runner を差す）を**置き換える**（2026-11-12 の実装で、拡張を外した。ADR-0035 は `Superseded by ADR-0036`）。[ADR-0027](0027-isolation-unit-is-environment.md)（隔離の単位は環境）は**置き換えない**。[ADR-0030](0030-freeze-agent-stack-return-to-stock-pi.md)（凍結）と [ADR-0031](0031-evaluate-existing-extensions-first.md)（既存の評価が先）に沿う
- **根拠の記録**: [CHG-0066](../change/0066-pi-sandbox-boundary.md)（問題の洗い出しと、境界の検討）、[調査記録](../research/agents/fence-latency-2026-11.md)（Fence と bwrap の実測）

## コンテキスト

ADR-0035 の構成（`pib` ＝ 拡張 `@yuru7/pi-sandbox` ＋ runner）を実機で使い、26 件の問題を洗い出した（CHG-0066）。根は 5 つある。

- **入口が分散している。** 拡張は bash だけを包む。`bg_run`・利用者の `!`・MCP・ファイルの道具は包まれない（`bg_run` は実測で、囲いの外で動いた）。
- **方針が分散している。** 「読ませない場所」の一覧が、権限ポリシー・共通設定・`runner.toml` にある。
- **拡張の内部に依存している。** runner は、拡張の引数の並びに依存する。
- **拒否リスト型である。** 一覧に無い秘密は見える。実測で、シェル履歴と Windows のドライブ（`/mnt/c` ほか）が内側から読めた。共有の `/tmp` には、tmux と X11 のソケットがある。
- **守る対象が未定義である。**

凍結前にも、近い検討をしていた（[CHG-0023](../change/closed/0023-guard-terminology.md) の候補 E「bash だけを Fence に通す」）。当時は、pi のプロセス全体を囲う方針（ADR-0012）を前提に、範囲を理由に見送った。今回の前提は違う。自作の判定器とハーネスは凍結し、stock の pi に権限の拡張を載せている。

実測で、次のことが分かった（調査記録）。

- pi の `shellPath` は、bash ツール・`bg_run`・利用者の bash（`!` と同じ経路）・子エージェントの bash のすべてが通る。
- 見える範囲を許可リスト型にすると、秘密・履歴・Windows のドライブ・`/tmp` のソケットが見えなくなる。Fence の設定でも、素の `bwrap` の約 20 行の引数でも、同じ結果になる。
- 囲いを通す 1 コマンドの遅さは、素の `bwrap` で約 16 ミリ秒、Fence で約 0.25 秒（`PATH` から `/mnt` を外した場合。外さないと約 1 秒）。

## 検討した選択肢

| 案 | 内容 | 判定 |
| --- | --- | --- |
| A | 現状（拡張が bash だけを包む） | 抜け道が多い。継ぎ足しで塞ぐと、仕組みと方針が増える |
| B | pi のプロセス全体を囲う | 範囲は最大。ただし、認証が内側に入り、コマンドから読める。凍結前の `pis` で、認証の写しと戻し・拡張の置き場・通信の許可リストの手間が大きく、使われなくなった |
| **C（採用）** | **コマンドの実行を、`shellPath` の 1 つの囲いに通す。pi 本体・認証・拡張・MCP は外に置く。ファイルの道具は、パスの判定で守る** | 範囲と使いやすさの釣り合いが良い |
| D | 環境ごと隔離する（専用の WSL・コンテナ） | ADR-0027 の領分。置き換えない |

### 案 C の実装の方式

| 方式 | 内容 | 判定 |
| --- | --- | --- |
| **素の `bwrap`（採用）** | 現行の runner を拡張し、引数を組み立てる 1 部品にする。約 16 ミリ秒 | 速く、上流への依存が小さい。自作は引数の組み立てだけ |
| Fence | Fence の設定を生成して、`shellPath` の先に置く。約 0.25 秒（`PATH` から `/mnt` を外した場合） | 見送り。固有の機能（通信の許可リスト・Landlock）をこの設計で使わない。公式は「全体を 1 回包む」使い方を勧め、コマンドごとに包む使い方は想定外。最新リリースから 2.5 か月停止し、遅さの PR も close された。WSL では `PATH` の調整が要る |

## 決定

**案 C を `bwrap` で実装する。**

### 1. 道具の種類で、守り方を分ける

| 対象 | 守り方 | 理由 |
| --- | --- | --- |
| コマンドの実行（bash・`bg_run`・`!`・子エージェントの bash） | **囲い（OS が強制）** | 任意のコードが動くので、文字列の判定では防げない |
| ファイルの道具（`read`・`write`・`edit`） | **権限の層が、パスを判定する**（既存の `pi-permission-system`） | パスが引数として渡るので、判定が正確にできる |
| 危険な操作（push・削除など） | 権限の拡張が確認する（変更なし） | — |
| pi 本体・拡張・MCP | 囲わない（信頼するコード） | 認証を外に残す |

### 2. 実行の入口は 1 つにする

pi 標準の設定 `shellPath` に、囲い付きの起動を差す。拡張（`@yuru7/pi-sandbox`）は使わない方向とする。`shellPath` は全セッション共通の設定なので、普段の `pi` は素通しにし、`pib` が立てる環境変数があるときだけ包む。Linux・WSL 専用とする。

### 3. 見える範囲は許可リスト型にする

ホーム・`/mnt`・`/tmp`・`/run/user` を空で覆い、必要な所（道具の置き場・キャッシュ・作業ツリー・GPU）だけを後から重ねる。通信は既定で開けておく。秘密が見えなければ、通信で持ち出せるものが少ない。通信の許可リストは、新しいドメインのたびに摩擦が出るので、既定にしない。

### 4. 方針は 1 か所に置く

「見える範囲の一覧」を 1 つの設定にし、囲いの設定とファイルの道具の判定を、同じ一覧から生成する。設定は、ユーザー階層だけを読む。作業ツリーの中の設定は読まない（エージェントが書き換えられるため）。プロジェクトごとの追加（データセットの置き場など）も、ユーザー階層に置く。

### 5. 自作は 1 部品に限る

- 自作するのは、囲いを組み立てる 1 部品だけ。判定・認証の仲介・環境の管理・pi の拡張は作らない。
- **既存の囲いの穴は、自作で埋めない。** 「保証しない」と書くか、別の囲いに替える（凍結前に、Fence の穴を自作で埋めた結果、自作層が約 2,266 行になり、保守が続いた）。
- 昇格の仕組みは作らない。囲いの外が要る作業は、囲いなしの `pi` で行う。強さの切り替えは、起動時に選ぶ。

### 6. 守る対象（想定）

外部の文章に指示された、敵対的でないモデルの危険な操作（うっかりを含む）。敵対的なコードやモデルは、範囲外とする（環境ごとの隔離の領分。ADR-0027）。

### 自作の記録（ADR-0031 の 3）

| 項目 | 内容 |
| --- | --- |
| (a) 既存で満たせない理由 | 拡張は bash だけを包み、`bg_run`・`!` が抜ける。`runnerCommand` は拡張の内部の並びに依存する。調べた範囲（10 個の拡張。全ソースの精読ではない）では、bash ツールの差し替えが中心で、シェル全体を包むものは見つからなかった。`pi-permission-modes` の囲いは `--dev /dev` が固定で、GPU が通らない |
| (b) 維持費 | 引数を組み立てる runner（実装後は約 520 行。コメントと docstring を含み、設定の検証が約 3 割）、`pib`（約 100 行）、`pib-shell`（約 15 行）、設定、試験（約 150 件）、自己確認。追従が要る上流は、pi の `shellPath` の仕様 1 点。`bwrap` 自体は広く使われ、安定している |
| (c) 撤去条件 | pi 本体が、同等の sandbox を標準で持ったとき。`shellPath` の仕様変更が、2 回続けて保守の負担になったとき |
| (d) 承認 | 利用者が、責務の分担と、実装の方式（素の `bwrap`）を承認した（2026-11-12）。自作の範囲は、引数を組み立てる 1 部品で、この承認に含む |

## 結果

**得るもの**:

- `bg_run`・`!`・子エージェントの bash も、同じ囲いを通る。
- 拡張の内部に依存しない。runner の引数の並びの契約がなくなる。
- 見える範囲の方針が 1 か所になる。
- 認証は外に残る。凍結前の `pis` のような、認証の写しと戻しは要らない。

**失うもの**:

- 拡張が持つ、`write`・`edit` の防護。権限の層のパス判定に任せる（要確認。下の「未決」）。
- 昇格の仕組み。囲いの外が要る作業は、囲いなしの `pi` で行う。
- 実行中の強さの切り替え。起動時に選ぶ。
- 囲いの内側から、Windows の実行ファイルや docker を呼ぶこと。

**保証しないこと**:

- 信頼するコード（pi 本体・拡張・MCP）。
- 悪意のあるコードやモデル。
- 通信での持ち出し（見える範囲を絞ることで減らすだけ）。
- ファイルの道具の判定が、パスの抜け道（シンボリックリンクなど）を塞ぐこと（未確認）。

## 実装（2026-11-12）

仕様は [pi-sandbox-runner](../spec/sandbox/pi-sandbox-runner.md)。

- 部品は、`pib`（起動。`--offline` が強い設定）・`pib-shell`（`shellPath` に差す。`PIB_SANDBOX` があるときだけ囲う）・`pi-sandbox-runner`（`bash -c` を bwrap の内側で実行）・設定（`runner.toml`・任意の `runner.local.toml`）。
- 見える範囲は許可リスト型。ホーム・`/mnt`・`/tmp`・`/run/user` を空で覆い、`visible` に書いた所だけを重ねる。`hide` が後から勝つ。
- `shellPath` は pi の `settings.json` に Linux だけ入れる（`modify` の生成）。`pib` は、囲いが効かない状態（部品の欠け・`shellPath` が別の値・`HOME`・設定ディレクトリが正規の絶対パスでない）では起動せず、プロジェクトの `.pi/` の設定は `--no-approve` で読まない。
- 実測: bash ツール・`bg_run`・利用者の bash（RPC）・子エージェントの bash が、同じ囲いを通る。実機の自己確認（GPU の CUDA カーネルを含む）はすべて PASS。

### 実装で足した判断（ADR の範囲内）

- **worktree の git ディレクトリは、`.git` ファイルの値を信じない。** エージェントが書き換えられるため、git が登録時に書く back-reference と `commondir` の形が揃うときだけ、書き込み可で渡す。登録情報がエージェントの書ける場所にあるものと、作業ディレクトリを含む共有の `.git` は、形が揃っても渡さない（自己証明の防止）。
- **`shellPath` は、配備先の絶対パスそのものだけを認める**（別名のシンボリックリンクは、内側から付け替えられる）。`pib` は pi を常に `--no-approve` で起動し（実行時にプロジェクトの `.pi/` の設定を読まない。セッションの再開や `/resume` で別のディレクトリへ移っても、`shellPath` を上書きされない。起動時の `sessionDir` の先読みだけは pi の仕様で残るが、`shellPath` には影響しない）、`--approve` は受け付けない。代償は、プロジェクトの `.pi/` の設定（権限の設定など）が `pib` の実行で効かないこと。`HOME` と `PI_CODING_AGENT_DIR` は、正規の絶対パス（`.`・`..`・連続する `/` を含まない）だけを受け付ける（pi の字句的な整え方と OS の解決の違いで、検査する設定と読む設定が食い違うのを、解釈を再現せずに避ける）。
- **環境変数のトークンを、拒否リストで消す**（`env.unset`）。許可リストにはしていない（独自の名前は渡る）。
- **`visible` の追記は `runner.local.toml` に書ける**（共有の `hide` は後から勝つ）。`gpu`・`docker`・`git` は書けない。

## 見直しの条件

- 実測で、ファイルの道具の判定が外のパスを止めない（権限の層に任せられない）と分かったとき。
- 見える範囲の一覧が、実作業で小さく保てないと分かったとき（使われなくなるおそれ）。
- pi 本体が、同等の sandbox を標準で持ったとき。
