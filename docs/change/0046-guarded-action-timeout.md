# CHG-0046: 承認つきの操作（`guarded_action`）の時間切れを、退避して作業を続ける形にする

- **状態**: Exploring
- **更新日**: 2026-10-28
- **基準**: コミット 7422f88 以降、pi 1.4.0

## 目的と非目的

**目的**: `guarded_action`（`git commit`・`gh issue comment` など、承認つきの外部操作）の確認が**時間内に取れなかった**とき、親が止まって利用者の指示を待つのではなく、
**操作を実行せず、表示した内容を退避して、ほかの作業を続けられる**ようにする。利用者が戻ったときに、退避した内容を確かめて取り込める。
承認が取れないのは、利用者が席を外している・別の作業をしているとき（[CHG-0041](closed/0041-commit-auto-in-bypass.md) で見送った「確認の時間切れ問題」の移管先）。

- 承認が無いまま実行しない。**時間切れで勝手にコミットすることはしない**
- 退避は、HEAD・ブランチ・インデックス・作業ツリーに触れない（コミットのオブジェクトを作り、ref を置く）。**副作用ゼロではなく、「object と ref の保存を許す」機能**として定義する
- 利用者が**明示的に拒否**したときは、従来どおり（続け方を確認する）

**非目的**: 時間切れでの自動コミット・自動実行。bypass での確認の省略（CHG-0041 で見送り）。確認の画面の作り替え（編集中・拒否理由の入力中の期限は、初版の対象外）。

## 現在地

- **経路ごとの仕様の違い**（`review` の指摘で位置づけを訂正。2026-10-28）:
  - `docs/spec/guard/pi-extensions.md` の「時間切れと退避」は、**素の pi の補助拡張**（`commit-confirm`。bash の `git commit` を見る）の節。時間切れ・不在・画面なしは、`refs/pi/pending/<時刻>` に退避して、作業を続けさせる
  - 同じファイルの `guarded_action` の節（74 行）は、**無反応・取消・UI なし・子を、拒否（`not approved:`）と明記**している。つまり、現状は仕様どおり。「実装漏れ」ではなく、**利用者の運用方針（承認が取れなければ、そのまま次の作業へ）に合わせて、2 つの経路の仕様を統一する変更**
- **実際の経路**: コミットは `guarded_action` の `git_commit`。時間切れ（`DEFAULT_TIMEOUT_SECONDS` = 300 秒。`pi.confirm.timeout_seconds`）は、`outcomeReason("timeout")` を投げる。文言は「確認が時間内に無かったので拒否した。**再試行せず、利用者の新しい指示を待つこと**」。`guarded_action` を持つ役割では、bash の `git commit` は deny（`replaces`）なので、退避つきの経路は使われない
- **影響**: 2026-10-28 のセッションだけで、承認の時間切れが 6 回前後（会話からの概数）あり、そのたびに親が止まり、「もう一度」の指示を待った。ステージ内容とメッセージも、毎回作り直した
- **退避の部品**（`commit-confirm/pending.ts`）: `savePending` が、`commit-tree` でコミットのオブジェクトだけを作り、`refs/pi/pending/<時刻>` に置く。hook は呼ばれない。入力は bash の `git commit` の解析結果（`Analysis`）で、**保存の時点のインデックスを読み直す**（`wouldCommit`）。直前の保留があれば、それを親にした鎖にする
- **確認の画面**（`actions.ts`）: 期限があるのは最初の `select` だけ。「編集して承認」の `editor`、「拒否」のあとの理由入力 `input` には期限が無く、離席すると無期限に止まる

## 設計（案）

### 結果の分類（`review` の指摘 R1-4）

`guarded_action` の結果を、次に分ける。退避の文言は `actions.ts` 側で作り、共通の拒否理由（`outcomeReason`）を流用しない（退避していない別の経路を、退避済みに見せないため）。

| 結果 | モデルへの返答 |
| --- | --- |
| `executed` | 実行した |
| `deferred` | **元の操作は未実行**。退避した ref・件名・対象のファイル数。「再試行しない。この操作に依存しない作業を続け、最後に『保留した操作』として報告する」 |
| `defer_failed` | 未実行で、**退避もできなかった**（理由）。成功した ref は返さない。独立して進められる作業だけ続ける |
| `denied` | 利用者が拒否した。同じ操作をくり返さない。続け方を確認する（従来どおり） |
| `aborted`・`error` | 従来どおり |

### 時間切れの扱い（`git_commit`）

| 状況 | 今 | 案 |
| --- | --- | --- |
| 承認 | 実行 | 変更なし |
| 利用者の拒否 | `denied` | 変更なし |
| 最初の選択画面の無応答（時間切れ） | 拒否・待つ | **`deferred`** |
| 不在（先の時間切れのあと、利用者の入力が無い） | 毎回待つ | 待たずに `deferred` |
| UI なし（非対話の親） | 拒否 | `deferred`。ただし、**子の拒否・判定器・引数の検査は、これまでどおり先に通す**（UI なしだからと飛ばさない） |
| 編集して承認の `editor`・拒否理由の入力中 | 無期限に待つ | **対象外（初版）**。段 6 で期限の UI を別に設計する |

### 表示した内容の保存（スナップショット。R1-1）

退避は、**画面に出した内容そのもの**でなければならない。時間切れのあとに、実のインデックスを読み直すと、待つ間に別の操作が変えた内容を、「その画面の内容」として退避してしまう。

- 確認の**表示の前**に、一時のインデックスから、tree を確定する（`wouldCommit` の結果）。メッセージとあわせて、次を保持する:
  `{ treeOid, baseHeadOid, branchRef, indexId, message, requestId }`
- 時間切れのあとは、**実のインデックスを読み直さず**、この tree とメッセージを保存する。確定の途中で状態が変わったときは、保存成功にしない（`defer_failed`）
- 代償: 表示の前に tree を作る費用が増える。拒否された場合にも、未参照の tree object が残る（`git gc` が回収する）

### 保存の形（独立した退避。R1-2）

- **保留同士を鎖にしない**。各退避の親は、**表示時点の HEAD**。他の保留を自動で親にしない（別ブランチ・別 worktree の保留をつなげる、先の保留を外した内容が「打ち消し」に見える、同じ tree・別メッセージが保存できない、という問題を避ける）
- 出自（worktree・ブランチ・HEAD・要求の ID）を、コミットのメッセージの末尾か、記録に残す
- `git_commit` の入力には `--amend` が無いので、初版の制約は「メッセージとステージ済みの内容」だけ。共有部品の制約（`--amend` は退避できない）とは分けて書く

### 取り込み（段 4）

- `git reset --soft <退避>` は、**現在のブランチ先端を置き換える**。後から作ったコミットを、ブランチの上から外す恐れがあり、保留とインデックスが違えば、差分も生じる。**一般の取り込みとしては勧めない**
- まず、**一覧・差分表示・破棄**を、保存と同時に提供する
- 取り込みは、HEAD・インデックスが保存時と違えば、**一括の採用を拒否し、内容を選び直す**。採用は、通常の `git commit` と同一視せず、hook・署名を通すかを明示する

### 退避の保存先・寿命・秘密（R1-6）

- ref から辿れるので、`git gc` では消えない。**インデックスから後で外した秘密も、ref に残る**。メッセージも永続化される。`--mirror` などの送信の対象になりうる（通常のブランチの push とは別だが、同じ扱いではない）。pre-commit も通らない。「インデックスにすでにあるので新しい露出ではない」とは言えない
- したがって、**保存と同時に、一覧・差分表示・選択的な破棄**を入れる（保存を先に有効にして、破棄を後にしない）。保持期間・到達可能性を、仕様に書く
- `gh` の本文など、git のオブジェクトにならない操作は、初版に含めない。保存先を決めてから有効にする（段 5）。候補: 作業ツリー内の専用領域（権限 0700・記録 0600・排他的作成・リンクの拒否・ignore・保持と破棄の方針）。**保存する内容の保護と、モデルへ返す要約の伏字化は分ける**（復元できなくなるため、保存は原文）

### 実装の置き場（R1-5）

`pending.ts` を `harness/` から、兄弟の `commit-confirm/` へ import すると、配備先のサンドボックスの読み取りの許可（`~/.config/pi/harness` は有るが、`commit-confirm` は無い）に合わない恐れがある（未確認）。
最小の保存処理（`commit-tree`・`update-ref`）を `harness/` 配下に切り出し、素の pi 側（`commit-confirm`）がそれを使う形にする。解析・近似復元は持ち込まない。

### 不在の状態（R1-4）

- 親のセッションに属させ、**待ちの列（キュー）の中で判定**する（キューに入れる前ではなく）。すでに並んだ呼び出しが、次々に待たない
- 利用者の入力に世代番号を持ち、確認の開始後に入力があれば、その確認の時間切れで、不在を再設定しない
- `session_start` で初期化する。`git` と `gh` で共有するかは、段 5 で決める

## 評価基準

**必須**:

- **承認が無いのに、操作が実行されない**。HEAD・ブランチ・インデックス・作業ツリーが変わらない
- **退避の内容が、承認の画面に出した内容（メッセージと対象）と一致する**。待つ間に、別のプロセスがインデックス・ブランチ・HEAD を変えても
- 時間切れ・不在・UI なしのとき、親が止まらず、`deferred`（退避の ref・件名・未実行）を返す。保存に失敗したら `defer_failed` で、成功した ref を返さない。モデルが再試行しない
- 利用者の明示的な拒否・中断は、従来どおり
- 保存と同時に、一覧・差分表示・破棄が使える。秘密を模した値が、保存後にインデックスを変えても残ること・破棄で消せることを確かめる

**望ましい**:

- 並んだ `git_commit` が、先の時間切れで、後ろを待たない。待機中の入力のあとの時間切れで、不在が誤って再設定されない
- 承認の画面に「N 分応答が無ければ、実行せず内容を退避して作業を続ける」と出る
- 実モデルの小さな実験で、「コミット済み」と誤報しない・退避した操作に依存する作業を、成功の前提で進めない
