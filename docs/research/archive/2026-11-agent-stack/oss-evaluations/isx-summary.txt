## git の方式（kcage の clone モードの参考。最重要）
- **入れ方**: 箱の中で clone する。ホストの checkout は mount しない。`host-source` は、枝/タグの先端から届く objects だけを新しい独立 repo へ詰める（hooks・config・作業ファイルは入れない）。ホストのスナップショットを貸すときは、最小の bare repo を **ro** で mount し、箱側で `clone --no-hardlinks`・alternates を拒否・SHA-256 を検証する（docs/dev/GIT-PREPARATION.md）。
- **取り戻し方**: `isx://<箱>/<path>` の remote helper。ホストの git が、箱の中の `git-upload-pack`／`git-receive-pack` **だけ**（allowlist。uid 1000 で実行）へ pack プロトコルで直接接続する。ホストには hooks・config が転送されない。ホストで見る手順は `git diff main..fix-auth/main`・`cherry-pick`。
- **未確認**: ホストの fetch に `fetch.fsckObjects` を強制しているか（強制しているのは準備時の clone だけ）。
- **費用**: 作業ツリーを live に見られない。feature の worktree・`git flow` を使う運用とは前提が違う。

## 借りる価値のある点
1. clone＋fetch（上記）。ホスト側の fetch には `transfer.fsckObjects=true` を付ける。
2. 起動のたびに、制限を再適用・検証し、許可していない NIC・pci/usb・proxy デバイスが加わっていれば拒否する。機能が足りなければ fail closed（箱の中の規則へ降格しない）。
3. proxy-only を Incus の NIC ACL（ホスト側）で作る方式（kcage は NIC なし＋proxy デバイス。強さは kcage のほうが上だが、ACL 方式は設定が単純）。
4. doctor の 4 値（OK/WARN/FAIL/NOTE。NOTE は終了コードに影響しない）と `--bundle`（出力の構造的な伏せ字）、他ユーザーの holder の検出、秘密を置くファイルの権限。
5. `mcp.yaml`（agent は書けない許可表）・`host-routes`（`*.isx.internal`。箱からホストの制御役を呼ぶ）の発想。
