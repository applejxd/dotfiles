# トラブルシューティング

## 同梱スクリプトを実行できない

実行環境のポリシーで `python3 <script>.py` 形式の実行が拒否されることがある。ポリシーを迂回せず、同等の標準コマンドへ切り替える。

| 用途 | 代替 |
| --- | --- |
| ソース取得 | `curl -L -o eprint.tar.gz https://arxiv.org/e-print/<id>` と `tar tzf` / `tar xzf` |
| メタデータ | `curl -L "http://export.arxiv.org/api/query?id_list=<id>"` |
| ライセンス表示 | `curl -L https://arxiv.org/abs/<id>` を取得して `licenses/` を含む行を探す |
| PDF の基本情報 | `pdfinfo main-ja.pdf` |
| 本文抽出 | `pdftotext -enc UTF-8 main-ja.pdf main-ja.txt` |
| ページ画像化 | `mutool draw -r 100 -o page-%d.png main-ja.pdf 1,2,25` |
| ログ検査 | `grep -cE '^! ' main-ja.log`、`grep -c 'Missing character' main-ja.log` |

代替手段も拒否された場合は迂回せず、拒否内容をユーザーへ報告する。

## arXiv ソースが tar として展開できない

レスポンスが単一 TeX、gzip、エラーページの場合がある。Content-Type だけで決めず、ファイル形式を検査する。展開時は絶対パスと `..` を拒否し、作業ディレクトリ外へ書き出さない。

## ルート TeX が分からない

`\documentclass` を含むファイルを列挙し、`\input` / `\include`、画像、書誌ファイルの依存関係を確認する。ファイル名が `main.tex` とは限らない。

## 最終コマンドが欠落する

最終行に改行がないと、行数ベースの分割で `\end{document}` を落としやすい。分割後と統合後に文書終端と環境の均衡を検査する。

## 日本語が豆腐になる

フォントが未導入、フォント名が異なる、数式フォントに日本語を流している可能性がある。`fc-list`、ログの `Missing character`、PDF のフォント一覧を確認する。

## 目次や Figure が英語のまま

本文翻訳とは別に `\contentsname`、`\figurename`、`\tablename`、`\refname` を再定義する。クラスや babel/polyglossia の設定が上書きする場合は読み込み順を確認する。

## 引用が `?` になる

BibTeX/Biber の方式を原著から変えず、`latexmk` で必要な回数を実行する。翻訳時に引用キーを変更していないか比較する。

## 図中の英語が残る

キャプション翻訳だけでは不十分。すべての画像を開き、軸、凡例、吹き出し、ノード名を確認する。数式変数と自然言語を区別する。

## 原著がそもそもビルドできない

原著プリアンブルがクラス依存の未定義マクロ（`\thechapter` など）を参照していることがある。arXiv は投稿時の環境でビルドしているため、手元の TeX Live で失敗しても異常ではない。原著側を最小限の修正でビルドできる状態にし、訳文側にも同じ修正を入れる。修正内容は作業記録に残す。

## 分割翻訳で用語が揺れる

節をまたぐ同義語（「接続／つながり」「実現／ドロー」など）、区切り記号（`：` と `:`）、段落見出しの句点は分割の副作用で揺れる。統合後に全見出しと用語集の語を一覧して統一する。校閲サブエージェントは担当範囲しか見ないため、この工程は分割せずに行う。

## PDF は生成されたが内容が欠ける

`pdftotext` で節見出しと末尾を確認し、先頭・中間・末尾、図表ページを画像化する。ページ数だけでは全文性を保証できない。
