# 自宅の機だけの指示

## 開発中の Web サービス

- 開発中の Web サービス（開発サーバ・ダッシュボード・API の試作など）は、Tailscale が使える機（`tailscale status` が成功する）では、**tailnet の中だけに公開する**のを原則にする。アプリは `127.0.0.1` で待ち受け、`tailscale serve --bg <ポート>` で出す。`0.0.0.0` での待ち受けと、インターネットへ出す `tailscale funnel` は、利用者が明示したときだけ。tailnet の端末は利用者本人のものだけなので、tailnet への公開に、認証の有無や中身を理由にした事前の確認・警告は要らない（利用者の方針。2026-11-17）。
- 公開の手順（構文の確かめ方・WSL の機での `tailscale.exe`・既存の https ポートを上書きしない・片付け）は `tailscale-serve` スキルを読む。

## 複雑な不具合の修正が膠着したとき

- **膠着の判断**: 同じ失敗に対する修正を 2 回試しても、原因を絞る新しい証拠が得られなければ、追加の編集を止める。失敗しても仮説を一つ潰せたなら進捗とみなす。承認待ち・長時間コマンドの実行中・外部サービス待ちは膠着とみなさない。
- **起動前の確認**: 利用者が委譲を止めていなければ、`subagent` の `action: "list"` に `options: { agentScope: "user", capabilities: true }` を指定する。`oracle` が読み取り専用の Pi の子（ツールは `read`・`grep`・`find`・`ls` の範囲のみ）で、Astra でない Copilot モデルに割り当てられていると確認できなければ起動しない。
- **独立した診断**: 確認を通った場合だけ、その膠着について `oracle` を 1 回だけ起動する（`async: true`、`options.agentScope: "user"`、`options.context: "fresh"`、モデルは指定しない）。再現手順、期待値と実際の結果、否定した仮説とその根拠、関連するファイルを渡す。親の推測は事実と分ける。別の有力な原因仮説と、仮説を区別できる最小の実験を求める。
- **修正の再開と停止**: 親がその実験を行い、原因を絞る証拠が得られたら修正し、元の再現手順や回帰テストで確認する。原因を絞れないか独立した診断ができなければ、編集を重ねず、試したことと未解決点を利用者に報告して止める。Astra は利用者が明示したときだけ使う。
