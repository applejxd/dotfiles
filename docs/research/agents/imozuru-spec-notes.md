## 記録 I2 — 検索役のサブエージェントを使わない理由（採らなかった案）

- **観測日**: 2026-10-21 / 2026-10-24

### 問い

上流の「検索役」（Web 検索できる軽いモデルのサブエージェント 2 本）を、このリポジトリでも使うか。

### 結果

元の文: このリポジトリの `guarded_task` の子（`explore` / `review`）は読み取り専用だが、`websearch.py` の `search`・`papers`・`fetch` と `chain.py` は確認なしに実行できる（2026-10-24 に `explore` の子で `websearch.py search` を実行して確かめた。許可は `[pi.skill_scripts.allow]` にあり、役割を問わず効く）。

なお、`explore` / `review`（`explorer` 役）の子は、スキルのスクリプトの許可が全役割に効くため、`websearch.py` の `search` / `papers` を確認なしで呼べる（2026-10-21 の実測。使い捨ての試験）。専用の検索役 `searcher`（`bash` だけ・`search` / `papers` だけ・軽い階層）を足す案は、imozuru の試用のあとに判断する。

### 考察

採らなかった案: 専用の検索役 `searcher`。既存の許可で子が `search` / `papers` を呼べるので足さない（試用後に再判断）。

## 記録 I3 — `pis` の内側のプロキシ越しの取得（2026-10-25）

- **観測日**: 2026-10-25
- **環境**: `pis -p` の内側

### 結果

元の文: 内側は DNS が引けないので、`url_problem` の事前の名前解決で全 URL が失敗していた。Fence のプロキシは、許可ドメインの外を 403 で拒む（`curl` で実測）。

実測（2026-10-25、`pis -p` の内側）: `fetch.py` は arxiv の abs を `OK`（終了コード 0）で保存でき、許可外のドメインは
`FAIL … URLError: <urlopen error Tunnel connection failed: 403 Forbidden>`（終了コード 1）で止まった。

仕組みは [web-search の記録](web-search-spec-notes.md) と同じ。

## 記録 I4 — レビューの経緯（2026-10-22）

- **観測日**: 2026-10-22

`review` の子（別系統のモデル。読み取りと `git` の読み取りだけ）に、取り込む前に 3 回レビューさせた（2026-10-22。1 回約 0.2〜0.4 ドル）。最初の 1 回は展開前の取得物しか無く、読めなかった。

| 回 | 見つかったこと | 対応 |
| --- | --- | --- |
| 2 | **BLOCKER**: `confine()` が渡したディレクトリしか見ず、中の子パスのシンボリックリンク経由で外へ書ける / DNS の検査後に再接続するので DNS rebinding が効く。**MAJOR**: 送る URL・題名・著者名に秘匿チェックが無い / `yt-dlp` の設定・標準入力 | リンク走査・根の固定・`imozuru_net.py`・`refuse_secrets()`・`--ignore-config` と標準入力の遮断 |
| 3 | **BLOCKER**: プロキシ環境変数があるだけで直接接続も固定を失う / ハードリンクが `confine()` を通る。**MAJOR**: YouTube（`yt-dlp`）は固定を通らない / 代替の秘匿検査が弱く、feed URL は送る直前に検査されない | 要求ごとのプロキシ判定・ハードリンクの拒否・YouTube の分離・代替の補強・feed URL の検査 |
| 4 | **BLOCKER**: プロキシ経路は固定できない。**MAJOR**: YouTube の環境変数は継承で迂回できる / feed URL は名前を引いたあとに秘匿検査している | 環境変数をやめて `fetch_youtube.py` に分離・秘匿検査を先に移した。プロキシ経路は**許可に載せないことで対応**（修正は未着手） |

- レビューは、3 回とも私の暫定の結論に反対した（「`confine()` を足せば全部を許可に載せてよい」など）。依頼文は、`pi-guard.md` の「[review への依頼の書き方](../../spec/guard/pi-guard.md#review-への依頼の書き方)」の型で書いた
- レビューの子は**コードも試験も実行できない**（判定で拒否される）。「53 件が通った」などの実行結果は、親が実行した値で、子は再検証していない
- 問題なしとされた点: `fetch.py` の `<name>`（単一のファイル名）の検査、`report.py` の引用元の検査、外部コマンドを引数リストで起動していること
