# 撤去後の試験を、これ以上減らす価値があるかの実測（2026-11-12）

> **現行の仕様**: [開発ガイドの検証の方針](../../spec/development.md#検証の方針と選択実行)。撤去の経緯は [ADR-0037](../../adr/0037-retire-custom-profile-and-other-harnesses.md)。

## 記録 T1 — 残った約 1,550 件の時間配分と、重複の洗い出し

- **観測日**: 2026-11-12
- **対象**: `develop` の `d7cbc7ef`（ADR-0037 の撤去の直後）に `f975f083` を重ねた状態。`pytest 9`・Python 3.13・6 並列。
- **結論（先頭）**: これ以上、試験の**件数**を機械的に減らす価値は薄い。時間は少数の遅い試験に偏っていて、重複らしい試験を減らすと、変異テストでの検出力が **5〜17%** 落ちた。

### 問い

1. 撤去後の全件（約 32 秒）の時間は、どこにあるか。
2. 他の試験に包含される、または同一のカバレッジの試験を減らせるか。減らして検出力は保たれるか。

### 時間の配分（`pytest --durations=0`）

- 合計 110.7 CPU 秒（setup・call・teardown）。`call` は 1,554 件で 92.7 秒。**0.1 秒未満が 1,413 件**。
- ファイル別: `test_shell_startup.py` 37.2 秒（33.6%・59 件。`runcpp` の C++ コンパイル）、`test_lint_templates.py` 10.3 秒（9.3%。`test_this_repository_passes` が 8.0 秒）、`test_pi_permission_decisions.py` 7.7 秒（`cc-safety-net` の表の試験が 4.7 秒）、`test_away_guard.py` 7.5 秒。
- 遅い順の上位 10 件で `call` の 36.3 秒、上位 30 件で 54.1 秒。**件数を半分にしても、時間はほとんど減らない**。

### カバレッジでの洗い出し

- 方法: `pytest-cov --cov-context=test` で、テストごとの行の集合を取り、(a) 他の 1 件の行の集合に厳密に含まれるもの（30 行以上）、(b) 同じファイル内で行の集合が同一のもの（先頭 1 件を残す）を数えた。
- 行のカバレッジが取れたのは 839 件だけ。残りは subprocess・シェル・docs・golden の試験で、この方法では判定できない。
- 結果: (a) 236 件、(b) 309 件が「減らせそう」に見えた。多くは `test_pi_sandbox_runner.py`（73 件）・`test_review_converge.py`（41 件）・`test_verify.py`（32 件）・`test_away_guard.py`（30 件）にある。

### 変異テストでの確認

方法: 対象のスクリプトに 1 か所ずつ変異を入れる。変異は、比較演算子の入れ替え・`and`／`or` の入れ替え・真偽値の反転・整数の ±1・`not` の除去・加減算の入れ替えの 6 種類。変異ごとに、同じファイルの試験を「全部」と「(a)(b) を除いた残り」で回し、落ちた（殺した）変異の数を比べた。簡易な自作の変異器（`ast`）で、`mutmut` ではない。

| スクリプト（対応する試験ファイル） | 変異数 | 全試験で殺した | 減らした後で殺した | 除いた試験 / 全試験 |
| --- | ---: | ---: | ---: | --- |
| `converge.py`（`test_review_converge.py`） | 97 | 82 | 68（−14） | 47 / 78 |
| `executable_away_guard.py`（`test_away_guard.py`） | 200（213 か所から抽出） | 102 | 94（−8） | 59 / 118 |
| `executable_pi-sandbox-runner`（`test_pi_sandbox_runner.py`） | 129 | 110 | 104（−6） | 128 / 284 |

- 約半分の試験を除いて、殺せる変異が 5〜17% 減った。**同一カバレッジの重複**（パラメータ違いの入力の試験）が、行は同じでも値の検査で変異を殺していた。
- `converge.py` で、(a) の 41 件だけを除いた別の実行（試験ファイルとスクリプトだけの一時コピー）では、80 件を殺し、減らす前と同じだった。(a)（包含される試験）より (b)（同一カバレッジの重複）のほうが危険、という傾向だが、1 ファイルだけの観測で、一般化しない。

### 限界

- 変異は 6 種類だけで、生き残った変異（`converge.py` は 15 件）には、等価な変異が混じる。`mutmut` などでは未確認。
- 同じファイルの試験だけで殺傷を数えた。他のファイルの試験が殺していた変異は、除いた試験の分として数えていない（重複を過大に見る方向）。それでも検出力は落ちた。
- 行のカバレッジが取れない試験（約 700 件）は対象外。

### 決めたこと

- 件数を減らす作業はしない。撤去（ADR-0037）で、13,593 件から 1,607 件、約 12 分から約 32 秒になったので、残りは時間でなく検出力を守る。
- 時間を詰めるなら、遅い少数の試験（`runcpp` の C++ コンパイル・`test_lint_templates.py::test_this_repository_passes`・`cc-safety-net` の表）を対象にする。いずれも変更に応じた選択実行（`mise run verify`）で、関係する変更のときだけ走る。
