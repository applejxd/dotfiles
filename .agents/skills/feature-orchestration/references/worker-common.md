# worker の共通の約束

親の依頼文から参照される。依頼文の個別の指示（担当ファイル・作ること・合格条件）が、ここより優先する。

## 役割と境界

- 編集するのは、依頼文の**担当ファイルだけ**。**編集は worktree の絶対パスだけで行う**（相対パスだと、本体のファイルを書き換えてしまうことがある。実際に起きた）。担当外のファイル・ほかの worktree・本体は、読み取りだけ（使い捨ては `$TMPDIR` に置いてよい。役割の system が正本）。
- git の状態を変える操作はしない（親が行う。役割の system が正本）。
- 同じ worktree や隣の worktree で、別の worker が動いていることがある。担当ファイルは分かれている。他の担当の途中状態で、試験が一時的に落ちることがある（自分の担当と関係がなければ無視し、最後に 1 回だけ再実行する）。
- 担当のコード以外にバグを見つけたら、直さず、再現のコマンドつきで報告する。

## ツール

- bash での読み書き・一行スクリプトは拒否される（役割の system が正本）。ファイルは `guarded_write` / `guarded_edit` で書き、読むのは `guarded_read`、探すのは `guarded_grep` / `guarded_find`。
- `guarded_edit`: 同じファイルへの編集は、1 回の呼び出しの `edits[]` にまとめる。`oldText` は一意にする。
- **整形 hook が、書き込み直後にファイルを書き換える**。続けて編集するときは、先に読み直す。
- 長いスクリプトは、ファイルに書いてから実行する。

## 検査

- 行長は 140（E501）。subprocess の `text=True` には `encoding="utf-8"` が要る。シェルスクリプトは先頭に `set -eu`。
- 重い検査（`mise run verify:all`）は回さない。**設定や生成物を変えたときは、その値を固定している既存の試験を `grep` で探して（キー名・値で `test/` 全体を検索）、同じファイル群を回す**。変更の意図どおり期待が変わる試験は、期待値をハードコードせず、単一ソースの値から取る形に直す。`uvx ruff check test scripts`、担当の試験、`uv run pre-commit run --files <ファイル>`（新規ファイルはステージ済みのときだけ検査される。ステージは親が行う）。
- 新しい試験ファイルを `scripts/verify.py` の `_PI_TESTS` に登録するのは、**依頼文が許したときだけ**。許されていなければ、親が登録するので、報告に「登録が必要」と書く。
- **広い範囲の試験（`test/agents/` 全体など）は、直列で回さない。** `pytest` は既定で直列で、`test/agents/` は約 31 分かかり、打ち切りの上限（約 15 分）に当たる（実測。全件検査は 8 並列で約 6.5 分）。広く回すときは `uv run --with pytest --with pyyaml --with pytest-xdist --no-project pytest <範囲> -q -n 4 --dist worksteal`（並列度 4。親や他の worker と同時に動くので、これより増やさない）。担当の数ファイルだけなら直列でよい。**時刻に依存する試験は、負荷で 1 度だけ落ちることがある**。落ちたら、その試験だけを単独で再実行して通るかを確かめ、報告に「負荷で揺れた」と落ちた出力を書く（親が原因を調べる）。

## 公開リポジトリ

- 私物・勤務先の具体（組織名・環境・ポリシー・社内の URL）を、コード・コメント・docs・試験のどこにも書かない。条件つきの一般論で書く。
- docs は日本語。日付を書くときは `date '+%F %H:%M'` で確かめる。

## 時間と報告

- **約 15 分で打ち切られる**。優先順位の高い順に作り、時間切れの前に報告する。
- 報告に入れるもの: 変更・作成したファイル、各検査の出力（抜粋。「通った」は実行した出力を添える）、依頼や型と食い違った点、確かめられなかったこと、未完了の項目とその原因、判断に迷った点。
