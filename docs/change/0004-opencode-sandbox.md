# CHG-0004: OpenCode の保護を OS のアクセス制御へ移す

- **状態**: In progress
- **更新日**: 2026-09-22
- **基準**: OpenCode V2（`v2.0.12`）/ `@anthropic-ai/sandbox-runtime` v0.0.76
- **対象 OS**: **Ubuntu / WSL のみ**（macOS と Windows は [CHG-0002](0002-opencode-ask-by-default.md) の方針を維持）

## 目的と非目的

**目的**: 列挙型の規則では任意コード実行の権限境界を作れないので、
**OS のアクセス制御を保護の主役にする**。自動許可は事前承認した作業範囲に
限り、実ホームへの適用と外部への作用は別の権限として扱う。

**非目的**:

- macOS / Windows の設計変更。bwrap が無いので現行方針を維持する
- Claude Code / Copilot CLI の設計変更
- **「sandbox を入れたので全部 `allow`」にすること**。境界はファイルの話で、
  通信・認証情報・公開操作は別に扱う（[判断の根拠](#なぜ切り替えるか)）

## 発端

[CHG-0002](0002-opencode-ask-by-default.md) は「境界は無い」という前提で
plugin に安全網を積んできた。段階 3 まで配備した時点で次が見えた。

| 観測 | 内容 |
| --- | --- |
| 規則が単調増加している | 誘導 5 本・伏字化 9 本・パターン 71 本。誤爆のたびに除外条件が増える |
| 誤爆の原因が構造的 | 「コマンドとして使う」と「文章として書く」をシェルの構文解析なしに区別できない。1 日で 3 件踏み、うち 1 件は**コミットそのものができなくなった** |
| **書き込み保護が成立していない** | write deny の 38 glob は `edit` ツールにしか効かず、shell のリダイレクトには**一切効かない** |
| 塞げない経路が残る | `printf` / `tee` / `python3 -c "open(...)"`、`> $VAR`、`base64` / `tr` |

決定打は 3 番目。**保護の中核が動いていなかった**。

## なぜ切り替えるか

判定の問いが変わる。

| | 列挙型 | 境界がある場合 |
| --- | --- | --- |
| 各コマンドに問うこと | このコマンドは何ができるか（**shell では答えられない**） | 効果は境界の外に出るか |

後者は答えられる。列挙の対象が「許すもの（約 300 件）」から
**「越えるもの（10 件程度）」**へ縮む。

### 境界を過信しない

外部レビュー（Astra）の指摘を採る。**sandbox は許した範囲内の事故を防がない。**

| 危険 | 境界で防げるか |
| --- | --- |
| 秘密の読み出し・持ち出し | **防げる** |
| 境界外への書き込み | **防げる** |
| 未コミット成果物の破壊 | **防げない**。git が唯一の網 |
| ネットワーク経由の送信 | 許可ドメインの範囲でのみ可能 |
| リポジトリ自身への細工 → 後日の `chezmoi apply` で実環境へ | **防げない**。適用時の差分確認が唯一の網 |

最後が効く。**このリポジトリは「ホーム全体を書き換える source state」**なので、
境界内で自由に書けることは「後で実環境へ反映される内容を自由に書ける」ことと
同義になる。だから `chezmoi apply` を境界の外に置き、そこで差分を見る。

### 段階 0: `srt` の成立確認と構成の決定（完了）

`@anthropic-ai/sandbox-runtime` は Claude 専用ではなく**汎用**で、seccomp の
ために**既に導入済み**だった。実地で次を確認した
（[調査記録](../research/opencode/permission/sandbox-runtime.md)）。

| 検査 | 結果 |
| --- | --- |
| `~/.ssh` / `~/.config/gh` / `~/.git-credentials` | 拒否 |
| ワークスペースの読み書き | 成功 |
| **`git push`** | **`could not read Username`** |
| **`gh auth status`** | **未ログイン扱い** |
| 許可ドメイン / 許可外ドメイン | `200` / **遮断** |
| `cmd.exe`（WSL の脱出経路） | **拒否**（seccomp） |
| **`chezmoi`（snap）** | **internal error** |

**認証情報を見せないだけで `git push` と `gh` の書き込みが止まる。**
コマンド文字列の判定は 1 つも要らない。

#### 構成の決定: サービスではなく**実行ごと**に包む

当初は `opencode serve --service` を包む想定だったが、**成立しなかった**。

サービスは TCP `127.0.0.1` で待ち受け、TUI がそこへ接続する。Linux の `srt` は
**ネットワーク名前空間を丸ごと除去する**ため、内側で待ち受けても外から届かない
（実測: 内側の `bind` は成功、外側からの接続は `TimeoutError`）。

代わりに **plugin が `tool.execute.before` でコマンドを `srt` 包みに書き換える**。
差し替えが効くことを計装で確認した。

```text
original: echo REWRITE_ME  →  mutated: echo REWRITTEN_BY_PLUGIN
モデルが受け取った出力: REWRITTEN_BY_PLUGIN
```

**この構成の代償**は次の 2 点。計画に織り込む。

| 代償 | 影響 |
| --- | --- |
| `read` / `edit` / `grep` / `glob` は境界の外に残る | `grep` / `glob` は**段階 5 で禁止して shell へ寄せる**。`read` / `edit` は permission の deny（実測で効く）に委ねる |
| 「包むかどうか」の判断が文字列に戻る | **既定は包む**ので、漏れても安全側へ倒れる（列挙の向きが反転する）。例外は `chezmoi apply` のみで、適用は人間の操作へ寄せる |
| **固定費が全 shell 呼び出しに乗る** | CLI 経由で実測 **657 ms**（素の `echo` は 7 ms）。ライブラリ API で償却する想定だが**未計測**。基準 6 のゲートにする |
| **保護機構そのものが書き換えられる** | 権限設定も plugin のソースも全て書ける（実測）。`denyWrite` で守る |

#### 固定費への対処

plugin は node（サービス）の中で動くので、CLI ではなく**ライブラリ API** を使う。
`SandboxManager.initialize()` を plugin のロード時に 1 回だけ呼び、コマンドごとには
`wrapWithSandbox()`（文字列を返すだけ）を呼ぶ。プロキシの起動を償却できる。

**この償却は未計測。** 実装の最初に測り、割に合わなければ構成を見直す。

#### 分かった癖（導入時の注意）

- **`denyRead` は許可領域の内側にしか効かない。** 外側のエントリは
  **黙って読み飛ばされる**。「広い領域を deny → `allowRead` で戻す」が唯一の
  正しい書き方
- `allowWrite` はワークスペースの**根**を指定する。サブディレクトリだと失敗した
- 広い `denyRead` の下では `$HOME` が差し替わる。`$HOME` 直下に書けても
  実ホームには現れない（境界の破れと誤読しない）
- PATH の `srt` は**別物**（Python の字幕処理ツール）。実体を直接叩く
- 版は `latest` の浮動指定で **Claude Code と共有**している。片方の都合で
  上がると両方の挙動が変わる

### 段階 1: `chezmoi` を snap から外す

snap 版は bwrap 内で動かない。ブートストラップの 1 行を差し替える。

```sh
# README の変更
- sudo snap install chezmoi --classic
+ sh -c "$(curl -fsLS get.chezmoi.io)" -- -b "$HOME/.local/bin"
```

`~/.local/bin` は PATH にあり、`sudo` も不要になる。`chezmoi upgrade` が
使えるようになる副次効果もある（snap 版では効かない）。

**mise 先行には変えない。** `chezmoi` が `mise` を入れる一方向の依存を保つ。
逆にすると `chezmoi apply` の最中に mise 自身を更新する場面が自己参照になる。

**完了条件**: snap を外した状態で `chezmoi apply` が通り、sandbox 内で
`chezmoi --version` が動くこと。

### 段階 2: plugin が shell の実行を包む

`tool.execute.before` で `e.input.command` を `srt` 包みへ書き換える。

| 区分 | 置き場 |
| --- | --- |
| 書き込み可 | ワークスペースの根、`~/.cache`、`/tmp` |
| **書き込み禁止**（`denyWrite`） | `home/dot_config/agents/`、`home/dot_config/opencode/guide-plugin/`、`scripts/agents/generate.py`、`home/dot_config/mise/config.toml.tmpl` |
| 読み取り可 | 上記 + mise、`~/.local/bin`、**プロジェクトごとの許可パス** |
| **見せない** | `~/.ssh`、`~/.config/gh`、`~/.git-credentials`、`~/.config/opencode`、`~/.claude*` |
| **包まない**（境界の外） | `chezmoi apply` / `re-add`。`ask` のまま残す |

`denyRead` は「`/home/<user>` を deny して `allowRead` で戻す」形で書く。
ピンポイントの deny は**黙って無視される**。

#### 保護機構そのものを守る（`denyWrite`）

**権限設定も plugin のソースも、いまは全て書ける**（実測）。書き換えて
`chezmoi apply` を 1 回承認させれば保護が消える。`srt` の `denyWrite` は
`allowWrite` より優先されるので、ワークスペース内でもこれらだけ禁止にする。

この結果、**保護設定を変える作業自体が境界の外での操作になる**。
権限を変えるのに明示的な承認が要るのは正しい形だと判断した。

#### 包めないときは止める

包み込みに失敗した・引数の形が想定外だった場合に**通常の shell 実行へ落ちてはいけない**。
落ちるなら境界ではない。失敗時は `deny` にする（基準 4）。

#### 固定費のゲート（基準 6）

**着手の最初に実測し、許容値を超えたら構成を見直す。** CLI 経由は 657 ms/回
（素の `echo` は 7 ms）。plugin はサービス（node）の中で動くのでライブラリ API で
償却できる見込みだが**未計測**。

判定は「`initialize()` を 1 回にできたか」ではなく**実測遅延**で行う。

| 測るもの | 内容 |
| --- | --- |
| ウォーム時の短いコマンド | `git status` 相当の反復 |
| 代表的な作業全体の所要時間 | 検証コマンド一巡 |
| 異常時の挙動 | 並行実行・キャンセル・異常終了 |

段階 5 で `grep` を shell へ寄せると呼び出しが増える（実履歴で最多の 114 件）。
許容値はそれを見込んで決める。

#### `chezmoi apply` の扱い（P0-2）

境界の内側からは実行できない（ホーム全体への書き込みが要るため）。

**当初案（コマンド完全一致で例外にし `ask` で残す）は不十分。**
完全一致は**実行される内容を固定しない**。`chezmoi apply` が何をするかは
source state とスクリプトが決めるので、エージェントがそれらを編集できるなら、
1 回の承認で書き換えた内容が実行される。

したがって次の構造にする。

- エージェントは **source state の変更まで**
- **適用は差分確認のうえ人間が行う**
- 保護機構のソースは `denyWrite` で触らせない（上記）

作業の 1.0%（実履歴 11 件）なので、手作業に寄せても負担は小さい。

**完了条件**: 通常の作業が境界内で回り、秘密 3 パスが読めず、保護機構のソースが
書けず、`chezmoi apply` の適用手順が定まっていること。

### 段階 3: `ask` → `allow` へ反転

**設定で既定を下げてはいけない。** plugin 側で引き上げる。

```text
plugin が境界の実在を確認 → ask を allow へ引き上げる
  plugin が死んでいる       → 包む処理も引き上げも同時に死ぬ → ask のまま（安全）
  sandbox が起動していない  → 確認が失敗 → ask のまま（安全）
```

確認は環境変数ではなく**実際に見えないはずのパスを触ってみる**。起動時に
1 回で足りる。これで現在の fail-open が **fail-closed に反転**する。

> 2026-09-22 に、plugin が数時間ロードされていない状態を「配備済み」と
> 誤認する事故を起こしている。設定で `allow` に下げていたら全部素通りだった。
> [hook の呼ばれ方](../research/opencode/permission/hook-order.md)

引き上げの対象外（`ask` / `deny` のまま残すもの）。

| 残す理由 | 例 |
| --- | --- |
| 境界を越える | `chezmoi apply` / `re-add`、`sudo` |
| 内側でも不可逆 | `rm -rf` 系。未コミットの成果物は境界内でも壊せる |

**完了条件**: 境界が生きているときだけ確認が減り、境界を落とすと
確認が戻ることを実地で確認できること。

### 段階 4: 許可リストを `common.toml` で単一ソース化

パスとドメインの両方を `common.toml` から生成する。

#### プロジェクトごとのパス許可

chezmoi 管理下でも機密でないパス（`~/.config/shell` など）は、
プロジェクト単位で開けられることを実測した。

| パス | 設定 | 結果 |
| --- | --- | --- |
| `~/.ssh` / `~/.config/gh` / `~/.config/opencode` | 未許可 | **拒否** |
| `~/.config/shell` / `~/.config/mise` | `allowRead` | **読める** |
| `. ~/.config/shell/shellenv.sh` | — | **読み込み成功** |

> **許可リストをプロジェクト側のファイルに置かないこと。** 敵対的な
> リポジトリが `~/.ssh` を自分で許可できてしまい、
> [プロジェクト設定がグローバルに勝つ問題](../research/opencode/permission/gaps.md)と
> 同じ穴になる。`common.toml` にプロジェクトパスをキーとして持たせる。

#### ドメイン

`[sandbox] claude_network_allow` は現在 **Claude 専用**（Copilot にドメイン単位の
制御が無いため）。OpenCode でも使えば同じリストを共有できる。
実地で不足を洗う（`mise.jdx.dev` が入っていないことを確認済み）。

不足しても破綻はせず接続が失敗するだけなので、追記で回復できる。

**完了条件**: 検証コマンド（`uv run` / `pre-commit` / `mise`）が境界内で
通ること。

### 段階 5: 誘導の向きを反転し、不要になった層を捨てる

境界ができると、**保護されている経路と、されていない経路が入れ替わる**。

| 経路 | いま | 境界の導入後 |
| --- | --- | --- |
| shell | 保護が弱い | **OS が強制する** |
| `grep` / `glob` | 結果フィルタ（事後の除去） | **変わらず弱い** |
| `read` / `edit` | permission の deny（実測で効く） | 変わらず効く |

そこで**誘導の向きを反転**する。`execute.before` で例外を投げるとツールを止められ、
メッセージがモデルへ届くことを実測した
（[調査記録](../research/opencode/permission/sandbox-runtime.md)）。

| ツール | 扱い | 理由 |
| --- | --- | --- |
| **`grep` / `glob`** | **禁止し、shell の `grep -rn` / `find` へ寄せる** | 保護が事後の除去しかない。shell なら OS が強制する |
| `read` | **残す** | permission の deny が実測で効く。shell 代替は誘導で潰したばかり |
| `edit` | **残す** | 確実な代替が無い。shell で書かせると信頼性と確認負担が悪化する |

**これで「事後の除去に頼る経路」が消える。** 基準 2 の担保が最も弱い箇所を
無くせるのが狙いで、確認回数の話ではない。

#### 層ごとの判断

| 層 | 現在 | 移行後 | 理由 |
| --- | --- | --- | --- |
| 誘導（`cat` → `read`） | 2 | **0** | shell から秘密が見えなくなる |
| 誘導（`grep` / `glob` → shell） | 0 | **2** | 反転の本体 |
| 誘導（`cd` / ヒアドキュメント） | 3 | 3 | 作法と負担。境界と無関係 |
| 結果フィルタ | 37 | **0** | ツールを使わせないので不要 |
| 伏字化: パス参照 | 34 | **0** | shell から到達できない |
| 伏字化: 内容の形 | 9 | 9 | 境界内の `.env` などに効く |
| permission | 225 | 225 | `read` / `edit` とリポジトリ外を守る |
| **計** | **310** | **239** | **約 23% 減** |

#### 代償

`grep` は実履歴で最も多い残存呼び出し（114 件）。これが全て shell 経由になるので、
**固定費の影響が直撃する**。基準 6 の許容値はこれを踏まえて決める。

**完了条件**: 事後の除去に頼る経路がゼロになり、規則の総数が減っていること。

## 評価基準

**必須:**

1. Claude / Copilot / Codex / Gemini の生成物に diff が出ないこと
2. **保護対象 × 禁止操作 × 実行経路の組み合わせごとに、禁止操作を阻止する機構と
   検証根拠があること。** 阻止できない組み合わせは残余リスクとして明示し、
   受容を判断すること
3. **境界が起動していないとき、確認が減らないこと**（fail-closed）
4. **包めないときは実行を止めること。** 通常の shell 実行へ落ちるなら境界ではない
5. `chezmoi apply` を実行する手順が残っていること
6. 短いコマンドの実測遅延が、先に決めた許容値以内であること

**基準 2 の数え方。** 読み取り・書き込み・外部送信を分けて見る。
**結果フィルタは「実証できた情報開示の抑制」だけを担保として数え、
アクセス拒否とは同列に扱わない**（件数・エラー・集約に情報が残りうるため）。

> **削減目標は未達。** 当初の必須基準「規則と除外条件の総数が減っていること」は
> 達成できない。組み込みツールが境界の外に残り、それを守る規則を捨てられない
> ため。**安全性の改善を優先して必須条件を差し替えた。**
> 総数は補助指標として追い続ける（現在 310 件）。
>
> 「Claude Code も同じ構造だから健全」という論拠も**撤回した**。実装上の前例では
> あるが、残余リスクを受容してよい根拠にはならない（外部レビューの指摘）。

## 候補比較

| 候補 | 支持する根拠 | 不利な点 | 扱い |
| --- | --- | --- | --- |
| **`srt` で shell の実行ごとに包む** | 汎用・導入済み・proxy と seccomp が同梱。実地で成立 | 組み込みツールが外に残る。固定費 | **採用** |
| サービスごと包む | 組み込みツールも覆える | **不成立**。ネットワーク名前空間の除去で TUI から届かない。`--stdio` も不可 | **見送り** |
| **`grep` / `glob` を禁止して shell へ寄せる** | 事後の除去に頼る経路を消せる。誘導の機構をそのまま使える | `grep` は最多の呼び出し（114 件）で固定費が直撃 | **採用**（段階 5） |
| `read` / `edit` も禁止して shell へ寄せる | 全ファイル操作が境界の内側になる | `edit` に確実な代替が無い。信頼性と確認負担が悪化する | **見送り** |
| bwrap を自作でラップ | 依存が減る | proxy と seccomp を自作することになる | **見送り** |
| Landlock | mount namespace を作らない | ファイル制限だけで通信・IPC を覆えない | **見送り** |
| 列挙型を続ける | 追加費用ゼロ | 書き込み保護が成立せず、規則と誤爆が単調増加 | **打ち切り** |
| `gh` を文字列で fetch のみ許可 | 実装が小さい | `gh api -X POST` で抜ける | **見送り**。認証情報を渡さないことで代替 |

## 保留にしたもの

[CHG-0002](0002-opencode-ask-by-default.md) 段階 4 以降のうち、次は**保留**する。
境界ができれば不要になるか、作り直しになるため。

| 保留するもの | 理由 |
| --- | --- |
| リダイレクト先を分解して `edit` の判定表に当てる | 境界が同じことを OS 側で行う |
| `claude_write_deny_globs` にシェル起動ファイルを追加 | 境界の内側に入れなければ足りる（macOS / Windows では別途必要） |
| 少数の静的 allow を増やす | 反転すれば不要 |
