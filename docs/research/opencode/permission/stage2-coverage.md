# 段階 2 を配備した後の被覆率（実履歴 1,031 呼び出し）

> **調査日: 2026-09-22 / 対象: `opencode v2.0.12`**
>
> [CHG-0002](../../../change/0002-opencode-ask-by-default.md) 段階 2 の
> 配備後に、実際の効き方を実履歴で測った。「どれだけ確認が減るか」ではなく
> 「**どれだけ秘密への経路を塞げたか**」が主題。

## 0. 結論

| 問い | 結果 |
| --- | --- |
| 秘密へ触れた（触れうる）呼び出しの割合 | **15 / 1,031 件（1.5%）** |
| そのうち今の 3 層が受け止める割合 | **15 / 15 件（全件）** |
| 出力に実際に秘密が載っていた件数 | **4 件**。全件が伏字化または誘導で止まる |
| 誘導後も確認が出る割合 | **901 / 1,031 件（87%）** |
| 伏字化の誤爆 | **3 件（0.3%）**。いずれも保護パス名を**文字列として書いた**もの |

**確認はほとんど減っていない。** 減らすのが目的ではないので想定どおり。

## 1. 数え方

`session_message` を JSON 走査して `shell` ツールの呼び出しを取り出した
（1,031 件・全セッション）。判定器は**実物**を使う。

- 静的 permission: `build_opencode_permissions()` の `shell` 規則を後勝ちで当てる
- 誘導・伏字化: `guide-plugin/index.js` を node でそのまま動かす

**複合コマンドの分割は近似**。OpenCode の scanner の規則は非公開なので、
`&&` / `||` / `|` / `;` / 改行で割った。

## 2. 履歴をそのまま数えると誘導だらけになる

| 判定 | 件数 |
| --- | --- |
| 誘導 deny | 781（75.8%） |
| 確認（ask） | 240（23.3%） |
| 静的 allow | 6（0.6%） |
| 静的 deny | 3（0.3%） |

内訳は `cd` が 768 件で、ほぼ全部これ。**ただしこの数字は意味が薄い。**
誘導は止めるだけでなく**書き換えさせる**ので、規則ができた後は `cd` が
`workdir` 引数に置き換わり、同じコマンドは再び出てこない。

## 3. 誘導後の定常状態

`cd X && …` を剥がし、純粋な読み取りを `read` ツールへ移してから数え直す。

| 行き先 | 件数 |
| --- | --- |
| 確認（ask）のまま | 901（87.4%） |
| `read` ツールへ移る | 108（10.5%） |
| 静的 allow | 15（1.5%） |
| 静的 deny | 7（0.7%） |

**10.5% が deny の効く経路へ移った。** ここが段階 2-A の効果で、
確認の削減ではなく保護の獲得にあたる。

残る 901 件のうち、状態を変えないものは 103 件（11.4%）しかない。
残り 798 件はヒアドキュメント付きの長いスクリプトか、書き込みを含む。
**allow へ移せる余地は小さい。**

## 4. 秘密へ触れた呼び出しと、それを受け止める層

| 層 | 件数 |
| --- | --- |
| 伏字化（パス参照） | 7 |
| 誘導 deny（`cd`） | 7 |
| 伏字化（内容の形） | 1 |

出力に実際に秘密が載っていたのは 4 件。

| 実例 | 受け止める層 |
| --- | --- |
| `cat ~/.config/opencode/service.json; …`（サービスの password） | 伏字化（パス参照） |
| `tr '\0' '\n' < /proc/…/environ`（環境変数の token） | **伏字化（内容の形）** |
| `cd … && pgrep …`（サービス情報） | 誘導 deny |
| カナリア（検証用に自分で置いたもの） | 伏字化（パス参照） |

2 つ目が重要で、**パス判定では捕まえられない**。`/proc/…/environ` は
保護 glob に載っていないため、内容の形で見る規則が唯一の網になる。
逆に 1 つ目は値が不透明なら内容の形では捕まらない。**両方要る**。

## 5. 誤爆

出力全体が伏字になる呼び出しは 14 件（1.4%）。うち 3 件が誤爆で、
すべて**保護パス名をスクリプト本文やメッセージに書いた**もの。

```text
mise exec -- python3 - <<'PY'  … "/home/u/.ssh/id_ed25519" …   ← 試験用の文字列
```

配備直後に踏んだ `git commit -m '… ~/.claude.json …'` も同じ型で、
`deny_path_unless` で `git` / `gh` のメッセージ指定を除外して収めた。
残る誤爆はヒアドキュメント内の文字列で、**除外しようがない**
（コマンドとして使うのか文章として書くのかを構文なしに区別できない）。

誤爆しても理由が本文に残るので、再実行で回復できる。0.3% なら許容する。

## 6. 含意

- **段階 5（残り約 280 件の allow 化）は引き続き「何もしない」でよい。**
  状態を変えない呼び出しは 103 件しかなく、しかも自動実行では
  `allow` と `ask` が等価
- **内容の形による伏字化は外せない。** パス判定では `/proc/…/environ` の
  ような経路を捕まえられない
- **誘導の価値は確認削減ではなく経路の移動。** 10.5% が `read` へ移り、
  そこでは permission の `deny` が実際に効く
