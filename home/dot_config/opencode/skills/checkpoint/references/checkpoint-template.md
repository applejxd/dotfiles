# Checkpoint テンプレート

下のコードブロックの中身をそのまま写して使う。

- 見出しは 6 つを**この順序で**置く。`checkpoint.py lint --structure` が検査する
- `<!-- machine: -->` より下は hook が上書きするので、人も AI も書かない。
  圧縮時刻・HEAD・作業ツリーの状態はそこに入る。**ヘッダには書かない**
- `covered_through` には**その要求の固定境界**を書く。現在の会話地点ではない

復帰試験（段 3）で分かった、外すと復帰できなくなる点:

- **`## Next` は「何を」だけでなく「どうやって」まで書く。**
  「段 3 の復帰試験を実施する」だけでは、手順と合格条件が分からず着手できない
- **略語・独自の用語をそのまま使わない。** 展開するか `## Refs` で参照先を示す
  （「A1 最小構成」のような語は、前任者の会話を持たない読み手には通じない）
- **`## Refs` に未作成の文書を挙げるときは「未作成」と明記する。**
  復帰に必須ではないと分かれば、読み手は探しに行かずに済む

```markdown
<!-- checkpoint: v1
     session: <セッション ID>
     cli: opencode
     updated_at: <ISO8601>
     covered_through: <その要求の固定境界>
-->
# Checkpoint — <作業の短い名前>

## Goal

<3 行以内。これを満たしたら終わりと言える条件>

## Constraints

<ユーザーが指定した制約。却下済みの方針。1 行ずつ>

## State

<完了したこと / 未完のこと / 未解決の論点。各 1 行>

## Evidence

<実行したコマンドと結果。推測は書かない>

## Next

<次の 1 アクションだけ。「何を」だけでなく「どうやって」まで書く>

## Refs

<docs/... へのパス + 何のために読むのか。未作成なら「未作成」と書く>

<!-- machine: ここから下は PreCompact が上書きする。意味内容の予算に含めない -->
```
