# CHG-0033: 自作したサンドボックスに価値があったかを、サンクコストを除いて判定する

- **状態**: Exploring
- **更新日**: 2026-10-24
- **基準**: 現行の `pis`（Fence 0.1.67 + `ocs` + ハーネス + 子の worktree/Landlock）、コミット `d3a2da5`。比較の相手は、[記録 O1・O2](../research/agents/openshell-comparison.md) と [記録 C1](../research/agents/sandbox-alternatives-comparison.md) の時点（2026-10-24）の既製品

## 目的と非目的

**目的**: 今回自作したサンドボックス（`ocs`、`pis`、ハーネスの判定器とガードツール、子エージェントの worktree 隔離、各 CLI の hook の生成）に、**価値があったか**を、**エビデンスに基づいて、サンクコスト（過去に使った時間・費用・コード量）を除いて**判定する。結論は、次の 3 つのうち 1 つ: **維持**、**部分的に置き換える（既製品の仕組みを取り入れる・自作を縮める）**、**全面的に置き換える**。

**非目的**:

- 過去の支出を理由に、現行を正当化も否定もしない（サンクコスト）
- 既製品を、この案件の中で導入する・実装する（判定の後、必要なら別の案件にする）
- 「安全か」の絶対的な評価（独立した検証が無いものは、ベンダーの主張として扱う）

## 現在地

### 暫定の判定（段 P5）

**結論（暫定）: 部分的に置き換える（縮小）。全面的な置き換えは、証拠が支持しない。**

> **利用の偏り（利用者の訂正、2026-10-24）**: これまでのサンドボックスは使い勝手が悪く、**サンドボックスなしでの起動がほとんど**だった。この期間は `pi` 自体の作り込みに集中していたため、境界を張った状態での実運用が少ない。したがって、下の「事故を防いだ記録が無い」「実際に必要だった証拠が 4 件」は、**価値が無いという証拠ではなく、測定が成立していない**（利用が少ないと、止めた事故も誤検出も記録に残らない）。価値の判定のうち、**便益の側は保留**とし、費用の側（保守の量、二重保守）と、この環境の必須の条件を満たす既製品が無いことは、引き続き根拠にする。価値の測定は、使い勝手が改善し、他のプロジェクトで常用するようになってから（段 P6）。

1. **「今、ゼロから選ぶなら」（問い (a)）**: この環境の必須の条件は、WSL2 で動く・`pi` を包める・ホストの道具（`mise`・`uv`）をそのまま使える、の 3 つ。**今回調べた範囲の既製品に、3 つを同時に満たす記述は見つからなかった**（[記録 C1](../research/agents/sandbox-alternatives-comparison.md)）。OpenShell と Docker Sandboxes は、コンテナか VM のイメージが前提で、ホストの道具・pi・WSL2 の少なくとも 1 つが「原文に記述なし」または不利。nono は、pi を名指しで対応し、WSL2 でファイル制御は完全だが、資格情報の代理が WSL2 で既定では使えない。コマンドの内容を解析して拒否する層は、既製品に**見つからなかった**（探した範囲）。したがって、**「自作しなければ必須の条件を満たせなかった」可能性が高いが、「現行が最良」とまでは言えない**（動かした比較が無い。nono はファイル制御を小さく試す価値がある）
2. **「今から乗り換えるなら」（問い (b)）**: 全面的な置き換えを支持する証拠は無い。乗り換え先の候補が必須の条件を満たす記述が無く、動かして確かめてもいない。一方、**縮める余地には証拠がある**: 判定器の Python 版（約 4,975 行）と正解データ（約 33,317 行）は、[ADR-0017](../adr/0017-pi-only-and-ts-judge.md) が「TS 版との一致が確認できたら外す」と決めた**オラクル**で、撤去の記録は見つからなかった。この二重保守が実際に続いている（直近 2 週間の Python 版に触れる 8 コミットのうち 6 件が TS 版と同時。今日の CHG-0032 もそう）
3. **価値の有無の答え**（問い「自作に価値があったか」）:
   - **証明されたこと**: (i) 必須の条件を同時に満たす既製品が、探した範囲に無い。(ii) 実機で、内側に漏れていた資格情報の環境変数（`ORCA_AGENT_HOOK_TOKEN`）を見つけて直した（自作の起動時の検査があったから）。(iii) 作業ツリー内の秘密の伏字化が、実履歴で秘密を止めた記録がある（OpenCode 時代の記録）
   - **証明されていないこと**: 15 件の要件のうち、実際に必要だった証拠があるのは 4 件だけ。**実際に事故を防いだ記録は見つからなかった**。判定器の限界価値（境界だけで足りたか）、子の隔離の需要は、動作確認のみで、事故の記録が無い
   - **否定されたこと**: 「作り込みは落ち着く」という見立て。直近 4 週は週約 60 コミットで、fix が 63 件
4. **覆る条件**: (a) nono をこの環境で試して、ファイル制御・`pi` の包み・ホストの道具が現行の境界と同等で、`ocs` の保守（約 2,266 行、直近 2 週間で 13 コミット）を置き換えられると実測できたら、境界の層を nono へ置き換える。(b) コマンド内容の解析層を持つ既製品が見つかったら、判定器の置き換えを再検討する。(c) WSL2 の中で動く、資格情報の代理を持つ既製品が見つかったら、「資格情報が内側から読める」例外を解消する。(d) 判定器が、境界だけで足りることが実測できたら（判定器を外しても、実履歴の秘密・破壊の検知が変わらない）、判定器の縮小・撤去

### 調べて分かったこと

[記録 O1・O2](../research/agents/openshell-comparison.md)・[記録 C1](../research/agents/sandbox-alternatives-comparison.md)（どれも動かしていない。原文の抜き書き）:

- OpenShell は、判定する側を境界の外に置き、資格情報をエージェントに渡さず、ネットワークを実行ファイル単位・API 単位で縛り、方針の変更を形式検証する、という設計を**文書の上では**持つ。実行環境はコンテナか VM。WSL2 は experimental で、実際の不具合報告がある。2026-08 に重大な脆弱性が 2 件公表されたが、影響を受けるのは 0.0.33 以前で、現行は 0.1.5（修正済みの記述は NVIDIA の JSON に無く、影響範囲からの推測）。pi は名指しされていない（任意のエージェントの持ち込みは可）
- Docker Sandboxes は、Windows ネイティブで動き、資格情報をネットワーク境界で注入し、ブランチごとの worktree を作る。「experimental」で、WSL2 の中で動かす記述と pi の記述が無く、導入記事の著者は性能の低下とコミット署名を課題に挙げる
- nono は、pi を名指しで対応する。WSL2 では Landlock のファイル制御は完全だが、資格情報の代理は既定で拒否される（WSL2 の init が seccomp の通知リスナーを占有するため）
- 比較記事（第三者）は、現行で使っている Fence も、OpenShell・nono・srt と並べている。Fence は pre-1.0 で、強い隔離境界を意図しない、と述べる

### 現行について分かっていること

リポジトリのファイルで確かめたもの:

- 目的は「エージェントのうっかり（外部への誤送信、ワークスペース外の破壊、秘密の誤読）を止める」こと。精査していないリポジトリを安全に開くことまでは求めない（[ADR-0012](../adr/0012-ocs-boundary-for-accidents.md)）
- `pis` は、pi の認証ファイルなどを、境界用の agent 置き場へ写して使う（`home/dot_local/share/ocs/pi.py` の `COPY_FILES`）。**資格情報は境界の内側から読める**。保護対象のパスの読み取り拒否で守っている
- ガード（判定器・ハーネス）は、エージェントと同じサンドボックスの内側で動き、境界が効いているかを起動時のカナリアで確かめる（[pi-guard](../spec/guard/pi-guard.md)）
- ホストの道具をそのまま使える。WSL2 で動く。GPU は `devices.allow` で通せる（[CHG-0029](0029-worktree-isolation.md)）

`explore` の子が、ADR・仕様・案件から、**文書に記述のある 15 件**を抜き出した。親が確かめたのは代表の要件。実際に必要だった証拠があるのは、次の 4 件:

| 要件 | 実際に必要だった証拠 | 満たす層 |

| 秘密の誤読の防止 | 実履歴（OpenCode 時代）の 1,031 呼び出しのうち秘密に触れた 15 件を、3 層が全件受け止めた（`docs/research/opencode/permission/stage2-coverage.md`）。出力に載ったのは 4 件 | Fence + `ocs` + 判定器 |

## 評価基準

**判定の原則**（利用者の指示、2026-10-23）:

1. **サンクコストを判断に使わない。** 過去に使った時間・費用・コード量は、理由にしない。比べるのは「今から先」の費用と便益
2. **過去の実測は、将来の予測の証拠として使ってよい。** 保守の頻度、事故の件数、試験の量、使えた機能は、サンクコストではなく、将来の費用と便益を見積もるための観測
3. **2 つの問いを分けて答える。** (a)「今、ゼロから選ぶなら、何を選ぶか」、(b)「今から乗り換えるなら、何が得で、何を失うか（乗り換えの費用を含む）」。(a) だけで判定しない
4. **エビデンスの種類を区別する。** 実測・一次情報（公式 docs・issues・NVD）・第三者の評価・ベンダーの主張。根拠が無い判断は「不明」と書き、推測で埋めない
5. **結論は、維持 / 部分的に置き換え / 全面的に置き換え のうち 1 つ。覆る条件を書く**

**決定規則**（段 P5）: 必須の要件をすべて満たす候補のうち、将来の費用（保守 + 運用 + 乗り換え）が最小のものを選ぶ。必須の要件を満たす既製品が無ければ、現行を維持し、既製品の仕組みで取り入れられるもの、自作を縮められるものを、別の案件にする。今回は、必須の要件（WSL2・pi・ホストの道具）を同時に満たす既製品が見つからなかったので、この規則の後半に当たる（結論は「現在地」の「暫定の判定」）。
