# Presentation Structure

参考: 田崎晴明「発表スライドについての基本的なルール」
<https://haltasaki.github.io/writings/html/slides.html>

## Long-form talks

15分以上、または構成が単純でない発表は次を基本形とする。

1. **タイトル**
2. **目次**
3. 本文
4. **まとめ**

## Title slide

- 1枚目は必ずタイトルスライド。
- タイトルは内容を簡潔に表す名称にする。statement、問題提起、結論文を主タイトルにしない。
- 主タイトルをページ内で最も大きくする。
- statement や対象読者への約束は副題にする。
- 発表者名・所属が分かる場合は明記する。推測で作らない。

例:

```text
RAGからAgentic RAGまで
AIコーディング経験者のためのLLMシステム入門
```

## Agenda

- 長い発表では全体を3〜5パートへ分ける。
- 目次は短く見せ、まだ説明していない詳細を読み上げない。
- 本文のセクション名と同じ言葉・順序を使う。
- 必要なら章の切替時に現在地だけを再表示する。
- 長い発表では、章ラベル、目次再掲、進捗表示、`05 / 21`形式のページ番号などを
  組み合わせ、聴衆が現在位置と残りを把握できるようにする。

## Body slide headings

- 原則として上部に、そのページの内容を示す簡潔な表題を置く。
- 一枚に複数の独立テーマを詰めない。
- 1枚1メッセージであり、1枚1分ではない。枚数ではなくリハーサルで時間を決める。
- 表題を作れないページは、分割・統合・削除を検討する。

## Final summary

- 最後は必ず「まとめ」スライドを表示する。
- 聴衆が全体像を思い出せる3〜5項目にする。
- 目次と同じ大分類へ対応させる。
- 次の行動やリンクはまとめの一部に置けるが、行動要請だけのページを最後にしない。
- 時間が不足した場合でも、まとめを表示して終える。
- 出典・ライセンス・補足資料を本編後へ置く場合は appendix と明示し、
  本編の最後と発表時に最後に表示するページはまとめにする。

## Audience level

- audience だけでなく、既知とみなす概念、スライド上で説明する用語、
  許容する実装詳細、扱わない詳細を計画に記録する。
- 初心者向けでは全体像と語彙を優先し、熟練者向けでは設定・制約・例外を増やす。
- 形式的な謝辞や組織紹介の独立ページは既定で作らない。
- 再現性・帰属に必要な貢献やクレジットは、本文またはまとめ下部で簡潔に示す。
