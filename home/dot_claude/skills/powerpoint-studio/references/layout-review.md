# Whole-deck Layout Review

「崩れていない」と「読みやすい」を別々に確認する。重なり検査に通っても、
表の列見出しが本文からずれたり、広いカード内の重要語が小さすぎたりすることがある。

## Preserve before improving

現在のPDF・PPTX・生成ソース・レンダーを保存する。承認されたページや図、内容の順序、
出典、リンク、持ち時間、背景・書体・ページ番号は維持対象として扱う。
良いページまで同じ構図へ作り替えない。改訂範囲とスキルへ戻す一般則を分ける。

## Inspect two scales

1. モンタージュで、主役の大きさ、密度、構図の反復、全体の読み順を確認する。
2. 全ページを原寸で見て、各ページを「維持」「局所調整」「再配置」に分類する。
3. 目次、比較、表、階層図など、それぞれの読解目的から具体的な変更を決める。
4. 機械的に判定できる不変条件は宣言して検査する。余白の美しさや構図の好みを
   恣意的な一律の数値で合格にしない。

### Agenda and short rows

長い章名と長い進行説明を左右の細い列へ押し込まない。横幅が不足するなら
章名を上段、進行・範囲を下段へ置き、番号は両者のまとまりを示す位置へ揃える。
目次を読むために細かな進行文字を解読しなければならない構成を避ける。

### Comparison cards

同列カードでは名前、図、説明、状態の段位置を合わせる。
名前は比較対象を識別する主要情報である。長い名前だけを縮小せず、
Part番号と技法名を別行にするなど、意味に沿った折り返しを使う。
小さな入れ子枠やバッジが主要語より目立つ場合は、囲みを減らすか役割を整理する。

### Tables and matrices

列ごとに一つのアンカーを持ち、ヘッダーと全行で共有する。
テキストの左端を揃える列、数値の右端を揃える列、状態記号を中央に置く列を区別する。
背景のカード境界が揃っているだけでは、列が正しく見えるとは限らない。

### Role explanations and metric groups

概念名とその説明を狭い横並びにするより、見出しの下に説明を置く方が読みやすい場合がある。
同様に、指標群のラベルと指標リストを左右へ詰めず、上段の群名と下段のリストへ整理する。
下段のリストは、行数が違っても読み始めを揃える。
文字箱のy座標だけでなく、縦方向の揃えも`top`へ明示する。同じ高さの箱を
中央揃えにすると、2行と3行のリストでは先頭行がずれる。y座標を目分量で
ずらす対症療法ではなく、揃える基準を一致させる。

### Figures and screenshots

既に読める図を、他ページとの見た目の一致だけを理由に拡大・再配線しない。
引用原図やスクリーンショットの文字を勝手に書き換えない。読ませる箇所を特定し、
必要ならクロップ・パネル分割を選ぶが、原図の意味や証拠を失わせない。
図内部の配線・文字検査は `diagram-geometry.md` の契約を維持する。

## Opt-in regression checks

実際に確認した整列や主要語の下限を `deck-plan.json` の `meta.layout_checks` に宣言する。
これはデッキ固有の不変条件であり、全デッキに適用する固定フォントサイズではない。

```json
{
  "layout_checks": [
    {
      "slide": 3,
      "kind": "alignment",
      "shapes": ["table-method-header", "table-method-cell"],
      "axis": "left",
      "tolerance_inches": 0.03
    },
    {
      "slide": 4,
      "kind": "font-size",
      "shapes": ["comparison-method-name"],
      "minimum_pt": 14,
      "require_no_autofit": true
    },
    {
      "slide": 5,
      "kind": "alignment",
      "shapes": ["retrieval-list", "generation-list"],
      "axis": "top",
      "tolerance_inches": 0.01,
      "text_anchor": "top"
    }
  ]
}
```

同名のshapeは全て検査する。例えば`table-method-cell`を複数行に付けると、
ヘッダーと全行の左端を一緒に確認できる。列挙した名前が見つからない場合は失敗とし、
名前変更によって検査対象が黙って消えないようにする。
整列の対象はshapeの枠のアンカーで、字面そのものではない。対応する文字箱は
内側marginと段落の揃え方も合わせる。グループ内や回転した整列対象は、
座標を誤って比較しないよう未対応として報告される。
先頭行を揃えるリストでは`text_anchor: "top"`も指定し、文字箱の縦揃えを
明示的に検査する。未設定の継承値は推測せず報告する。`middle`、`bottom`も指定できるが、
行数の違うリストの先頭行を揃える用途には使わない。

`font-size`は文字runのサイズと明示された縮小率を確認する。
`require_no_autofit`は、重要語がレンダラーで後から縮む設定を拒否するための任意指定。
フォント名、色、サイズ帯は既存のtypography/style policyで引き続き検査する。
最終表示の可読性は原寸レビューで判断し、格納ptだけから推定しない。

```bash
uv run scripts/audit_layout_groups.py deck.pptx \
  --plan deck-plan.json --output layout-groups-report.json
```

`validate_deck.py`にも組み込まれる。未宣言なら従来デッキの挙動は変えない。

## Close the loop

修正後に全ページを再生成し、変更ページを独立レビューへ渡す。
維持したページ・図は可能なら旧PDFとの画素比較で確認する。
意味を変えない改行・整列の修正でも、ページ数、出典リンク、ノートと時間、
PPTX/PDFの描画一致、レポートの鮮度を再確認する。

今回得た一般則だけを該当するスキル節へ戻す。個別ページの座標をそのまま
永続的な「正解」として保存せず、どの条件でその配置が有効かを残す。
