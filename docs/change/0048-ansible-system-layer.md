- **更新日**: 2026-10-29

## 目的と非目的

**目的**: `home/.chezmoiscripts/100_linux/` の、sudo を使う処理（apt の導入・`/etc` の設定・サービス・apt の鍵とソース・`chsh`）を、Ansible に移すと、**保守しやすくなるか**を、実際に移行して測って決める。
判断の軸は、実装の費用（エージェントが担う）ではなく、**長く保守する費用**（手書きの冪等性・正しさの担保・ツールの更新による破損・構成要素の数・試験）。

**非目的**: Windows・macOS・ユーザ領域の設定（chezmoi・mise・uv のまま）。IaC ツール全面の導入（調査で、価値が無いと判断。[調査記録](../research/chezmoi/ansible-for-sudo-scripts.md) 7 節）。

## 現在地

- 調査記録の結論: **Linux のシステム層だけ Ansible の価値がある（条件付き）**。全体への導入の価値は無い。決め手は、自作の IaC もどきを保守せず、apt のロックや鍵・サービスの端の事例を module に任せられること。代償は、更新による破損と構成要素の増加
- このリポジトリの保守の実績（`git log`）: `.chezmoiscripts/` は 3260 行・171 コミット・`fix` 68。`fix` の中身は、プラットフォームの癖が多く、冪等性・安全性の不足が次
- sudo の扱い: Linux にキープアライブが無い（macOS にだけある）。Ansible なら、始めに 1 回の `become` のパスワードで足りる。**それだけを楽にするなら、キープアライブのテンプレートを Linux にも使う方が安い**（調査記録の 5 節）
- **試作（段 2）**: `worker` の子（job-2bff43bbf7cb8966）に、作業場所 `.tmp/ansible-trial/`（`src/` に元のスクリプトの複製）で、playbook の作成と Docker での測定を依頼中。最初の起動（worktree 隔離）は、**隔離の子が実モデルの認証のロックを書けず、2 秒で失敗**した（[CHG-0029](0029-worktree-isolation.md) の未解決点に記録）。隔離なしで起動し直した

## 評価基準

**撤退する条件（どれか）**:

- 手書きの冪等性の検査が、実際には減らない（`command` の `changed_when` などの回避策が、同じくらい要る）
- `--check` が実用にならない
- 固定した版を上げたときの手直しが大きい（major と collection の更新で、直すものが多い）
- Raspberry Pi で、実行の時間と容量が許容できない

**続ける条件**: 上のどれにも当たらず、行数と読みやすさが良くなり、2 回目が `changed=0` になる。
