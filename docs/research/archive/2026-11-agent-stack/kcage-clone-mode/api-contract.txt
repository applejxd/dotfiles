## 1. 用語と前提

| 用語 | 意味 |
| --- | --- |
| repo 集合 | 親 1 つ（`rel="."`）と、その下に入れ子で置かれた独立した子 repo（submodule ではなく、ポインタも無い）。許可表の `path`（ホストの親 repo）が根 |
| rel | 根からの相対パス。親は `"."`。検証は §2 の `policy.validate_rel` |
| 主 clone | 箱の `<workdir>/<rel>`。箱専用の clone で、常に develop をチェックアウトする |
| ワークスペース | feature ごとの worktree の束。箱の `<workdir>/.tmp/worktrees/<名>/<rel>`（親は `<名>` 直下）。枝は全 repo で `feature/<名>` |
| inbox | ホスト側の bare repo（repo ごとに 1 つ）と `manifest.json`。置き場は `StatePaths`（`~/.local/share/kcage/inbox/<id>/`） |
| manifest | ホストだけが書く正本（§4.1）。repo 集合・seed 時の配置・箱と共有済みの oid を持つ |
| seed | ホスト→箱。初回に全 repo の bundle を送り、箱で clone を再現する（`kcage up` が自動で行う） |
| collect | 箱→inbox。箱の枝を bundle で受け、検査してから inbox の ref を更新する（`pi` 終了時・`stop` 前・`rm` 前に自動） |
| take | inbox→ホストの repo。`refs/heads/<枝>` を CAS で更新する（FF のみ） |
| feed | ホスト→箱。develop・main・ホストの枝を bundle で渡す（FF のみ） |
| wip | 未コミットの作業ツリーを一時 index から commit にし、`host-wip/<日時>`・`box-wip/<日時>` の枝として渡す。適用はしない |
| view | 箱の作業ツリーの読み取り専用の複製を、ホストの専用ディレクトリへ出す（`.git` と自動実行される設定は除く） |
| adopt | 箱で作られた新しい子 repo を、利用者の明示でホストの管理下へ入れる（D20） |

- **信頼の向き**
  - ホストは信頼する。箱は信頼しない。箱が書いたものは、ホストの git を含めて、検査を通るまで解釈しない。
  - 箱の helper（`kcage-box`）の出力も、箱由来のデータとして扱う。ホストは JSON を厳格に検査してから使う。
- 箱の clone の `.git` は箱のもの。ホストの `.git` は箱に見えない。
- root 側の新しい権限は無い（§8）。

## 2. 許可表と `kcage.toml` の項目（締める方向だけ）

### 2.1 許可表 `[repo.<id>]` の追加キー（`policy.py`）

| キー | 型 | 既定 | 検証 |
| --- | --- | --- | --- |
| `git` | `"shared"` \| `"clone"` | `"shared"` | それ以外は `PolicyError` |
| `workdir` | `"auto"` \| `"host"` | `"auto"` | `"host"` は `git = "clone"` のときだけ。`shared` と併用したら `PolicyError` |
| `max_repos` | 整数 | 16 | 1〜64（親を含む） |
| `seed_max_mib` | 整数 | 4096 | 64〜65536（全 repo の bundle の合計） |
| `repo_allow` | 文字列の配列 | `[]`（全許可） | 最大 64 件、各 200 字以下。成分は `[A-Za-z0-9._*-]+`、`**` は最後の成分だけ |

- `"."`（親）は `repo_allow` に関係なく常に許可する。
- `_REPO_KEYS` に 5 キーを足す。
- v1 では `kcage register` にフラグを足さない。許可表は手編集し、`render_repo_block` は変えない。

### 2.2 `kcage.toml` の追加キー（`config.py`）

- `repos = ["src/foo", ...]`（任意）。**探索の代わりに宣言する**。
  - 省略は「探索の結果」。`repos = []` は「親だけ」。
  - 子の rel だけを書く（`"."` は不可）。最大 64 件、重複不可。各要素は `validate_rel`。
- `_SPEC_KEYS` に `"repos"` を足す。**root もこの集合を使う**ので、足さないと `kcage up` が未知のキーで拒否される。
- `resolve` が次を検査する。違反は `ConfigError`。
  - `spec.repos` が非 `None` なのに `rp.git != "clone"`。
  - `1 + len(spec.repos) > rp.max_repos`。
  - どれかの rel が `repo_allowed` に当たらない。

### 2.3 root 側と CLI 側で解釈が一致する置き場（署名）

## 5. `scripts/kcage/gitsync/` の公開 API

依存の向き（循環なし）:

```text
gitrun(層0) ← repos(1) ← inbox(2) ← seed(3) ←─┐
gitrun ← wip(3)  ← repos ─────────────────────┤← sync(4) ← commands(5) ← cli
gitrun ← view(3。危険名の正本)                 ┘
```

- `sync` は `inbox`・`seed`・`wip`・`view`・`repos` を import してよい。逆は不可。
- `commands` だけが `kcage.cli` を import する。`cli` は `commands` を遅延 import する。

**`take` の規則（事前検査。repo ごと）**

| 状況 | 結果 |
| --- | --- |
| その repo に枝が無い、または空 | `skipped`（検査には影響しない） |
| ホストに同名の枝が無い | 作成（CAS の旧値はゼロ oid）。`--as` なら別名 |
| ホストに同名があり、新しいほうが子孫（FF） | 更新（CAS） |
| ホストに同名があり、同じ | `unchanged` |
| 非 FF、またはホストの worktree でチェックアウト中（develop 以外） | `refused`。`--as` で別名にできる |
| 枝が `develop`: どの worktree もチェックアウトしていない | `update-ref`（CAS） |
| `develop`: チェックアウト中で、追跡ファイルが clean | その worktree で `merge --ff-only --no-overwrite-ignore --no-edit`（`advanceTarget` と同じ規則） |
| `develop`: チェックアウト中で、追跡ファイルに変更あり | `refused`（変更ファイルを表示） |
| `develop` の差分に `risk_globs`・`is_autoexec_path` の一致がある（または `risk_globs is None`） | `accept_risk_paths=True` が無ければ `refused`（一致の一覧を出す） |

- `take` が適用するのは `refs/heads/*` の CAS か、上の FF の merge だけ。それ以外の書き込みは無い（H3・H4）。
- `adopt` の規則（D20）:
  - `rel` が `validate_child_rel`・`repo_allowed`・`max_repos` を満たすこと。
  - ホストに無いか、空のディレクトリであること（symlink が途中に無い）。
  - 箱の `scan-new-repos` が報告した rel であること。
  - 通ったら、ホストが `git init -b develop --template=` で作る。ホストの作業ツリーへは何も書かない。
  - その後 inbox を作って manifest に足し、その repo だけ collect する。
  - 「親の `.gitignore` への追記・`setup.sh` への反映は利用者の作業」というヒントを出す。

## 6. `scripts/kcage/boxtool/kcage_box.py`（箱の中の単一ファイル helper）

- 配置: seed が `<box_home>/.kcage/bin/kcage-box`（0755、uid 1000）へ置く。
  - 実行は `python3 <helper> <verb> ...`。箱の PATH に載せる stub は v1 では不要。
  - 箱の AI は絶対パスで呼ぶ。
- 前提: 箱の `python3` は 3.10 以上、`git` は 2.38 以上（`merge-tree --write-tree` 用）。標準ライブラリのみ。`kcage` を import しない。
- 箱が書き換えうるので、**ホストは出力を信頼せず検査する**。`version` の `helper` が契約の版（1）と違えば、ホストが置き直す。
- 標準出力:
  - 人向けは表（1 行 1 件、タブ区切り）。
  - 機械向けは `--json`（§4.5）。
  - `bundle`・`export` は標準出力がバイナリ。
  - 診断は標準エラー（1 行 1 理由）。拒否は `REFUSED <rel>: <理由>`。
- 終了コード: §0 と同じ（3 は何も変更していない）。

| 動詞 | 引数 | 動作 |
| --- | --- | --- |
| `version` | `[--json]` | helper・git・python の版 |
| `layout` | `[--json] [--verify]` | `layout.json` を出す。`--verify` は各 repo の `.git` が実ディレクトリ・`rev-parse --absolute-git-dir` が自身・`core.worktree` なし・`objects/info/alternates` なし・remote なし・`.git/config` にホストのパスなし、を確かめ、余分な `.git` も出す |
| `seed-apply` | `--dir DIR` | plan を読み、sha256 を照合し、`git init --template=` → `fetch '+refs/heads/*:refs/heads/*' --update-head-ok` → `checkout -f` → `info/exclude` を書く。`seeding`→`seeded` の印と `layout.json` を書く。印が無いのに workdir が空でなければ、他人のデータとみなして拒否（3）。`seeding` だけが残っていれば workdir の中身を消してやり直す |
| `refs` | `[--json]` | 全 repo の枝先・HEAD・dirty・shallow |
| `bundle` | `--rel R --ref PATTERN... --known OID...` | 標準出力に bundle。`known` のうち箱に実在する oid だけを `--not` にする。変化なしなら空出力で終了コード 0 |
| `feed-apply` | `--dir DIR [--json]` | bundle を `refs/kcage/host/*` へ fetch。develop・main・master は、祖先関係なら FF（チェックアウト中かつ clean は `merge --ff-only`、他の worktree でチェックアウト中は `checked-out`、それ以外は `update-ref`）。祖先でなければ `diverged`（ref を残す）。`host-wip/*` とホストの枝は新規作成のみ、既存は FF のみ |
| `snapshot` | `--stamp S [--ws N] [--rel R]... [--json]` | 未コミットを一時 index から commit にし、`box-wip/<S>` を作る。ignore と入れ子の repo は除く。上限は §5.5 と同じ |
| `scan-new-repos` | `[--json]` | layout に無い `.git`（実ディレクトリ）を報告 |
| `export` | `[--ws N]` | 作業ツリー（親と子）の tar を標準出力へ。`.git` と `HOST_AUTOEXEC_NAMES` に当たるものは入れない。ホストはもう一度検査する |
| `ws start` | `NAME [--from BRANCH] [--only REL,...]` | §下 |
| `ws ls` / `ws status` | `[NAME] [--json]` | 一覧、repo ごとの枝・ahead・dirty。`gone`（git flow などで worktree が消えた）も検出 |
| `ws path` | `NAME` | ワークスペースの絶対パスを 1 行 |
| `ws update` | `NAME` | 各 worktree で `git merge develop`。衝突は停止して 3（repo とファイルを出す） |
| `ws merge` | `NAME FEATURE... [--continue]` | その `feature/<f>` を持つ repo だけ `--no-ff` で merge（bundle の代わり）。衝突は 3 |
| `ws finish` | `NAME [-M MSG] [--dry-run]` | 経路 B。子→親の順。主 clone が develop で clean であることと、`merge-tree --write-tree` で全 repo の衝突を事前検査し、1 つでも衝突なら何も変更せず 3。通れば `merge --no-ff` を適用し、worktree と枝を片付ける。途中の失敗では済んだ repo の merge が残る（reflog で戻せる。原子的ではない） |
| `ws rm` | `NAME [--force]` | 追跡ファイルの変更・未追跡があれば 3。無視ファイルだけなら worktree ごと消す。枝は `branch -d`（未統合は `--force` が無ければ残す） |
| `ws join` | `NAME REL` | detached の子に `feature/<NAME>` を切って参加させる |

- **`ws start`**
  - 事前検査: `<ws>` が無い。`<ws>/<rel>` が空き（親が追跡している同名のパスは衝突）。枝が他の worktree にチェックアウトされていない。
  - 基点: `--from F` があればそれ。無ければ `.gitflow` の `startPoint`、さらに無ければ develop→main→master。
  - 作成: 親から順に `git worktree add [-b feature/NAME] <path> <基点>`。
  - 既存の `feature/NAME` は attach する。
  - `--only` に無い repo は `--detach`。
  - 失敗したら、この実行で作ったものだけを巻き戻す。
- **git flow との関係（D19）**
  - `ws` は git flow に依存せず、`git worktree add` を直接使う。単一 repo のワークスペースは `.gitflow` の `worktreePath`（`.tmp/worktrees/<名>`）と同じ位置なので、`git flow feature start --worktree` で作ったものを `ws ls` が認識する。
  - 箱では `git flow` をそのまま使える（箱の `.git/config` は箱のもの）。
  - 箱への git-flow-next の導入は §8 の `template.py`。

## 7. `cli.py` の新動詞と旗

全て共通旗 `--repo ID`（箱の id）を受ける。`--repo` と区別するため、repo 集合の中の絞り込みは **`--rel REL`**（繰り返し可）にする。`git = "shared"` の repo では、新動詞は終了コード 2「git = clone のときだけ使える」で終わる。

| 動詞 | 旗 | 出力 |
| --- | --- | --- |
| `kcage seed` | `[--branch B]... [--dry-run] [--json]` | `SeedPlan` の要約か `SyncReport` |
| `kcage repos` | `[--json]` | repo 集合（探索か宣言か）、manifest との差分（増えた・消えた）、`skipped`。箱が止まっていても動く（ホストのみ） |
| `kcage collect` | `[--wip] [--ws NAME] [--rel REL]... [--json]` | `SyncReport`（`--ws` は `--wip` と一緒のときだけ） |
| `kcage take BRANCH` | `[--rel REL]... [--as BRANCH2] [--partial] [--accept-risk-paths] [--dry-run] [--json]` | `SyncReport`。**BRANCH は最初の引数**で、違えば終了コード 2（`[pi.confirm]` の前方一致 `kcage take develop` を旗の順で回避させないため） |
| `kcage feed` | `[--branch B]... [--rel REL]... [--wip] [--dry-run] [--json]` | `SyncReport` |
| `kcage view` | `[--ws NAME] [--path-only]` | 展開した view のパスと `ExtractReport` の要約 |
| `kcage ws VERB ...` | 箱の helper の `ws` 動詞へ透過（`VERB` が §6 の `ws` 動詞でなければ 2） | 箱の標準出力・標準エラーと終了コードをそのまま返す |
| `kcage adopt REL` | `[--dry-run]` | `SyncReport`。人だけの動詞（§8 の S1g で `[bash] deny`） |

**自動で呼ぶ点（`git = "clone"` のときだけ。`policy.parse` が読めない・shared なら何もしない）**

- `kcage up`: kcage-root の `up` が成功した後、`is_seeded` が偽なら `seed`。
  - 失敗したら、箱は起動したまま終了コード 1 にして「kcage seed で再実行」と案内する。
- `kcage pi`: pi の終了後に `auto_collect(reason="pi")`。終了コードは pi のものを返す。
  - collect の失敗は警告だけ。別の操作がロック中なら黙って飛ばす。
- `kcage stop`: 停止の前に `auto_collect(reason="stop")`。失敗しても停止は続ける。
- `kcage rm`: 削除の前に collect。失敗したら中止して 3。`--no-collect` で省略できる（既定の追補。§12）。

**`doctor`（clone 版）**: ホストの `.git` の検査（`check_git_config`・`check_git_metadata`）を、次に差し替える（`Check` は `(name, status, detail)`）。

| 名前 | fail | warn | ok |
| --- | --- | --- | --- |
| git モード | 許可表を解釈できない | — | `clone（workdir=…）` |
| repo 集合 | 上限超え（`LimitExceeded`）・宣言が実在しない | 探索と宣言の差、manifest との差（再 seed が要る） | N 件（探索か宣言か） |
| repo の形 | 浅い・partial の repo がある | `.gitmodules` を持つ子 | なし |
| inbox | manifest が読めない・version 違い・`check_inbox_config` に食い違い | — | 一致 |
| seed 状態（箱が起動中のみ） | — | 未 seed・新しい `.git`（`scan-new-repos`） | seeded |

**`selftest`（clone 版）**: `selftest_commands` の `git` 検査（`GIT_RO_PATHS`）を差し替え、home・env・direct は残す。

| 名前 | 内容（pass の条件） |
| --- | --- |
| 箱にホストの repo が無い | `/proc/self/mountinfo` に、workdir・`.git`・ホストの repo のパスの mount が無い。`/mnt/?` が空 |
| 箱専用の .git | `layout --verify` の全 repo が ok |
| 余分な .git | `extra_git` が空（あれば warn。collect が新しい repo として報告する） |
| helper の完全性 | 箱の helper の sha256 がホストの `helper_source()` と一致（不一致は warn） |

- 悪性 bundle・tar の拒否は、ホストの試験（`test/kcage/`）と S0 の実機確認で確かめる。実行時の selftest には入れない。

## 8. root 側の変更の最小の範囲

root 側に新しい権限・動詞・sudoers の行は**増えない**。clone の操作は全て、既存の passwordless の `exec` 動詞経由。`PASSWORDLESS`・`VERBS`・`sudoers_snippet` は無変更。

- **`config.py`**
  - `_SPEC_KEYS` に `repos`。`parse_spec` と `resolve` の検査は §2.2 のとおり。

- **配備**: `kcage-root` が import する `policy`・`model`・`config`・`plan`・`root_helper` を変えるので、**`kcage setup --update` が要る**。
  - `scripts/kcage` は丸ごと複製される（`setup.py` の `cp -r`）ので、`gitsync/`・`boxtool/` も root の配備に入る。root は import しないので無害。
- **`template.py`（D19。S1 の別担当・任意の導入）**
  - `GITFLOW_NEXT_VERSION` と `GITFLOW_NEXT_SHA256` の定数を足す。
  - 版と sha256 は、実装の担当が公式リリースから確認して書く。確認できなければ `None` のままにし、導入の手順を飛ばす。
  - 反映には `kcage template` と箱の作り直しが要る。
- **S1g（親だけ。権限の境界を動かすので実装の前に `review`）**
  - `home/dot_config/agents/common.toml.tmpl` の `[pi.confirm] bash` に `"kcage take develop"`・`"kcage take main"`・`"kcage take master"`・`"kcage ws finish"` を足す。

## 10. 試験の方針

実 git を使う一時リポジトリと、`LocalBox`（箱を一時ディレクトリで模す）を共有ヘルパーにする。`incus` は使わない。

```python
# test/kcage/gitsync_fixtures.py（pytest は収集しない名前）
def git(cwd: Path, *args: str, input: bytes | None = None, env: Mapping[str, str] | None = None) -> str: ...
    # 実 git。固定の identity・GIT_CONFIG_GLOBAL=/dev/null。git 2.38 未満なら merge-tree 系の試験は skip
def make_repo(path: Path, files: Mapping[str, str | bytes] | None = None, *, branch: str = "develop",
              extra_branches: Sequence[str] = ()) -> Path: ...
def commit_file(repo: Path, rel: str, content: str | bytes, msg: str = "c", *, branch: str | None = None) -> str: ...  # oid
def make_monorepo(root: Path, children: Sequence[str] = ("src/c1", "src/c2"),
                  grandchildren: Sequence[str] = ("src/c1/vendor/g1",), *, ignore_children: bool = True) -> Path: ...

class LocalBox:                                      # BoxExec の実装。argv を実際に実行する（HOME=home、cwd=home、PATH は継承）
    def __init__(self, root: Path, *, workdir: Path | None = None, fail_on: Mapping[str, int] | None = None) -> None: ...
    home: Path; workdir: Path; calls: list[tuple[str, ...]]
    def __call__(self, argv: Sequence[str], *, stdin=None, stdout_path=None, max_bytes: int = 4 << 20, timeout: float = 60.0) -> ExecResult: ...

def make_env(tmp: Path, box: BoxExec | None = None, *, now: datetime | None = None, nonce: str = "n0") -> SyncEnv: ...
    # StatePaths(tmp/"state")・HostGit(home=tmp/"hhome")・box_home=LocalBox の home。now と nonce は固定
def make_cfg(workdir: Path, *, repos: Sequence[str] | None = None, max_repos: int = 16, repo_allow: Sequence[str] = ()) -> BoxConfig: ...
def seeded_box(tmp: Path, *, children: Sequence[str] = ("src/c1", "src/c2")) -> tuple[SyncEnv, BoxConfig, Path, Manifest]: ...

EVIL_BUNDLES = ("dotgit-tree", "dotgit-case", "dotgit-trailing-space", "dotgit-ntfs", "gitmodules-symlink", "gitlink",
                "bad-ref-dotdot", "bad-ref-dash", "bad-ref-ctrl", "unexpected-ref", "prereq-missing", "corrupt-pack",
                "oversize", "child-path-touch")
def evil_bundle(tmp: Path, kind: str, *, base: Path | None = None) -> Path: ...   # git hash-object -w -t tree --literally 等で作る
EVIL_TARS = ("abs", "dotdot", "symlink", "hardlink", "device", "fifo", "dotgit-deep", "dotgit-case", "setuid",
             "oversize-file", "too-many", "nul-name", "long-name", "autoexec-name")
def evil_tar(tmp: Path, kind: str) -> Path: ...
```

- **悪性データ**: 各 kind が、期待する `Rejected.code`（`REJECT_CODES`）で拒否されること。**1 つでも受理したら失敗**（撤退条件）。拒否した後、inbox の ref とホストの `.git` に変化が無いことも検査する。
- **`test_gitsync_invariants.py`（H1・H2 の機械検査）**:
  - `gitsync/` で `subprocess` を import するのが `gitrun.py` だけであること。
  - `shell=True` が無いこと。
  - `HostGit` を通さずに `"git"` を spawn していないこと。
- **試験の単位**
  - `gitrun`: `run_bytes` の上限・時間超過・`HostGit` の環境と先頭引数。
  - `repos`: 探索・宣言・上限・symlink・入れ子・submodule。
  - `inbox`: 受理・拒否・fsck。
  - `seed`・`sync`・`wip`: `LocalBox` で往復。
    - `take` の表（FF・非 FF・同名・チェックアウト中・develop の clean/dirty・risk）。
    - `wip` は未追跡・削除・リネーム・実行ビット・ignore・秘密・子の除外。
  - `view`: 悪性 tar。
  - `boxtool`: 各動詞（実 git の一時 repo）。
  - `commands`: argparse の引数と終了コード。
- **実機の確認（S0。導入済みの箱に `kcage exec` だけ）**:
  - `incus exec` の標準入出力がバイナリを壊さないか（sha256）。
  - 箱の `python3`・git の版。
  - seed の所要時間。
  - ワークスペースの入れ子の worktree。
  - 実 box での悪性 bundle の拒否。
  - これは契約の外で、親が手順を作る。

## 11. 既定で無効の旗

`git = "shared"` が既定で、clone は**許可表で明示したときだけ**（C3）。無効のとき、既存の挙動を一切変えない。

- 変えない箇所（確認方法つき）:
  - `config.resolve`: shared の `BoxConfig.mounts` は従来と同一（`git="shared"`、`workdir=None`）。既存の `test_config.py` を**無修正で**通す。
  - `plan.instance_config` は shared で `user.kcage.git` を足さない。
  - `plan_exec` の `--cwd` は `repo_path`。
  - `plan_up` の steps は shared で従来と同一。
  - `root_helper` の `up` は commondir の経路が従来どおり。
  - CLI: 新動詞は shared で終了コード 2。`up`・`pi`・`stop`・`rm` の追加動作は clone のときだけ。許可表が読めなければ shared とみなす。
- 確認方法:
  - 既存の `test/kcage/test_*.py` が無修正で通ること（追加のみ）。
  - 新しい `test_clone_flag.py` が、shared の policy で `plan_up`・`plan_exec`・`resolve`・`build_argv` の出力が従来のスナップショットと一致することと、新動詞が 2 を返すことを確かめる。
- 既存の shared の箱を clone へ切り替えると、`plan_up` が `LABEL_GIT_KEY` の食い違いで拒否する（戻し方は collect・take の後に `kcage rm` → `kcage up`）。

## 12. 契約に入れない（実装の担当が決める）こと、ずれたときの直し方

**担当が決めてよい（契約の外）**

- `discover` の走査アルゴリズム、`scan_new_objects` の git の呼び方（`rev-list --objects`・`log --raw` など）。
- `SAFE_ARGS` の細部（上の追加以外）。
- `GIT_ALLOW_PROTOCOL` の値。bundle とローカルの fetch が通る最小にする。通るなら空、通らなければ `file`。
- 人向けの表の整形、進捗の文言、エラー文の文言。
- `view` のモード（0444/0555 の扱い）と世代入れ替えの細部。
- 秘密検出の名前・内容の一覧（`SECRET_VALUE` と同系統）。
- `ws finish` の内部の順序（外から見える事前検査と終了コードは契約どおり）。
- JSON への任意キーの追加。読む側は無視するので、version は上げない。

**ずれたときの直し方**

- 下位の層（gitrun）の署名を優先して動かさない。食い違いは、上位の層（呼ぶ側）が合わせる。
- 型・署名を変えるときは、先にこの契約書を直し、動いている worker へ知らせる。契約の外に及ぶ変更は先に親へ相談する。
- 見込みの実装が合わないときは、配線（接続）の側で直す。直す・捨てる費用は、待つ時間より安いとみなす。

**守る条件との対応（要約）**

- C2: ホストの既存の運用（`git flow feature start --worktree`・`.tmp/worktrees/`・PR ビューア・`bundle.py`・全件検査のロック）のコードは変えない。変わるのは `common.toml.tmpl` の確認の追加だけ（S1g）。
- C4: H1〜H5 と §10 の悪性データの試験で縛る。限界は「git 本体の未知の脆弱性」、`take develop` と `view` で入る箱由来のファイルをホストのエディタなどが実行する経路（`risk_globs`・`HOST_AUTOEXEC_NAMES` の警告は機械では防げない）、ホストの pi が箱由来のテキストを読むときのプロンプトインジェクション。
- C5: push・公開・リポジトリ外の削除は入れない。消す操作は、箱専用データ（`seeding` の印があるときの workdir）と、`.kcage-view` の印がある view の世代交代だけ。

**この契約で既定として決めた追補（D の補足。違えば直す）**

- `ws adopt` は `ws join` に改名した（ホストの `kcage adopt`（D20）との衝突を避ける）。
- repo 集合の絞り込みは `--rel`。`--repo` は箱の id と衝突するため。
- `kcage rm` の前の collect を clone のときだけ入れた（失敗したら中止。`--no-collect` で省略）。

## 契約を決める上で、利用者に聞くべきこと

1. **`ws finish` の既定**（経路 B の merge の形）。推奨: git flow に依存しない `--no-ff` merge（PR ビューアの merge commit と揃える）。代替は `.gitflow` の squash に合わせる案（履歴が 1 コミットにまとまる）。
2. **`kcage rm` の前の自動 collect**（clone のときだけ。失敗したら中止、`--no-collect` で省略）。推奨: 採る。既存の `rm` の挙動を clone で変えるが、箱だけにあるコミットの消失を防ぐ。
3. **S1g の確認の範囲**（権限の境界を動かすので、実装の前に `review`）。推奨: `[pi.confirm]` に `kcage take develop|main|master` と `kcage ws finish`、`[bash] deny` に `kcage adopt`。
4. **名前の追補**。推奨: `ws join`（`ws adopt` から改名）と `--rel`。
5. **`kcage register` の新フラグ**を v1 に入れるか。推奨: 入れない（許可表は手編集で十分。root 側の引数の解釈を増やさない）。

## 更新（親。波 1 の結果の反映。2026-11-08）

波 2 以降の担当は、上の本文より**こちらを優先**する。

- **gitrun.py は実装済み**（枝 `feature/kcage-clone-gitrun`）。`GIT_ALLOW_PROTOCOL` は `file`（空では bundle もローカル fetch も通らない）。`HostGit.__call__` の `env_extra` は**許可リスト方式**（`GIT_INDEX_FILE`・`GIT_WORK_TREE`・`GIT_OBJECT_DIRECTORY`・`GIT_ALTERNATE_OBJECT_DIRECTORIES`・`GIT_AUTHOR_*`・`GIT_COMMITTER_*` だけ。他は `ValueError`）。`HostGit` の既定の `cwd` は空の私用 `home`（0700）。`datetime.UTC` を使う（Python 3.11 以上）。
- **共有ヘルパー `test/kcage/gitsync_fixtures.py` は実装済み**（`LocalBox`・一時 repo・悪性 bundle/tar の作り方・`need_git(minor)`・`CHILD_REL = "src/c1"`・`evil_tar(..., n=, size=)`・`make_env(..., limits=)`・`seeded_box`）。使い方は `test/kcage/test_gitsync_fixtures.py` を見る。
- **重要な実測（git 2.43）: `git fetch <bundle>` は `fetch.fsckObjects=true` でも fsck しない。** `.git`・`.GIT`・`".git "`・`git~1` の tree と `.gitmodules` の symlink は fetch が成功する。取り込み後の `git fsck --strict --no-dangling` は終了コード 4 で検出する。したがって **`inbox.import_bundle` は、fetch の後に必ず `git fsck --strict --no-dangling` と `scan_new_objects`（`.git` 名の変種・gitlink・`.gitmodules` の symlink・ref 名・親の commit が子 repo の rel 配下に触れていないか・サイズ）を走らせ、拒否したら ref を更新しない**（先に一時 ref へ受け、通ったら正式な ref へ移す）。gitlink・不正な ref 名・`unexpected-ref`・`child-path`・`oversize` は fsck も fetch も通るので、`scan_new_objects` と ref 名検査の責務。`corrupt-pack` と `prereq-missing` は fetch が失敗して ref も作られない。
- **view の配置（担当 D の提案を採用）**: 展開先は `<view>/<name>` の**兄弟**（`<view>/.new-<name>-<nonce>`・`.old-…`・`.tmp-…`）。`safe_extract` の `dest` は「存在しないパスで、親は存在する」。tar は**無圧縮のみ**。箱側の export は、無圧縮の tar で通常ファイルとディレクトリだけを出す。ws 名の規則は契約 §4.4 の `^[a-z0-9][a-z0-9._-]{0,63}$` に統一する（D の実装は大文字を許すので、接続時に D 側を合わせる）。
- **波 2 の依存の緩和**: `inbox.py` は `repos.slug_of` に依存しない（`model.RepoEntry.slug` を呼び出し側が渡す）。`wip.py` も `repos` に依存せず、repo の絶対パスと rel を引数で受ける。
