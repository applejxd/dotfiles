- **状態**: In progress
- **更新日**: 2026-11-02
- **基準**: pi 1.4.0、[CHG-0044](0044-plan-agent.md)（計画役）・[CHG-0045](0045-orchestrator-parent.md)（親の絞り込み）、[子エージェント](../spec/guard/pi-subagents.md)

## 1. 要約と状態

- **問題**: 子（explore・review・plan・worker）は、グローバルの `AGENTS.md`（8.4 KB）と、リポジトリの `AGENTS.md`（11 KB）の**両方を全文**受け取る。親向けの規則（委譲・取り込み・全件検査・承認・`ask`・停止の方針）が混ざり、子の制約（読み取り専用・コミット不可）と食い違う
- **方針**: 正本の本文に**子向けの印**を付け、ハーネスが印のある部分だけを選別して子に渡す。受け渡しの経路（pi の文脈の一覧を変換するか、`-nc` で止めて再投入するか）は、S0 の観測で決める。選別と受け渡しは**対立案ではなく併用**
- **つなぎ**: 段 1 の前置き（子の system の先頭に「親向けの指示は適用しない」）。全文が届く以上、親向け規則に従う余地が残るので、終点ではない

## 2. 事実（確かめたこと）

- 子の起動引数（`home/dot_config/pi/harness/index.ts` の `spawnChild`）に `--no-context-files`（`-nc`）は無い。`explore` の子に自己申告させて、両方の `AGENTS.md` が入っていることを確かめた（2026-11-02）。子自身が、親向けの指示が混ざり、自分の制約と両立しない箇所があると報告した
- `-nc`（pi 1.4.0 の CLI。`AGENTS.md` と `CLAUDE.md` の自動発見を止める）は、**作業先リポジトリの `AGENTS.md` も止める**はず（範囲は S0 で測る）。ハーネスは全リポジトリ共通なので、無条件に付けると、**他のリポジトリの子が、そのリポジトリの規約を失う**
- 規則の棚卸し（83 件）: 親だけ 35・子にも必要 37・不要/重複 2・判断が分かれる 9。子に必要な分は、原文で約 4.4K 文字（全体の約 46%）。分類と字数は目視（±10%）
- 役割の system と食い違う箇所: worker の「pytest・git は確認なしでは実行できないことが多い」（今日の worker は実行できた）。4 役に「日本語で返す」の明文が無い。公開リポジトリの注意は worker と explore にだけある
- Windows の素の `pi` の子も、**同じハーネスを読み、`PI_HARNESS_CHILD=1` を立てる**（別の `subagents` 拡張が起動する）。`CHILD` だけで動く hook は、Windows にも効く
- `pre-commit` の秘密検出（gitleaks）は `--staged` で、`--files` の対象ではない（`pass_filenames: false`）

## 3. 守る条件

- **C1** 子に必要な規約を落とさない。必要なのは、**行動規則**（実行・承認・委譲・コミット）だけでなく、**成果物・判断の不変条件**（BOM・生成元・公開範囲・README の方針など）。後者は worker だけでなく、評価する review・設計する plan にも要る
- **C2** 親の挙動を壊さない。比較の基準は、文言整理（S1）後の版
- **C3** 規則の**正本は 1 つ**。子用の写しを別に持たない。役割の system・`worker-common.md` との重複と矛盾を解消する
- **C4** 他の環境（Claude Code・Copilot・OpenCode・Windows の `subagents`）を壊さない。**起動契約で明示した経路だけ**が変わる
- **C5** 公開リポジトリ。私物以外の具体を書かない
- **C6** 段階的で戻せる。戻し方は、設定の変更と、**起動済みの子の終了・親の再起動（reload）**まで含める（環境変数は起動済みの親に届かない）
- **C7** 反例先行の試験と、実機の評価（§5）。構造の試験は規約の遵守を保証しない
- **C8** worker に任せられる単位に分ける。共有ファイル（`common.toml.tmpl`・golden・`index.ts`・docs の索引）は 1 feature ずつ。**新しい試験の登録（`verify.py`）は、取り込み前に feature の中で行う**（取り込み前の関門が見る）
- **C9** 契約（§4）。「無印」と「破損」を同じ扱い（全文を渡す）にしない
- **C10** 起動契約。`spawnChild` が、検証済みの**役割名**と**文脈のモード**を明示して渡し、子側の処理はその契約があるときだけ動く

## 4. 設計

### 4.1 記法と契約

- 正本（`agent-instructions.md`・各リポジトリの `AGENTS.md`）に `<!-- child:<役割> -->`〜`<!-- /child -->`（役割: `explore`・`review`・`plan`・`worker`・`all`）。印の無い部分は親だけ。親専用の印 `<!-- parent -->`。**導入済み**を示す版つきの識別子をファイルの先頭に置く

| 状態 | 動作 |
| --- | --- |
| 導入前（識別子も印も無い） | 全文を渡す（他のリポジトリの規約を守る）。理由を表示 |
| 導入済みで、構文・分類が正常 | 印のある部分だけを渡す |
| **導入済みで、破損・未分類・未知の役割** | **子の起動を失敗させ**、原因を返す |
| 明示的な `inherit`（環境変数・設定） | 全文を渡す |

- 混在する節は、項目ごとに印を付けさせる（`lint`）。新しい節・段落・表の追加も、未分類として検出する
- 抜粋の先頭に「親の指示からの抜粋（あなたは子エージェント）」と出典（グローバル / このリポジトリ）を付ける。出典ごとに、抜粋か全文継承かを表示する（**全文継承の表示は、通常の経路では出ない**。§8）

#### 実装で決まったこと（`child-context.ts` の `resolveContext`・`lint`）

**(a) 印に似た行**:

| 行 | 導入前（有効な識別子も有効な印も無い） | 導入済み |
| --- | --- | --- |
| `<!--` の直後の語が `child` / `parent` の行（有効な印を除く） | **無視して全文** | 破損（子は起動に失敗） |
| `<!--` の直後の語が `child-context` で始まる有効でない行（版の書き損じなど） | **常に破損** | 破損 |
| 上以外の普通のコメント（例: `<!-- generated from parent guide -->`） | 無視して全文 | ブロックの外なら未分類 |

- 「印に似た行」= **`<!--` の直後の語**が `child` / `parent` の行。コメントの中身に語があるだけの行は含めない
- 導入済みの判定: 有効な識別子・有効な印・識別子の書き損じのどれかがある。印に似ただけの行は含めない
- 経緯: 「コメントのどこかに `child` / `parent` がある行」を似た行にしていたため、導入前のファイルの普通の HTML コメントで子が終了した（§7 の S4 の review。親が実物で再現）

**(b) コードブロックの区切り**:

- 区切りは文字（`` ` `` か `~`）と長さを保持する。閉じは、同じ文字で同じか長い並びで、後ろに何も無い行
- 中の印・見出しは無視する（印として数えない）
- 開きの行に `` ` `` を含む `` ` `` の並びは区切りにしない（行内コード）
- ブロックの外のコードブロックは未分類（子向けか親だけの印で囲む）

**(c) 動作表**（役割 × モード。役割は `explore` / `review` / `plan` / `worker`、`all` は 4 役）:

| 入力 | `inherit` | `extract` |
| --- | --- | --- |
| 導入前（印なし・普通のコメント・印に似た行） | 全文（`why: inherit`） | 全文（`why: legacy`） |
| 導入済みで正常 | 全文 | その役割のブロックだけ（ブロックの間は空行 1 つ） |
| 導入済みで、その役割のブロックが 0 件（他の役割のブロックはある） | 全文 | 空の抜粋（見出しだけが子に渡る） |
| 導入済みで、破損・未分類・未知の役割・未知の版・入れ子・閉じ忘れ | 全文 | **エラー**（子は終了。原因に行番号つき） |
| 識別子が無く、有効な印だけがある | 全文 | **エラー**（識別子が無い） |
| 識別子はあるが子向けブロックが 1 つも無い | 全文 | **エラー** |
| 未知のモード・未知の役割 | エラー | エラー |

- 明示の `inherit` は、中身を見ない（破損していても全文）

**(d) ブロックの外**:

- **見出し行（`#`〜`######`）だけが、ブロックの外にあってよい**。抜粋には見出しも印も入らない
- 見出し以外の空でない行がブロックの外にあれば**未分類**（導入済みでは子の起動に失敗）。新しい節・段落・表・コードブロックは、子向けか親だけのブロックに入れる

### 4.2 受け渡し

- **S0 の実測（2026-11-02）で (P) を採る**（`before_agent_start` の `systemPromptOptions.contextFiles`（`{path, content}`）を書き換えると、最終の prompt に反映される。[記録](../research/agents/child-context-probe.md)）。**保持の条件（persist の実測）**: (1) `contextFiles` は**ユーザーメッセージごとに元の内容で渡し直される**ので、**子の起動時に 1 回だけでなく、`before_agent_start` のたびに毎回書き換える** (2) ツールの往復では呼ばれず、書き換えは残る (3) 複数の拡張は `-e` の順に実行され、後の拡張が前の書き換えを見て、**最後の書き換えが勝つ** (4) いずれかの拡張が `{systemPrompt}` を返すと、**それが全体を決め、文脈の書き換えは効かない**（今の拡張に、`before_agent_start` で返すものは無い。新しい拡張を足すときの注意） (5) `/reload` の後の次のターンも効く (6) `-nc` のとき空の `contextFiles` へ足した要素だけが prompt に出る（抜粋を足す口にもなる）。比べた案: (P) pi の文脈の一覧（hook）を、ファイル単位で変換する。`-nc` は要らず、祖先・順序・出典を保てる。(N) `-nc` で止め、選別した結果を `--append-system-prompt` に入れる。この場合は、pi の収集との**同等性**（出典・順序）を先に確かめる
- **起動契約**: `spawnChild` が、検証済みの役割名（`explore` と `review` は同じ profile なので、profile では区別できない）と文脈のモードを、環境変数で明示する。子側はその契約があるときだけ動き、親・`commit` 役・Windows の経路は変えない。未知のモードは、黙って選別にしない

#### 実装で決まったこと（S4。`index.ts`・`generate.py` の `pi_child`）

| 項目 | 実装 |
| --- | --- |
| 設定 | `[pi.child] context = "inherit" \| "extract"`（`common.toml.tmpl`。既定 `inherit`）。未知の値・未知のキーは生成が止まる |
| 環境変数（親） | `PI_HARNESS_CHILD_CONTEXT`。空でなければ設定より優先。**未知の値は子を起動せず**、原因を結果に返す（`commit` 役も起動しない） |
| 起動契約 | `spawnChild` が子へ `PI_HARNESS_CHILD_AGENT`（役割名）と `PI_HARNESS_CHILD_CONTEXT`（`inherit` / `extract`）を渡す。**子の役割が `explore` / `review` / `plan` / `worker` 以外（`commit` など）なら常に `inherit`** |
| 子側の発動条件 | `PI_HARNESS_CHILD=1` かつ `PI_HARNESS_CHILD_CONTEXT=extract` かつ役割名が 4 役のどれか。**`PI_SUBAGENT_CHILD=1`（Windows の別の `subagents` 拡張が起動する子。親の環境変数を引き継ぐ）は契約変数が残っていても対象にしない** |
| 子側の hook | `before_agent_start` を**毎メッセージ**で書き換える（保持の条件 (1)）。対象は `contextFiles` のうち、`path` の末尾が `AGENTS.md` / `CLAUDE.md` の要素だけ。抜粋のときは先頭に「【親の指示からの抜粋】… 出典: `<path>`」を付ける。導入前の全文継承は内容を変えない |
| 失敗のしかた | `resolveContext` がエラー、または予期しない例外のとき、stderr に「子の文脈 (AGENTS.md) の抜粋に失敗したので子を終了: <原因>」を出し、**`exit 78`** で子のプロセスを終わらせる。原因を先頭に置き（220 字に切る）、出典のパスは末尾 60 字を添える。親は「process exited」と stderr の末尾を結果に出す。hook の throw は pi が握りつぶして子が全文のまま動くため、throw ではなく終了する |
| 入力の形の検査 | `systemPromptOptions` がオブジェクトでない・`contextFiles` が配列でない・要素がオブジェクトでない・`path` / `content` が文字列でないときは「契約違反」として終了（空の配列は正常）。`String()` で補正しない |
| 結果の見出し | `- 文脈: inherit` または `- 文脈: extract` の 1 行（`spawnChild` で起動した job の結果） |
| 観測 | `PI_HARNESS_CHILD_CONTEXT_REPORT=<パス>`（試験用）。決定ごとに `{path, kind, why, blocks, before, after}` を 1 行の JSON で追記する。本文は書かない。`after` は見出しを含む、実際に入れた長さ。書けなくても子の動作には影響しない |
| 変えない経路 | 親・契約が無い子（`PI_HARNESS_CHILD=1` だけ）・`inherit`・4 役以外・`PI_SUBAGENT_CHILD=1` の子 |

- 試験: `test_pi_child_context.py`（解決器の表）・`test_pi_child_context_wire.py`（配線。実の子を起動）・`test_child_context_sources.py`（正本 2 つの役割別の期待・`lint`）・`test_pi_child_persist.py`（保持の条件）・`test_pi_child_prompt.py`（全文継承の特性化）
- この変更で入れた「切り替え」は無い。既定は `inherit` のまま（内容と権限は今と同じ。見ることができる差は、環境変数 2 つと見出しの 1 行）

- **S5 の評価設計**（同一の版・モデル・effort・依頼で、文脈のモードだけを変える。新しい作業先・会話。順序を入れ替える）:
  - 場面は全役（explore・review・plan・worker）と、親向け規則へ誘導する反例を含める。数は、場面 × 2 方式 × 複数回で、少数の成功を根拠にしない
  - 判定を分ける: (1) 必須規則の違反・危険な操作の試行 (2) 正しい拒否（増えてよい） (3) 不要な拒否・中断 (4) 課題の達成・レビューの検出漏れ。採点は、自己申告でなく、実際のツール呼び出し・差分・検査の出力
  - 許容する回帰と観測期間を、切り替えの前に決める。決まらなければ既定は維持。切り替え後も、一定期間は opt-in の試用

## 6. X-1〜X-6 の方針

| X | 方針 |
| --- | --- |
| X-1 検査の実行 | worker は試験・lint を実行して出力を示す。**拒否されたら**止めて「未確認」と書き、親が実行すべきコマンドを「次の候補」に書く。実行できるかの予測の文は置かない。読み取り専用の役（explore・review・plan）は**試験・ビルドを実行しない**（読み取りの git・grep は可） |
| X-2 新規ファイルの検査 | 未確認。S0 で、hook ごと（lint と秘密検出）に、新規・追跡済み・ステージ済みの対象を測り、結果を `AGENTS.md` と `worker-common.md` に反映する。`--files` を全検査の保証にしない |
| X-3 試験の登録 | 親、または依頼文が許した worker が、**取り込み前に feature の中で**登録する。worker が許されなければ、報告に「登録が必要: <パス>」 |
| X-4 拒否後 | 拒否条件を満たす正規の別手段（読むのは `guarded_read` など）へは切り替えてよい。言い換え・分割・偽装での回避はしない。手段が無ければ止めて報告 |
| X-5 検索 | 外部ソフトの挙動が絡む未知の不具合は、手元の調査より先に検索。それ以外は必要なときだけ。worker が外部依存の未知の不具合に当たったときの扱いも落とさない |
| X-6 一時ファイル | 使い捨ては `$TMPDIR`。**`$TMPDIR` が作業ツリーの外のときは、作業ツリーの `.tmp/` の下**（作業ツリーの外へは書かない）。担当ファイル以外は読み取りだけ、の例外は、この使い捨て用ディレクトリに限る。残すものは作らず、`.tmp/keep` は親が指示したときだけ |

公開リポジトリの注意は、review と plan にも足す。強さは正本（私物の環境の事実は書いてよい）に合わせ、`worker-common.md`（私物の具体も禁じる）との食い違いは、意図した追加の制約として明示するか、正本に統一する。
