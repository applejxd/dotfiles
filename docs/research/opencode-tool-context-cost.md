## 0. 本書の用途

CHG-0002 は「シェルコマンドをカスタムツールへ畳んで確認回数を減らす」案を
含む。ツールを増やすとシステムプロンプトが膨らんでコンテキストを圧迫する、
という懸念があったため、実際の固定費を測った。

## 1. 結論

**`codemode` を既定（`true`）のまま登録すれば、ツールを増やしても固定費は
0 bytes。** コンテキスト逼迫を理由にツール化を避ける必要はない。

## 2. 方法

`session.hook("context")` でモデルへ送られる直前のツール一覧を観測した。

## 3. 結果

### ベースライン

| 項目 | 実測 |
| --- | --- |
| ツール数 | 13 |
| ツール一覧のサイズ | 12,596 bytes |
| システムプロンプト | 30,015 bytes |

### 登録方法による差

| 登録方法 | 常時提示の一覧 | 固定費 |
| --- | --- | --- |
| `codemode: true`（既定） | **載らない** | **0 bytes** |
| `codemode: false` | 載る | 111 bytes（単純なツール 1 個） |

`codemode: true` のツールは `search()` 経由の遅延提示になる。モデルが
必要と判断したときだけ記述が展開されるため、常時提示の一覧には現れない。

## 4. 設計への含意

CHG-0002 の `verify` ツールは既定（`codemode: true`）で登録する。

ツールを 5 個に分けるか enum 引数 1 個に畳むかという別の論点はあるが、
それは**提示されたときのコスト**の話であり、本記録が測った固定費とは
別の軸である。固定費の観点ではどちらも 0 bytes になる。
